价值函数与贝尔曼方程

这组方程是后面每个算法的公共骨架。你要能写出一套策略（一套"看到什么状态就选什么动作"的规则）， 以及它的价值函数（从某个状态出发，按这套策略走下去，平均能拿多少总分） vπ、qπ（π 是策略） 和两个贝尔曼方程（把"这一步的价值"和"下一步的价值"连起来的等式），并看懂后面每一个算法的更新式都只是它的一种解法。

你会得到

  • 能说清 vπ(s) 与 qπ(s,a) 的定义和相互关系
  • 能写出贝尔曼期望方程与贝尔曼最优方程，并指出它们差在哪里
  • 能解释"最优策略就是对 q* 贪心"为什么足够

为什么不能只看回报

第 0003 课定义了回报（从现在起一直到结束，把每一步奖励加起来的总分） Gt，但它是随机变量：同一套策略跑两次，得到的 Gt 不一样。 要比较两套策略，你需要的是一个平均值："从一个状态出发，按这套策略走下去，平均能拿多少"。

这就是价值函数存在的理由：把随机的回报压缩成一个可以排序、可以比较的数。 它评的对象是策略，而策略由智能体（做决策的那一方，就是你写的程序）掌握。

价值函数还是所有 RL（reinforcement learning，强化学习）算法的中间语言。 策略梯度（不绕道估价值，直接调整策略参数的那类方法）即使不拿它当更新目标，也要拿它当基线 （从回报里减掉的一个参照值，只用来降波动，不改变平均方向）。

两个价值函数

在策略 π 下，状态 s 的价值叫状态价值（只看状态、不管具体选哪个动作的那个价值）， 写成期望回报：

vπ(s) = 𝔼π[ Gt | St = s ] (4.1)

式子里的 𝔼 是期望号（期望，同一件事重复很多次之后的平均结果）：同一套策略从 s 出发跑很多次， 把每次的总分平均起来，就是这个状态值多少分。

在状态 s 下先强制选动作 a、之后再按 π 走的价值，叫动作价值（在某个状态下先选某个具体动作，之后再好好走，能拿多少总分）：

qπ(s, a) = 𝔼π[ Gt | St = s, At = a ] (4.2)

两者关系很直接：状态价值就是按策略概率对动作价值加权平均：

vπ(s) = Σa π(a|s) · qπ(s, a) (4.3)

工程上记住一条：有模型时可以只学 vπ；没有模型时，必须学 qπ。因为挑动作要比较"哪个 a 更好"， 而 v(s′) 里没有 a 的信息。你只能靠 p(s′|s,a) 去推， 这个量叫转移概率（这个跳转不一定百分之百确定，而是一组可能性，各带着自己的概率）， 描述的是状态转移（你做完动作之后，环境从当前状态跳到下一个状态）。 第 0008 课之后所有无模型方法都在学 Q，原因就在这里。

贝尔曼期望方程

把 Gt 按定义拆成"这一步的奖励 + 折扣后的下一步回报"， 再对环境的随机性取平均，就得到贝尔曼期望方程（Bellman expectation equation，动作层按策略概率加权的那组方程）：

vπ(s) = Σa π(a|s) Σs′,r p(s′, r | s, a) [ r + γ vπ(s′) ] (4.4)
qπ(s, a) = Σs′,r p(s′, r | s, a) [ r + γ Σa′ π(a′|s′) qπ(s′, a′) ] (4.5)

式中 γ 是折扣因子（越往后的奖励，算进总分时权重越小，相当于给它打了个折）。 γ 这类需要你自己设定、而不是从数据里学出来的参数，叫超参（需要你自己设定、而不是训练学出来的参数）。

这两个式子的结构叫备份图（backup diagram，一次更新从哪里取值、又怎么合并的那张图）：根节点是 s， 往下一层是策略分出的各动作（期望），再往下一层是环境分出的各 (s′, r)（期望）， 叶子才是 vπ(s′)。所有更新式都是在描述"这次更新从哪些叶子取值、怎么合并"。

注意它在数学上是一个线性方程组：状态空间（所有可能局面的集合）有 n 个状态， 就有 n 个未知数、n 个方程。所以理论上你可以直接解出 vπ。 前提是知道 p(s′,r|s,a)，并且 n 小到能解方程。

状态一多就解不动了，只能一轮轮迭代着逼近，最后停在某个价值上不再变化。 这种"再迭代一次也不变"的解叫不动点（再迭代一次也不变的那种解）。

贝尔曼最优方程

把"对策略取期望"换成"对动作取最大"，得到的就是贝尔曼最优（Bellman optimality equation）：动作层直接取最大，不再按策略加权。

v*(s) = maxa Σs′,r p(s′, r | s, a) [ r + γ v*(s′) ] (4.6)
q*(s, a) = Σs′,r p(s′, r | s, a) [ r + γ maxa′ q*(s′, a′) ] (4.7)

两个方程的关键差别只有一个字：对动作的期望变成了 max。代价是它不再是线性方程 （max 是非线性的），所以不能一步解出来，只能一轮轮迭代逼近。这直接引出第 0005 课的 DP（dynamic programming，动态规划）。

它的结论很有用：只要拿到 q*， 每个状态下挑让 q*(s,a) 最大的那个动作，就得到最优策略。 这里的 arg max 读作 arg-max，意思是"挑出让后面那个式子最大的那个选择"。 于是"在所有策略构成的巨大空间里搜索"就退化成"每个状态各自取最大"。

这样挑出来的做法叫贪心（只挑眼前最好的那个）。按它得到的策略是确定性策略 （每个状态固定选一个动作，不靠抽签）。反过来，按概率随机挑动作的那类策略叫随机策略 （同一个状态下按概率随机挑，不固定某一个）。

别读过头：存在性定理说的是"至少有一个最优策略，而且它可以用贪心方式取得"， 不是说"最优策略唯一"。同一个 q* 下，多个动作并列最优很常见， 实现时 argmax 的平局规则会决定你最终拿到哪一个。

为什么说它是公共骨架

回头看，整个课程后面的东西都是这一组方程的不同解法：

方法对贝尔曼方程做了什么
动态规划（0005）已知模型，反复做期望备份，直到收敛（一轮轮算下去，数值不再明显变化，稳定下来了）
蒙特卡洛（0007，把一整局走完，用真实拿到的总分来估计价值）用整条轨迹的回报 Gt 代替方程右边
时序差分（0008，不用等到一局结束，用"走一步之后的新估计"来更新"走这一步之前的估计"）用 r + γV(s′) 这个单步样本代替整条轨迹
DQN（0013）用神经网络逼近 q*，在采样的转移上做回归

第 0005 课会把第一行展开：先把一套策略的价值反复算准， 这一步叫策略评估（给定一套策略，算出它到底值多少分）；再根据算出来的分数，把策略里明显吃亏的选择换掉， 这一步叫策略改进（根据算出的分数，把策略里明显吃亏的选择换掉）。两者交替进行，就是策略迭代（反复"打分 → 改招"，直到改不动为止）。

所以训练不收敛的时候，先回到这一步问两个问题：我到底在逼近哪一个方程？我的目标值里有没有漏掉 γ 或终止条件？ 绝大多数实现 bug 都落在两个地方：终止状态的备份（不该有下一状态）和 γ 的幂次。

课后练习

1. 关于 vπ(s) 与 qπ(s,a) 的关系，哪一项是对的？

  1. qπ(s,a) 等于对全部动作取最大值之后的结果
  2. 两者之间没有确定关系，必须用两套完全不同的数据估计
  3. vπ(s) 等于 qπ(s,a) 在全部状态上的平均值
  4. vπ(s) 是各动作价值 qπ(s,a) 的策略加权平均

为什么：式 (4.3)：在状态 s 下，策略以 π(a|s) 的概率选不同动作， 状态价值自然就是这些动作价值的加权平均。

A 把期望换成了 max，那是 v* 与 q* 之间的关系，不是 π 下的关系。 B 错：有确定性关系，知道其中一套就能推出另一套。 C 混淆了"对动作加权"与"对状态取平均"。

2. 贝尔曼期望方程与贝尔曼最优方程最关键的差别是什么？

  1. 最优方程只在分幕任务里成立，期望方程对两类任务都成立
  2. 期望方程对动作按策略概率加权，最优方程对动作取最大值
  3. 最优方程里不出现折扣因子，期望方程必须显式写出折扣项
  4. 期望方程描述环境的动态，最优方程描述的是智能体的策略

为什么：两式的备份结构完全一样，唯一区别是动作层用 Σa π(a|s) 还是 maxa。 前者对固定策略成立，后者对最优价值成立。

A 错：两式对分幕与持续任务都成立（持续任务要求 γ < 1）。 C 错：两式都含 γ。D 错：两式都从环境动态 p(s′,r|s,a) 出发。

3. "对 q* 贪心的策略就是最优策略"，这条结论的价值在哪里？

  1. 它把"在全部策略里搜索"变成了"每个状态各自取最大动作"
  2. 它证明了最优策略必须是随机策略，否则无法覆盖所有动作
  3. 它说明只要状态空间有限，最优策略就一定只有唯一的一个
  4. 它要求环境模型必须已知，否则贪心策略根本没办法被定义

为什么：策略空间随状态数指数增长，穷举不可行； 但贪心性告诉我们只要拿到 q*， 逐状态取 argmax 就够，而且得到的是确定性策略。

B 说反了：确定性贪心策略通常就是最优策略，随机性不是必需品。 C 错：最优策略可以不止一个，并列最优时 argmax 的平局规则决定选哪个。 D 混淆了两件事：这条结论本身是关于"最优性"的结构性定理， 而"怎么算出 q*"才是需要模型的算法问题。

4. 说贝尔曼方程是"后面所有算法的公共骨架"，是什么意思？

  1. 所有算法都必须先把贝尔曼方程精确求解出来，才能开始学习
  2. 所有算法都使用同一个步长设置和同一个折扣因子取值
  3. 各个算法都是对同一组方程的估计方式与求解方式的不同组合
  4. 所有算法都不需要环境模型，因此都直接在线上采样贝尔曼方程

为什么：动态规划是迭代求解它，蒙特卡洛用时序回报替换方程右边， TD（temporal difference，时序差分）用单步样本替换，DQN 用网络逼近它的解。骨头是同一副，差别只在"怎么算右边"。

A 错：无模型方法从不精确求解它，只是用样本近似。 B 错：步长与 γ 是各算法自己选的超参。 D 错：动态规划必须要有完整模型，"都不需要模型"是错的。

5. 备份图（backup diagram）描述的是什么？

  1. 把价值函数随迭代次数的取值画成曲线，用来判断有没有收敛
  2. 一次价值更新从哪些后续状态取叶子值、又怎样把它们合并起来
  3. 把环境的转移概率画成矩阵图，用来检查状态转移是否合法有效
  4. 策略在状态空间中的访问频率分布，用来诊断探索是否足够充分

为什么：备份图是更新的依赖结构：根是当前状态， 经动作层与环境分支到达叶子 v(s′)， 再把叶子值加权（或取最大）合并成新的根值。看见一张备份图就能写出对应的更新式。

A 说的是学习曲线，C 说的是转移矩阵可视化，D 说的是状态访问分布。 三者都是有用的工具，但都不是备份图。

代码题 1 · 实现贝尔曼期望备份

背景贝尔曼期望备份把当前的价值估计按一步转移推进一步，是策略评估里反复执行的那一步操作，后续动态规划与值迭代都拿它当内层循环。已知模型时才能这样算：每个动作的期望由转移概率加权得到。输入是价值、模型与策略，输出是策略评估一轮之后的新价值。

请实现 bellman_backup(V, P, R, policy, gamma)。

Vnew[s] = Σa policy[s, a] Σs′ P[s, a, s′] ( R[s, a] + γ V[s′] ) (4.8)

输入

  • V：长度 S 的 float numpy 数组，也就是"一排数字的容器"，形状记作 (S,)，存当前的状态价值估计；
  • P：形状 (S, A, S) 的转移概率数组。P[s, a, s′] 是状态 s 采取动作 a 后转到 s′ 的概率；形状说的是每个维度各有多少个位置，下标都从 0 开始；
  • R：形状 (S, A) 的期望即时奖励数组；
  • policy：形状 (S, A) 的随机策略，每行加起来为 1；
  • gamma：float 折扣因子。

输出

  • 返回长度 S 的 float numpy 数组，第 s 个元素是状态 s 备份一次之后的价值。

会被检验gamma=0 时结果退化为按策略加权的期望即时奖励；输入恰好取到不动点时输出与输入逐项相同；确定性策略和动作各半的随机策略都各有一组数值要对上。不要修改传入的 V、P、R；只用标准库与 numpy，本题不需要随机数。

卡住了？看提示
  • Σ 是求和号，意思是把后面那串全加起来。内层 Σs′ P[s, a, s′] · V[s′] 就是 P[s, a] @ V， 一个下标一次取出 (S,) 的一行，矩阵乘之后返回一个数。@ 是 numpy 的矩阵乘法运算符。
  • 外层对动作求和时，每一项都要乘上权重 policy[s, a]，不要漏掉它。
  • 先建 out = np.zeros(S)。np.zeros(S) 返回长度 S、全是 0 的数组。对每个状态 s：设 total = 0.0， 再对每个动作 a 把 policy[s, a] * (R[s, a] + gamma * (P[s, a] @ V)) 累加进 total，最后写进 out[s]。
  • 不要改传入的 V、P、R；返回新数组 out。

代码题 2 · 由 v 得到 q，再提取贪心策略

背景策略改进是策略迭代的第二步：先算出当前策略的动作价值，再对每个状态取其中最大的动作，得到一个新策略。这两个函数就构成这一步的计算，被策略迭代的主循环反复调用。输入是价值与模型，输出是新策略。按策略改进定理，这个新策略不会比原策略差。

请实现 q_from_v(V, P, R, gamma) 和 greedy_from_q(Q)。

输入

  • q_from_v 的 V：长度 S 的 float 数组，某个策略的状态价值；
  • q_from_v 的 P：形状 (S, A, S) 的转移概率数组；
  • q_from_v 的 R：形状 (S, A) 的期望即时奖励数组；
  • q_from_v 的 gamma：float 折扣因子；
  • greedy_from_q 的 Q：形状 (S, A) 的动作价值数组。

输出

  • q_from_v 返回形状 (S, A) 的 numpy 数组，Q[s, a] 是状态 s 强制选动作 a、之后按原策略走的动作价值；
  • greedy_from_q 返回长度 S 的整数数组，第 s 个元素是状态 s 的动作下标，平局取下标最小的动作。

会被检验测试检查两个返回值的形状与元素：q_from_v 在 V 全为 0 时结果等于 R，且不修改传入的 V、P、R；greedy_from_q 返回整数下标的数组，平局时取小下标；还会用真实 vπ 算一遍再贪心，验证新策略的动作价值不低于 vπ。只用标准库与 numpy，本题不需要随机数。

卡住了？看提示
  • q_from_v 不需要 policy 参数：它算的是"先强制选 a、之后按原策略走"的价值，形状要从 (S,) 变成 (S, A)。
  • 一行就能算完：Q = R + gamma * (P @ V)。P 的形状是 (S, A, S)， P @ V 会把最后那一维和 V 逐项相乘再求和，得到形状 (S, A)，正好和 R 对上。
  • greedy_from_q 用 np.argmax(Q, axis=1)：axis=1 表示"在每个状态那一行里挑动作"， 返回长度 S 的下标数组。平局时它取最小下标，正好满足要求。
  • 不要修改传入的 V、P、R；返回的 Q 是新数组，policy 要用整数类型。
