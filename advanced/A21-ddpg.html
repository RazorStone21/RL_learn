进阶 · 第五部分 · 连续控制与最大熵

DDPG：确定性策略梯度

这一节讲一个专门为"动作是连续的数"设计的算法。 连续动作的例子有机械臂每个关节转多少度、空调设几度、广告出价多少。 本节先看老办法为什么在这类动作上失灵，再写出新算法往哪个方向调参数， 最后说明怎么让训练稳住。

你会得到

  • 能说出连续动作下 maxaQ 为什么失效，DDPG 用什么替代
  • 能写出 ∇aQ · ∇θμ（θ 是策略参数，μ 是确定性策略）并解释两个因子各自的作用
  • 能实现软更新，并说清 DDPG 的探索噪声与过估计问题从哪来

连续动作下，max 没法算

策略（一套"看到什么状态就选什么动作"的规则）就是出招习惯。 本课学的是确定性策略（deterministic policy）：每个状态只输出一个动作，不掷骰子。 调好它的办法叫策略梯度（policy gradient）： 不绕道去估价值，直接算"参数往哪调能让总分更高"。 用在确定性策略上，这套算法叫 DDPG（deep deterministic policy gradient，深度确定性策略梯度）。

问题出在哪？0013 课的 DQN（deep Q-network，深度 Q 网络） 要算 maxa′ Q(s′,a′)， 意思是"在下一个状态里，把能做的动作都比一遍，挑分数最高的那个"。 Q(s′,a′) 像成绩单：给它一个状态和一个动作， 报出这么做最后大概能拿多少分。s′ 是下一步的状态，a′ 是动作。 动作只有几十个选项时，逐个代进去比一遍就行。

动作变成连续的数就比不了了：关节可以取 0.317 弧度，也可以取 0.3171 弧度， 中间有无穷多个值。这时 maxa Q(s,a) 不再是比较，而是一个优化问题：在一条曲线上找最高点。

这个最高点没有公式解。用梯度上升慢慢爬也行，但每步都要爬一次，慢， 而且可能只爬到局部最高。

老办法为什么非要取最大？因为最优的价值满足一个等式，叫 贝尔曼最优方程（把"这一步的价值"和"下一步最好的价值"连起来，每一步都挑当前最好的动作）。 max 就是从这来的。

DDPG 的做法是绕开这一步：不再现搜最好的动作， 而是学一个函数，让它看到状态直接把动作算出来。

策略梯度怎么算：让裁判指路

这套办法里有两个网络。 一个负责出动作，叫 actor（出招的那一方，负责决定做什么动作，也叫策略网络）。 一个负责打分，叫 critic（打分的那一方，负责估计局面值多少分，也叫价值网络）。 actor 是球员，critic 是教练。

critic 要学的分数叫动作价值（在某个状态下先选某个具体动作，之后再好好走，能拿多少总分）， 写作 Q(s,a)。只看状态、不管动作的那个估计叫 价值函数（从某个状态出发，按某套策略走下去，平均能拿多少总分）， 写作 V(s)。

要最大化的东西是一局结束时的总分，它叫 回报（从现在起一直到结束，把每一步奖励加起来的总分）。 同一个策略跑两次，回报通常不一样。所以真正要最大化的是它的长期平均，也就是期望， 写作 𝔼（期望，同一件事重复很多次之后的平均结果，不是某一次的结果）。

目标就是让这个平均最大，写作 J(θ) = 𝔼s∼ρ[ Q(s, μθ(s)) ]。 右下角的 s∼ρ 表示"状态按 ρ 这个规则来取"。ρ 是状态访问分布， 意思是训练时各个状态被访问到的频繁程度，它本身就是一个概率分布（每个结果各自有多大可能）。 μ 是策略网络，θ 是它的参数。

要让它变大，就对 θ 求梯度，用链式法则展开，得到主公式：

∇θJ ≈ 𝔼[ ∇aQ(s, a; φ) |a = μθ(s) · ∇θμθ(s) ] (21.1)

∇ 读作 nabla，意思是"上升最快的方向"。 ∇aQ 是 critic 递过来的一句话："动作往哪边改，价值会更高"； ∇θμ 把方向换算成"参数该往哪改"。两者相乘就是链式法则。 进入更新的只有 Q 的梯度，大小不影响方向。 所以 critic 必须能求导。

这条式子的来历是确定性策略梯度（deterministic policy gradient, DPG）： 它证明确定性策略的梯度可以写成不含动作期望的形式，所以不必对动作采样（按概率抽一个数）。

顺带认识一个亲戚：优势（在某个状态下，选这个动作比"平均水平"好多少）。

四个网络与软更新

critic 拿一批"状态、动作、结果"的数据，让 Q 的预测去靠近一个目标值。 麻烦在于这个目标值里本身就含 Q。

用自己当前的估计去构造目标，再拿它更新自己，这叫 自举（用自己当前的估计去更新自己当前的估计，等于自己拽自己的鞋带往上提）。 毛病是靶子在动：你刚把 Q 往靶子挪一点，靶子也跟着挪了。

解法是另存一份"稍旧"的网络专门算靶子，隔一阵才同步一次，它叫 目标网络（另存一份"稍旧"的网络专门用来算目标，隔一阵才同步一次，避免追着自己跑）。 比喻是照着旧照片找目标，别照镜子。

y = r + γ Qφ−( s′, μθ−(s′) ) (21.2)

式中 γ 是折扣因子（越往后的奖励，算进总分时权重越小，等于给它打了个折）， r 是这一步拿到的奖励，s′ 是下一步的状态。r 是真实拿到的分， 后面那一截用目标网络来估，这就是自举。参数右上角的减号表示"旧的那一份"。

目标网络怎么跟上？DQN 每 10000 步硬拷贝一次，拷贝那一瞬间目标会跳一下。 DDPG 换了个平滑的做法，叫 软更新（每次只把参数往新参数挪一点点，慢慢跟上，不要猛跳）。

θ− ← τθ + (1−τ)θ−,    φ− ← τφ + (1−τ)φ− (21.3)

式中 τ 是软更新系数，管每次挪多远，通常取 0.005。 τ = 1 退化成硬拷贝，τ = 0 则目标永远不动。 式子里的 ← 读作"更新为"，左边的值被右边的结果替换掉。

所以 DDPG 一共维护四个网络：actor μθ、 critic Qφ（φ 是价值网络参数）， 以及各自的目标网络，参数记作 θ− 和 φ−。

探索得从外面加

确定性策略有个副作用：同一个状态永远给出同一个动作。 训练时只按它走，就永远试不到别的动作。

DDPG 的做法是在动作上加一点随机数，写作 a = μθ(s) + N。 随机数从一个高斯分布（最常见的那个钟形分布）里取。 钟形分布中间高、两边低：大多数取值落在中心附近，离中心越远越少见。

从分布里取一个数，这一步叫采样。抽出来的数围着中心忽大忽小， 晃动的幅度由标准差（衡量波动大小）控制：标准差越大，离中心越远。

噪声多大要手调：太小探索不够，会卡在不够好的做法上； 太大动作几乎等于乱按。噪声幅度通常随训练慢慢变小。

原文用的是 OU 噪声（Ornstein–Uhlenbeck noise）： 它前后相关，比独立噪声更有惯性，适合控制问题。

最后别忘：加完噪声的动作可能超出合法范围，要 clip（裁剪，超过上下限就按上下限算）回区间里。 比如动作要求落在 [−1, 1]，算出来 1.3 就按 1 记。

为什么它脆弱，什么时候还值得用

critic 的估计总有误差，麻烦在于这个误差会自己放大。

假设 Q 在某个动作上被高估了。actor 沿着 ∇aQ 把动作往"分数更高"的方向调，正好调到那个位置。 这些动作被采得更多，critic 在那里报的分又被推得更高。 这叫过估计（因为总是取最大值，估计出来的分数系统性地偏高）， 比喻是每次都挑最好听的评价，越听越高。

再叠加对学习率（每次更新时往新信息的方向挪多远）、batch（一批样本，训练时一次处理一小批）、 噪声尺度的敏感，就有了"DDPG 能跑但难调"的名声。这类要你自己定、训练学不出来的数，统称 超参（需要你自己设定，而不是训练学出来的参数）。

另一个麻烦是波动大，也就是方差（同一个做法重复很多次，结果的波动有多大）大。

DDPG 属于 off-policy（边学的那套策略不是产生数据的那套，等于看别人的录像学自己的打法）， 所以能用经验回放（把走过的每一步都存进一个池子，训练时从池子里随机抽一批出来用）。 同一条数据被反复使用，样本效率（拿到同样多的经验能学多好，效率高就是"更省数据"）就高。

还有一条路是让策略自己保持随机。SAC（soft actor-critic，软演员-评论家）在损失里加一项叫 熵正则（在目标里加一项鼓励保持随机性，防止过早死磕一个选择）的东西。 熵（衡量"选择有多随机、多分散"，熵大代表还敢试）越大，策略越愿意试别的动作。

0022 课的 TD3（twin delayed DDPG，双延迟深度确定性策略梯度） 用三处修正治过估计：截断双 Q（用两套估计分别挑动作和打分，压住总是高估的毛病）、 让 actor 慢几拍再改动作、给目标动作加噪声抹平尖峰。

那什么时候还值得用 DDPG？它推理时不用采样，部署一次前向就出动作， 对延迟敏感的在线系统友好。维护老实现、读老论文时会用到它；新项目一般直接用 TD3 或者 SAC。

课后练习

1. 为什么 DQN 那套 maxaQ 不能直接用到连续动作上？

  1. 连续动作无法枚举，取最大值本身变成一个优化问题
  2. 连续动作的价值函数不存在，Q 只在离散动作集上有定义
  3. 连续动作下贝尔曼最优方程不成立，只能估计策略价值
  4. 连续动作的奖励不可微，目标函数因此无法做反向传播

为什么：动作是几十个离散选项时，max 就是挨个比一遍。 动作变成连续的数以后，max 变成"在一个函数的输出里找全局最高点"。 这个问题没有公式解，每一步更新都要解一次，慢，而且不保证找到全局最高点。

B 与 C 都不成立：动作价值对连续动作照样有定义， 贝尔曼最优方程对连续动作也成立，难的是算得动，不是定义不了。 D 弄错了对象：需要能求导的是 Q 对动作，不是奖励。

2. 式 (21.1) 里 actor 用到 critic 的哪一个量？

  1. critic 对状态的梯度，用它判断哪些状态更值得访问
  2. critic 输出的动作价值本身，拿它当回报直接做回归
  3. critic 对动作的梯度，在 a 等于 μ(s) 处取到的方向
  4. critic 对自身参数的梯度，用它同时更新 actor 参数

为什么：链式法则要的是 ∇aQ(s,a)，它回答"动作往哪边调，价值会更高"， 再乘 ∇θμθ(s)，把方向换算回策略参数。

A 用的是对状态的梯度，跟选哪个动作没关系。 B 拿 Q 当回报去做回归，那是 critic 自己的活，actor 要的是 Q 的梯度。 D 把 φ 和 θ 弄混了，critic 的参数由 critic 自己的损失更新。

3. 关于 DDPG 的目标网络与软更新，下列说法正确的是？

  1. 它比 DQN 更省事：只需给 actor 配一份目标网络
  2. 软更新让目标参数迅速跟上在线网络，以加快学习速度
  3. 软更新的 τ 取 0 时，目标网络就等于在线网络的一份拷贝
  4. 它让自举目标短期内稳定，τ 通常取一个很小的值

为什么：目标网络的作用和 0013 课一样，让回归目标短期内别动， 避免追一个一直在跑的靶子。DDPG 把"每 N 步硬拷贝"换成"每步挪一点"， τ 通常取 0.005，目标变平滑，但仍然会慢慢跟上在线网络。

A 不成立，actor 和 critic 各有一份目标网络。 B 把 τ 说成了"迅速跟上"。 C 说反了：τ = 0 时目标完全不动，τ = 1 才是硬拷贝。

4. DDPG 的行为策略从哪里获得探索性？

  1. 策略输出高斯分布的均值与方差，靠采样得到随机动作
  2. 在 actor 输出的动作上叠加外部噪声，如高斯或 OU 噪声
  3. 用 ε-greedy（ε 是探索率）以一定概率把某个动作维度替换成随机值
  4. 在损失里加入策略熵正则项，与优势演员-评论家（A2C）的做法完全一致

为什么：μ 是确定性的，给定状态只输出一个动作，策略本身没有随机性。 所以探索只能从外面加：a = μ(s) + N，加完再用 clip 限制回合法范围。

A 说的是随机策略（比如 SAC），那是另一条路线。 C 把 ε-greedy 硬套到连续动作上，DDPG 不这么做。 D 的熵项在 SAC 里才有，DDPG 的损失里没有熵。

5. 下列哪一项是 DDPG 脆弱性的核心原因？

  1. 它要用 Fisher 向量积与共轭梯度，二阶优化容易出错
  2. 它必须等到回合结束才能更新，方差很大且样本效率低
  3. actor 会主动利用 critic 的过估计，形成正反馈
  4. 它的经验回放缓冲区太小，样本相关性会让训练发散

为什么：actor 直接沿 ∇aQ 调动作，Q 在哪里高估， actor 就把动作往哪里推；这些动作被采得更多，Q 在那里被推得更高， 误差就这样被主动放大了。

A 说的是 0019 课的 TRPO（trust region policy optimization）。 它的信赖域（规定这一步只允许在"离旧策略不太远"的范围内改）DDPG 没有。 B 说的是 on-policy（边学的那套策略就是产生数据的那套）的方法，DDPG 是 off-policy。 D 不成立：回放缓冲区的大小是超参之一，不是它脆弱的根因。

代码题 1 · 手算一步确定性策略梯度并校验

背景这是 DDPG 里 actor 的更新步。 critic 已经能说出"动作往哪个方向改，Q 会变大"，actor 就照这个方向调自己的参数， 训练循环每采一个 batch（一批样本）走一次这里。 为了让梯度能逐个元素核对，本题把 critic 换成一个简单的二次型打分函数： 动作离"理想动作"越远，分越低。输入是一批状态，输出是目标值与它的一对梯度。

请实现 dpg_actor_grad(W, b, states, ideal_actions, action_weights)，按式 (21.1) 计算，返回 (J, dW, db)。

输入

  • W：形状 (n_actions, n_states) 的浮点数组。形状就是"几行几列"， 这里是 n_actions 行、n_states 列。它是线性 actor μ(s) = W s + b 的权重。
  • b：形状 (n_actions,) 的浮点数组，actor 的偏置，每个动作维度加一个常数。
  • states：形状 (B, n_states) 的浮点数组，本批状态，B 是这一批的样本条数。
  • ideal_actions：形状 (B, n_actions)，各状态下 critic 认为最好的动作 g(s)。
  • action_weights：形状 (n_actions,)，二次型 critic Q(s,a) = −Σk wk(ak − gk(s))² 的权重。 这里的 Σ 是求和号，意思是把 k 取遍所有维度后加起来。

输出

  • 返回元组 (J, dW, db)。J 是 Python float， 等于这一批样本 Q 的平均值 meani Q(si, μ(si))， mean 就是求平均。
  • dW 形状 (n_actions, n_states)、db 形状 (n_actions,)， 是 J 对 W、b 的梯度，对整批取了平均。 梯度就是"参数往哪个方向调，J 上升最快"。

会被检验测试用有限差分核对 dW、db 的若干元素。 有限差分就是把某个参数挪一丁点，看 J 变了多少，用这个变化率近似梯度。 另外检查沿梯度走一步后 J 上升；W = 0、b = 0 时按定义照算，不做特判。 只用标准库和 numpy，不要改写入参。

卡住了？看提示
  • 先算动作矩阵：A = states @ W.T + b。 @ 是矩阵乘法；W.T 是转置，行列对调，这样形状才对得上。 A 的形状是 (B, n_actions)。
  • np.asarray(x, dtype=float) 把输入变成浮点数组并返回； 它可能和原对象是同一个数组，所以只读它，不要改它。
  • 差值 diff = A - ideal，形状 (B, n_actions)。 对动作的梯度是 grad_a_q = -2.0 * w * diff。 w 形状是 (n_actions,)，numpy 会自动把它铺到每一行上， 这个规则叫广播（形状不同也能逐元素运算的自动扩展）。
  • 目标值 J = float(np.mean(-np.sum(w * diff ** 2, axis=1)))。 np.sum(..., axis=1) 把每一行的所有列加起来，返回长度 B 的数组； np.mean 再对这批取平均，返回一个数。
  • 对 W 的梯度：dW = (grad_a_q.T @ states) / B， 形状 (n_actions, n_states)。除以 B 是因为 J 里带了平均。
  • 对 b 的梯度：db = np.mean(grad_a_q, axis=0)， 形状 (n_actions,)，也就是按列求平均。

代码题 2 · 实现软更新（Polyak 平均）

背景这是 DDPG 里把目标网络往前挪一步的那段代码，叫软更新。 actor 和 critic 各有一套目标网络参数，训练循环在更新完在线参数之后调用它： 输入是两套参数，输出是把目标网络那套原地改过之后的结果。 "慢慢跟上，不要猛跳"就是靠它实现的。

请实现 soft_update(target, source, tau)，按 target ← τ · source + (1−τ) · target 原地改写 target，并返回 target 本身。式子里的 ← 读作"更新为"。

输入

  • target：目标网络的浮点 numpy 数组，会被原地改写。 数组就是一排数字的容器；原地修改就是直接在原来那个数组上改，不新建一个。
  • source：在线网络的浮点数组，形状与 target 相同，必须保持原样。
  • tau：Python float，软更新系数，取值在 0 到 1 之间，管这次挪多远。

输出

  • 返回传进来的那个 target 对象本身，而不是另建的新数组。

会被检验测试检查两个端点与中点： tau = 1 退化成硬拷贝，tau = 0 时目标完全不动， tau = 0.5 时逐元素取加权平均； 还会检查返回值与入参是同一个对象、source 没被改动， 以及反复软更新 100 步后目标缓慢逼近而不等于 source。只用标准库和 numpy。

卡住了？看提示
  • np.asarray(x, dtype=float) 返回一个浮点数组视图，它和传入的数组共享内存， 所以在它上面做原地运算就等于改传入的那个数组。
  • 分两步原地算：先 t *= (1 - tau)，再 t += tau * s， 这两步都不新建数组。
  • 最后 return target，返回调用者传进来的那一个对象，不要返回副本。
  • 检查一下你没有写 source *= ... 这类语句，那会把 source 也改掉。
