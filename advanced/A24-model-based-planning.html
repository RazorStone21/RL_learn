进阶 · 第六部分 · 模型基、离线与对齐

基于模型与规划：Dyna、MCTS 与 AlphaZero

这一节讲一个很朴素的思路：先在脑子里把计划过一遍，再动手。要回答三个问题： 手上的问题该不该上一个环境模型；Dyna 循环怎么画； 蒙特卡洛（把一整局走完，用真实拿到的总分来估计价值）树搜索，也就是 MCTS（Monte Carlo tree search），它的选择、扩展、模拟、回传在做什么。 说穿了就是先在脑子里把很多种走法各试一遍，再决定这一步走哪个。

你会得到

  • 能区分价值基 / 策略基 / 模型基三条路线，并说出各自吃的是什么资源
  • 能写出 Dyna 的一步循环：真实经验同时更新价值与模型，再从模型里回放
  • 能实现 UCB1（upper confidence bound 1，置信上界算法）选择与 MCTS 回传，并解释 UCT 里 √(ln N / n) 项在平衡什么

第三条路线：先有模型，再"想象"

到这里为止，课程里的算法都在不建模型：DQN（deep Q-network，深度 Q 网络）一族直接学价值， 这里面又分两种：一种先估值的，叫价值基；另一种策略（看到什么状态就选什么动作的那套规则） 直接学出招习惯的，叫策略基，PPO（proximal policy optimization，近端策略优化） 与 SAC（soft actor-critic，软演员-评论家）都属于它，每次交互都是消耗品。 用它们的时候，每走一步都要去真实系统里问一次答案。

人下棋不这样。你会先在脑子里把后面几步演一遍，觉得不划算就换一条路， 真要落子之前不用碰棋盘。下面这条路线，就是让程序也学会这一手。

先认识几个后面反复出现的词。这里的策略，就是一套"看到什么状态就选什么动作"的规则。 蒙特卡洛（把一整局走完，用真实拿到的总分来估计价值）。 自举（用自己当前的估计去更新自己当前的估计，等于自己拽自己的鞋带往上提）。 智能体（做决策的那一方，也就是你写的程序）。 人类偏好（只告诉你"这两个里我更喜欢哪一个"，不给绝对分数）， 这样叫是为了和 0002 课"每个臂一个打分"的偏好区分开。

模型基（model-based，先把环境本身学出来、再用它做计划的那类方法）方法多学一样东西： 环境模型（environment model），也就是 (s, a) → (r, s′) 的预测器。 这里的 s 是当前状态，a 是你这一步的动作， r 是这一步拿到的奖励，s′ 是做完动作之后的新状态 （s′ 读作"s 撇"，就是"下一步的 s"）。 这个预测器回答的是"你会得多少分、会走到哪个新状态"。

有了它就能在"脑子里"推演，不必每次都去真实系统试。 这类方法通常用 γ（读作 gamma，折扣因子， 意思是越往后的奖励算进总分时权重越小，相当于给它打了个折）给未来价值打折，写成 Q(s,a) = r(s,a) + γ Σs′ p(s′|s,a) V(s′)。 这里的 Q(s,a) 是动作价值（在某个状态下先选某个具体动作， 之后再好好走，能拿多少总分），它的意思是：在状态 s 下先选动作 a、之后好好走能拿到的总分估计。 式子里 Σ 是求和号，意思是"把后面那串东西全加起来"。 p(s′|s,a) 是转移概率，读作"在状态 s 做动作 a 之后，落到状态 s′ 的可能性有多大"。 式子里的 V(s′) 是状态价值，意思是从新状态 s′ 出发、之后按某套策略走下去，平均能拿多少总分。 把一个状态在所有动作上的价值合起来，就得到价值函数（用来估"这个局面值多少分"的那份函数）。 环境不一定只跳到一个地方，所以要把每个可能落点的概率乘上那里的价值，再全部相加。 拿模型这样算一遍，就叫一次贝尔曼备份（backup，把"下一步的价值"倒推回来更新"这一步的价值"）。 贝尔曼方程，就是把"这一步的价值"和"下一步的价值"连起来的等式，完整讲法在 0004 课，本课只要会照着算一遍。

三分法的判据是样本从哪来，与"用了什么网络"无关：模型基的样本有一部分来自模型。 对你的实际意义是：交互越贵，模型基越值。

Dyna：理解模型基最短的一条路

Dyna 架构只有一个循环，但每一步真实交互做三件事：

  • 用真实转移 (s,a,r,s′) 更新价值 Q（普通的 Q-learning 更新）；
  • 用同一条转移更新模型：记住"在 s 做 a 会到 s′ 并得 r"；
  • 再从模型里抽若干个 (s,a)，用预测的 (r̂, ŝ′) 做额外价值更新，这叫规划。
Q(s,a) ← Q(s,a) + α [ r + γ maxa′ Q(s′,a′) − Q(s,a) ],  (r,s′) 来自真实一步或模型 (24.1)

式中 α 是学习率（每次更新时往新信息的方向挪多远；太大会来回震荡，太小就学得慢）， 它决定这一步把 Q 往新估计的方向挪一小步。

这个式子的读法是：把 Q(s,a) 更新为"原来的 Q 加上一小步修正"，方括号里是"这一步实际拿到的 r， 加上打折后的下一步最好价值，再减去原来的估计"。 式 (24.1) 里唯一的区别就是 (r, s′) 的来源。 规划次数 n 是这里最重要的旋钮：n 越大，每条真实样本被榨得越干， 但每一步的计算量也越大，而且规划得越多，模型误差被重复利用的次数也越多。

学到的模型为什么会骗你

如果模型是环境给的（下棋的规则、仿真器），规划不会引入新误差。 但多数业务里模型要从数据里学，于是出现恶性循环： 模型在某处预测偏了，规划就在那个状态上算出偏掉的价值；策略于是更爱往那块区域跑， 收到的主要又是那块区域的数据，偏差被反复强化。

两条实践建议。其一，模型基方法的效果上限由模型在策略会访问到的区域的精度决定， 而不是全局平均误差。按策略访问分布去看模型，别只看整体 MSE（mean squared error，均方误差）。 其二，先用短规划（小的 n）跑通，确认没有系统性偏差再加长。

容易想反的一点："模型基一定比无模型更省样本"。 省的是真实交互，不是总计算量；规划消耗的是 CPU 与时间。 当真实交互便宜而算力紧张时（比如有便宜的仿真器），模型基反而不划算。

MCTS：把算力压在最有希望的分支上

当环境模型是规则或仿真器（棋类、调度、组合优化）， 就能在决策时做前瞻搜索。蒙特卡洛树搜索（MCTS， Monte Carlo tree search） 意思是在你真正走这一步之前，先在脑子里把以后很多种走法各试很多遍， 看哪一步试下来的结果普遍更好，然后只走那一步。蒙特卡洛在这里指 "把一整局走完，用真实拿到的总分来估计价值"。它反复执行四步：

  • 选择（selection）：从根开始，用 UCT 规则一层层往下走，直到遇到还有未扩展子节点的节点。
  • 扩展（expansion）：在这个节点上新建一个子节点，代表一个还没试过的动作。
  • 模拟（simulation）：从新节点出发，用快速策略（随手走）跑到终局， 得到一个回报（从此刻起一直到这局结束，把每一步奖励加起来得到的总分）。
  • 回传（backpropagation）：把回报沿路径反向传回，更新沿途节点的访问次数与平均价值。

第三步提到的回报，就是从此刻起一直到这局结束、把每一步奖励加起来得到的总分。 衡量一个局面好不好，看的是这个总分，不是眼前这一步拿了多少分。

选择那一步用的 UCT（upper confidence bound applied to trees，树上的置信上界） 就是把 0002 课的 UCB（upper confidence bound，置信上界）搬到树上：

a* = arg maxa [ Q(s,a) + c √( ln N(s) / N(s,a) ) ] (24.2)

第一项是利用（估值好的分支多走），第二项是探索 （访问少的分支优先）。子节点都没被访问过时那项按无穷大处理， 于是每个动作至少被试一次，这就是 MCTS 不需要额外探索策略的原因。

AlphaZero：把网络塞进 MCTS

纯 MCTS 的弱点很实际：随机模拟的回报噪声大，每次决策还要跑到终局。 AlphaZero 用两个网络替换掉这两部分：

  • 价值网络 vθ(s)（θ 是网络参数）直接给出局面评估，取代随机模拟到终局；
  • 策略网络 pθ(a|s) 给出先验概率，进入 UCT 的探索项，让搜索一开始就往像样的着法集中；
  • 搜索结束后，访问次数的分布被当作策略网络的学习目标，胜负当作价值网络的目标；数据全部来自自对弈，所以不需要人类棋谱。

顺带认识两个词：出招的那张策略网络叫 actor（出招的那一方，负责决定动作， 也叫"策略网络"），打分的那张价值网络叫 critic（打分的那一方，负责估计局面值多少分， 也叫"价值网络"）。一边出招、一边打分，再用分去改出招习惯，这套搭法叫 actor-critic。

这套循环有效的原因可以一句话概括：网络让搜索变强，搜索又给网络提供比它自己更好的目标。 代价是搜索与训练互相纠缠，出问题时很难判断是哪一边坏了。

什么时候值得上模型

你的处境建议
有可靠仿真器 / 规则，回合制、分支可控规划优先：MCTS（配网络则更强）

课后练习

1. 区分"模型基"与"无模型"方法，最本质的判据是什么？

  1. 是否使用了神经网络来拟合价值函数或策略函数那部分参数
  2. 用于更新的样本是全部来自真实交互，还是有一部分来自模型
  3. 是否需要一个已知的转移概率表，从而完全不需要与环境交互
  4. 是否在每次决策时都执行搜索，而不是让策略网络直接输出动作

为什么：判据是样本来源。模型基方法会从模型（学到的或已知的） 生成"想象"样本参与更新；无模型方法的每一个更新样本都来自真实交互。 这也直接决定了两者在"交互贵不贵"这个维度上的取舍。

A 无关：DQN 是纯粹的模型无关方法，却也用神经网络， 用不用网络和建不建模型是两件事。C 把"有模型"和"不用交互"混为一谈： 学到的模型本身要靠交互数据训练，而且几乎所有实用方法仍需真实数据校正。 D 描述的是规划式决策，是模型基常见的用法，不是定义。

2. Dyna 用一个学到的模型做规划，最主要的风险是什么？

  1. 规划次数越多，真实环境的交互次数会随之增加，总成本上升
  2. 模型只能记住已经访问过的转移，于是策略无法尝试全新的动作
  3. 模型误差会在反复规划中被不断复用，策略在想象里越走越偏
  4. 它需要额外训练一个策略网络，参数变多之后更容易过拟合数据

为什么：规划用的 (r̂, ŝ′) 是模型的预测。 一旦某处预测有系统偏差，价值更新就会把偏差固化；策略随后更频繁地访问那块区域， 数据、模型、价值三者互相强化，最终学到一个"在想象里最优"的策略。

A 说反了：规划的作用是减少真实交互，代价是算力。 B 混淆了"模型只能预测见过的转移"与"智能体不能选没做过的动作"： 探索动作仍然由 ε-greedy（ε 是探索率）之类的机制决定。D 描述的是 actor-critic 的结构， Dyna-Q 在表格型设定下连神经网络都不需要。

3. MCTS 的四个步骤里，"回传"这一步在做什么？

  1. 把模拟得到的回报沿路径反向传播，更新沿途节点的统计量
  2. 把根节点选出的动作发回给环境执行，并接收下一状态与奖励
  3. 把当前节点的价值估计向上取最大，替换父节点原有的估值数据
  4. 把搜索树里访问次数最少的那些分支剪掉，以节省内存与时间

为什么：回传就是把新拿到的回报带回所有祖先节点： 每个节点的访问次数 N 加一，平均价值 Q 向这个回报方向小幅移动。这样下一次选择时，UCT 用的统计量才是最新的。

B 混淆了"回传（backpropagation）"与"把动作施加到环境（step）"。 C 说成取最大值，而 MCTS 用的是访问平均值，不是最大。 D 描述的是剪枝，MCTS 靠的是把算力集中在访问次数多的分支上， 而不是显式删掉其他分支。

4. UCT 里的探索项 c√(ln N(s) / N(s,a)) 起什么作用？

  1. 它把所有的动作价值归一化到同一量纲，避免不同分支量级不一致
  2. 它随子节点访问次数增加而衰减，让少被访问的分支优先被尝试
  3. 它和先验概率相乘，使搜索过程完全依赖策略网络给出的偏好
  4. 它保证每次决策一定选到全局最优的那条分支，与访问次数无关

为什么：分母是子节点的访问次数，访问越多这一项越小； 分子是父节点访问次数的对数，父节点被访问越多，所有子节点的不确定性一起变大。 两者合起来就是 UCB 的形状：把预算分给"还没试够"的分支。

A 弄错了作用：它是用来平衡探索与利用的加项，不做归一化。 C 描述的是 AlphaZero 在 UCT 上再乘策略网络先验的变体（式 A.31）， 纯 MCTS 里没有这一项。D 是过强的承诺：UCT 是启发式，不保证选到最优分支。

5. AlphaZero 不需要人类棋谱，根本原因是什么？

  1. 它直接求解棋类规则对应的最优价值函数，因此不必再学习策略
  2. 它的价值网络在初始化时就通过规则推导出局面评估，无需训练数据
  3. 它的 MCTS 搜索足够强，只靠搜索就能达到超越人类的棋力水平
  4. 它的监督信号来自自对弈的胜负与搜索访问分布，不依赖人类标注

为什么：AlphaZero 的学习目标是自产的：胜负给价值网络当标签， 搜索得到的访问次数分布给策略网络当标签。数据由"当前的自己"生成， 所以人类棋谱这类外部标注就不是必需品。

A 把"求解"和"搜索"混了：它不解析求解棋类的最优价值，只用自举与自对弈逼近。 B 不成立：随机初始化的价值网络给不出有意义的评估，它的精度靠训练逐步提升。 C 夸大了搜索：论文里的棋力来自搜索与网络的组合，把网络换掉、只留随机模拟的 纯 MCTS 会明显弱得多。

代码题 1 · 写 UCB1 分数与 UCT 选择（numpy）

背景这是 MCTS 选择阶段的两步。树里每个节点记着平均回报 Q 与访问次数 N，UCB1 把 Q 和一项随访问次数衰减的探索奖励加起来，UCT 挑分数最高的子节点继续往下走，搜索循环每下探一层就调用一次。输入是父节点与子节点的统计量，输出是分数数组和选中的下标。

请实现 ucb1_scores(q_values, child_counts, parent_count, c) 与 uct_select(q_values, child_counts, parent_count, c)，分数按式 (24.2) 算：

scorea = Qa + c √( ln Nparent / Na )，Na = 0 时取 inf

输入

  • q_values：形状 (n_children,) 的浮点数组，各子节点已观测的平均回报 Qa。
  • child_counts：形状相同的浮点数组，各子节点的访问次数 Na。
  • parent_count：父节点的访问总次数 N(s)，传进来的是原始次数而不是对数。
  • c：Python float，探索常数。

输出

  • ucb1_scores 返回形状与 q_values 相同的浮点数组；计数为 0 的未访问子节点必须是 np.inf。
  • uct_select 返回一个 Python int 下标，即分数最高子节点的位置，并列时（包括多个未访问）取最小下标。

会被检验测试检查形状、未访问项为 inf、c = 0 时退化成按 Q 贪心（按现有估计挑看起来最好的那个），以及 Q 略低但访问次数远少的子节点会被探索项顶到前面。不要原地改写入参，只用标准库和 numpy。

卡住了？看提示
  • 先做一份副本 score = np.array(q_values, dtype=float)，别原地改调用者的数组。
  • 未访问的位置用布尔掩码挑出来：score[counts == 0] = np.inf， 只对访问过的算根号项，避免除零。
  • np.argmax 遇到并列返回第一个下标，正好是你要的"最小下标"。

代码题 2 · 写 MCTS 回传与一步规划

背景这是 MCTS 一次模拟的后半段加一步规划。选择到叶子后，回传把回报摊到路径上的每个节点；一步规划用已知模型做贝尔曼备份；策略从 Q 表抽贪心动作。输入是节点统计量或模型参数，输出是更新后的统计量与动作下标。

请实现 backpropagate(counts, values, parents, leaf, reward)、plan_one_step(rewards, transitions, values, gamma) 与 greedy_policy(q_values)。

① 回传从叶子 leaf 沿父指针走到根（parents[r] < 0），用加一后的计数更新路径上每个节点 t：

Nt ← Nt + 1,  Qt ← Qt + ( reward − Qt ) / Nt

输入

  • backpropagate 的 counts、values：长度 n_nodes 的浮点数组，存访问次数 N 与平均回报 Q；parents 等长整数数组，负值表示根；leaf 起始下标；reward 回报标量。
  • plan_one_step 的 rewards：形状 (n_actions, n_states) 的奖励表；transitions 形状 (n_actions, n_states, n_states)，[a, s, s′] 项是转移概率；values 形状 (n_states,) 的状态价值 V；gamma 折扣因子。
  • greedy_policy 的 q_values：形状 (n_actions, n_states) 的 Q 表。

输出

  • backpropagate 原地更新并返回 (counts, values)，即这两个数组本身；回传到根即停。
  • plan_one_step 返回同形状 (n_actions, n_states) 的浮点数组，元素为 r(s,a) + γ Σs′ p(s′|s,a) V(s′)；V 为负时照算，不做特判。
  • greedy_policy 返回长度 n_states 的 int64 数组，每状态取 Q 最大的动作下标。

会被检验测试检查回传路径上的计数与均值（回传到根即停、均值用加一后的计数）、一步备份数值（含 V 为负）与策略 dtype。只用标准库和 numpy。

卡住了？看提示
  • 回传的循环结构：t = leaf，处理完 t = parents[t]，直到 t < 0。
  • 均值更新要先把 counts[t] 加一，再用新的计数做除法。
  • 备份就是一次矩阵乘法：r + gamma * transitions @ values， 其中 transitions 形状为 (n_actions, n_states, n_states)。
