进阶 · 第二部分 · 无模型方法

蒙特卡洛方法

这一节解决没有模型时的第一个问题：你不知道环境内部的规律， 但仍然能靠一次次实际跑出来的完整回合，估出每个状态值多少分。这个办法叫蒙特卡洛方法， 这一节会把它讲清楚，也会讲清它的硬伤在哪里。

你会得到

  • 能写出首次访问蒙特卡洛预测的估计式，并说清每个符号对应代码里的什么
  • 能解释它为什么不需要环境模型，以及它需要什么前提
  • 能说出它与 TD（temporal difference，时序差分）在偏差与波动上的差别，判断自己的场景适不适合用它

不知道模型，但可以动手试

先说清楚"没有模型"是什么意思。第 0005 课的动态规划 需要你先知道一组概率。所谓转移概率，就是做完一个动作之后会跳到哪个状态、各有多大的可能性， 以及跳到那里能拿多少奖励。库存业务里就是"明天客户会买多少件，各种情况各占几成"。 这在现实里几乎永远拿不到。

拿不到概率，不代表什么都做不了。你可以直接去试：按现在的做法跑一天， 看看到底发生了什么，把结果记下来。这么跑很多遍，就攒下了一条条真实的经历。

蒙特卡洛方法（把一整局走完，用真实拿到的总分来估计价值） 用的就是这些经历，完全不需要那组概率，因此属于 无模型（model-free，只用交互得到的数据，不去问环境内部规律）方法。 名字来自赌场里的蒙特卡洛，说的就是"用大量随机试验去估一个数"。

这个想法你已经用过。想知道一枚硬币正面朝上的可能性有多大，你不会去拆开硬币量它的重心， 而是抛它一百次，数一数正面出现了几次。抛出来的结果就是"经历"，最后那个比例就是你的估计。

用采样回报的算术平均代替期望

先补两个零基础缺口，后面每一课都要用。

第一个是概率。概率就是"平均一百次里大约发生几次"：说某件事有 0.5 的概率发生， 就是平均一百次里大约有五十次发生。随机游走里"每步以 0.5 的概率向左走一格"， 意思是平均一百步里大约五十步向左、五十步向右。

第二个是期望。期望就是"同一件事重复很多次之后的平均结果"。 抛一枚公平硬币，正面得 1 分、反面得 0 分，重复很多次，平均每次大约得 0.5 分， 这个 0.5 就是得分的期望。注意它不必是某一次真的会出现的分数。

现在回到价值估计。给定一套策略（看到什么状态就选什么动作的规则），从起点跑完一整局，这一局就结束了。 这样的一整局叫回合（从开始到结束的一整局）。 跑一趟记下来的这串东西是：s0, a0, r1, s1, … , rT， 其中字母右下角的小字母表示它是第几步的量，比如 s0 是第 0 步的状态。

把一路上拿到的分数按折扣折算，加起来得到一个总分。 这个总分叫回报（从现在起一直到结束，把每一步奖励加起来的总分）。 折扣的力度由折扣因子（越往后的奖励，算进总分时权重越小，等于给它打了个折） 决定，它通常写作 γ。γ 是折扣因子。

于是折扣回报（每个奖励都先打折、再全部加起来的总分）可以写成： Gt = rt+1 + γrt+2 + …。 意思是从第 t 步往后，第一步的奖励原价算，第二步打一次折，第三步打两次折，以此类推。

蒙特卡洛（英文全称 Monte Carlo，本课简称 MC）的做法直接得近乎粗暴： 同一个起点多跑几局，把每次拿到的回报加起来再除以次数，这就是算术平均。

V(s) ≈ (1 / N(s)) Σi=1N(s) Gi(s) (7.1)

公式 (7.1) 里，Σ 是求和号，意思是"把后面那串东西全部加起来"； N(s) 是状态 s 一共被走到过多少次；Gi(s) 是第 i 次走到 s 时拿到的回报。 整条式子读作：把在 s 处收集到的所有回报加起来，再除以次数，就是 s 的价值估计。

还有一种分法要知道。首次访问（first-visit）的做法是： 一个回合里状态 s 可能出现多次，只统计第一次出现之后的回报。 每次访问（every-visit）则每次都统计。 两者在回合数足够多时收敛（一轮轮算下去，数值不再明显变化，稳定下来了）到同一个值[Sutton & Barto §5.1]，实践里首次访问更常用，因为它的证明更干净。

实现上不必存下所有回报，用增量式样本平均即可：

V(s) ← V(s) + (1 / N(s)) [ G − V(s) ] (7.2)

公式 (7.2) 里的箭头读作"更新为"。N(s) 是 s 被访问的次数。 访问越多，修正幅度越小，这就是"平均"在起作用。

把 1 / N(s) 换成一个固定的小常数，就得到能跟着变化走的版本。 这个常数叫学习率（每次更新时，往新信息的方向挪多远），通常写作 α。α 是学习率。 后面 TD 就是用这种写法。

蒙特卡洛控制：保证每个动作都被试到

前面只讲了"给一套策略打分"，这件事叫 策略评估（给定一套策略，算出它到底值多少分）。 但我们的目标不止是打分，还要把策略改好。要改策略，就得知道每个动作值多少分， 也就是动作价值（在某个状态下先选某个具体动作，之后再好好走，能拿多少总分）， 通常写作 Q(s, a)。

为什么一定要动作价值？因为改策略的时候要比较"这个状态下选哪个动作更好"。 只有动作价值能直接回答这个问题：挑出让 Q 最大的那个动作， 这个"挑出最大值对应的选择"的动作，读作 argmax（挑出让后面那个式子最大的那个选择）。

问题来了。如果行为策略一直只挑当前看起来最好的动作，那些从没被选过的 状态动作对就一次都没被采到过，它们的 Q 一直停在初始值上，等于错的。 而改策略的时候会拿这个错值去比较，改出来的策略就建立在噪声上。 "一直只挑当前看起来最好的"，这种挑法叫 贪心（在当前估计里挑看起来最好的那个）。

所以要保证每个动作都有机会被试到，常用的办法有两个。

  • 探索起点（exploring starts，每个回合从随机挑的一对状态和动作开始）： 这样任何状态动作对都有机会被采到。
  • ε-soft 策略（让每个动作都保留一点被选中的概率，谁都不许变成 0）： 行为策略对每个动作至少留 ε / |A| 的概率。 式子里的 ε 是一个 0 到 1 之间的小数， |A| 是动作的总个数。

把这两件事合起来，就是 on-policy（边学的那套策略，就是正在用来产生数据的那套）的蒙特卡洛控制： 用 ε-soft 的行为策略采回合、估计 Q，再把行为策略换成对 Q 的 ε-greedy 版本。 它仍然是 ε-soft 的，所以下一轮还能继续探索。这里的行为策略就是真正在环境里做决定的那套规则， 它会随着 Q 一起变。

off-policy 与重要性采样

上面讲的是"边学的那套策略，就是正在产生数据的那套"。这种情形叫 on-policy（边打边改自己的打法）。还有一种情形：数据是旧的策略跑出来的， 你想用这批数据去评估另一套新策略。这叫 off-policy（看别人的录像学自己的打法）。

这两套策略不一样，直接用旧数据算平均就会偏。修正办法是给每个回报乘一个比例。 比例的含义是：这个动作在新策略下出现的可能性，除以它在旧策略下出现的可能性。 这个比例叫重要性采样（用另一套策略产生的数据，来估计当前策略的表现，需要按概率比例做修正）比。这个比值写作 ρ。ρ 是重要性采样比。 它的定义是 ρ = Πt π(at | st) / b(at | st)。 式子里的 Πt 是连乘号，意思是把每一个时间步的比值都乘起来。

这个连乘有个坏处：它会让估计的波动随回合长度迅速变大。 几十步的回合里，只要有几步的比值明显大于 1，乘起来就会把回报放大成极端值。

所以在实践里，直接这样做的蒙特卡洛很少用。好用的 off-policy 方法要到 Q-learning 才出现，在第 0010 课。

硬伤：必须等回合结束

蒙特卡洛有一个绕不过去的限制：它要拿到完整的回报 G 才能更新。 回合还没结束，它就一个数也学不到。

如果一局要等三个月，或者任务根本不结束（持续运营的系统），这个办法就直接失效。 而且 G 把一个回合里所有的随机性都堆进了一个数，波动很大， 同一个起点的两次结果可能差得远。

下一课的 TD 就是冲着这两点来的：只用一个即时奖励加上"下一步的估计"就能更新，边走边学。

什么时候该用它

适用条件可以浓缩成一句：你能反复拿到完整的、有明确起止的回合。 一次促销周期、一局游戏、一轮 A/B 测试都算回合；一个永不结束的推荐流不算。

它还有一个优点：对环境的假设最少。连"下一步只取决于现在"这种条件都不需要满足， 也能拿来用（只是那时候你估的东西含义变了）。 这让它成为最保险的基线（拿来做对照的基准方法）， 代价是样本效率（拿到同样多的经验能学多好）低：同样的经验量，它学得比别人慢。

上面的演示把它与 TD(0) 放在同一个随机游走环境上对比：它的误差曲线起步很高， TD 一开始就压下来。把它的 α 调小，它最终能收敛到更低的误差。效率与极限精度的取舍， 就是下一课的主题。符号不确定时可以查符号表。

课后练习

1. 蒙特卡洛方法与动态规划相比，最根本的差别是什么？

  1. 不需要环境的转移概率，只靠采样得到的完整回合估计价值
  2. 不需要折扣因子，因此能直接处理无限长的回报序列
  3. 收敛速度一定快于动态规划，因为它不做全量的备份
  4. 只能处理随机环境，遇到确定性环境时就会完全失效

为什么：动态规划的更新要知道 p(s', r | s, a) 这组概率， 才能对着所有可能的情况求平均；蒙特卡洛用真实跑出来的回报取平均，直接绕过了这组概率， 代价是需要完整的回合和更多样本。

B 错：蒙特卡洛照样用折扣，处理无限长回报靠的是 γ 而不是"不需要 γ"。 C 说反了：蒙特卡洛的样本效率通常低于动态规划（dynamic programming，DP）。 D 也错：确定性环境照样能采样，只是每条轨迹重复而已。

2. 首次访问与每次访问这两种统计方式的区别在哪里？

  1. 首次访问只估计回合的起始状态，每次访问估计全部状态
  2. 首次访问每个回合只更新一次，每次访问沿路径更新多次
  3. 首次访问只统计状态首次出现后的回报，每次访问都统计
  4. 首次访问必须用常数步长，每次访问必须用样本平均值

为什么：差别只在于"同一个回合里状态出现多次时算几次"。 首次访问只在第一次出现时记一笔，每次访问每次出现都记一笔；两者极限相同。

A 把"首次"理解成了"只更新起点"，那是探索起点的概念，不是这个。 B 也说错了对象：一回合里可能更新很多个状态，只是每个状态最多记一次。 D 把访问规则和步长规则混在一起，二者互不绑定。

3. 为什么蒙特卡洛控制需要探索起点或 ε-soft 行为策略？

  1. 因为访问次数越多，环境反馈的奖励数值才会越准确
  2. 因为这套办法要求每个状态被访问一个固定的次数才算稳定
  3. 因为不访问所有动作就无法计算折扣因子对回报的影响
  4. 因为没被访问过的 (s, a) 没有估计，改进会用到错值

为什么：这套办法只用"见过的东西"做平均。某个状态动作对从没被采到， 它的 Q 就一直是初始值，而改策略时会拿这个错值去比较，甚至选中它。

A 把"奖励准确"和"价值被采样"混为一谈：奖励是环境给的，不需要多访问才变准。 B 编造了一个"固定次数"的要求：收敛需要的是访问次数趋于无穷，不是某个固定配额。 C 更是无关：折扣因子是你设定的常数。

4. 直接用重要性采样做 off-policy，典型问题是什么？

  1. 采样比连乘会让估计的方差随回合长度迅速增长
  2. 采样比恒等于 1，导致目标策略始终无法被真正评估
  3. 行为策略必须是完全随机的，否则采样比没有定义
  4. 必须额外知道环境模型，否则采样比无法被计算出来

为什么：采样比是每个时间步比值的连乘。比值可以远大于 1， 连乘之后能把一个普通回报放大成极端值，于是估计的方差随回合长度爆炸式增长。

B 说反了：采样比只在两个策略完全一致时才恒为 1，那时根本不需要 off-policy。 C 错：行为策略只要对所有动作概率为正即可（soft），不必均匀。 D 也错：采样比只用到两个策略在已发生动作上的概率，不需要环境模型；需要模型的是 DP。

5. 下列哪种业务场景最适合用蒙特卡洛方法？

  1. 持续运行、永不结束并且需要实时决策的竞价系统
  2. 做一次决策就要等上三个月才能看到结果的长期项目
  3. 能反复完整跑完、有明确起止的促销周期或一局游戏
  4. 每一步都必须立刻更新价值估计的在线推荐服务场景

为什么：蒙特卡洛的唯一硬前提是"能拿到完整回合"。促销周期、一局对弈这种 有明确起止、可以反复采样的场景，正好满足；而且它们通常对样本效率要求不高。

A 和 D 都缺"回合"这个前提，属于持续型任务，应该用能单步更新的 TD 类方法。 B 虽然形式上是回合，但一个回合三个月，它在拿到第一个回报前什么都学不到， 工程上不可接受，TD 的用武之地就在这里。

代码题 1 · 用首次访问蒙特卡洛估计状态价值

背景从这一节起没有环境模型可用，只能靠完整回合的采样。 这一题验证的就是蒙特卡洛预测：同一条随机走法反复跑很多局，把每局拿到的总分取平均， 用这个平均值当作每个状态的价值。mc_prediction 是价值估计的第一步， "给一套策略打分"时就调用它，后面还要拿它的结果和 TD 对比。 返回的 V 里，V[s] 表示"从状态 s 出发走到终点，平均能拿多少分"。

环境是 Sutton & Barto 的 5 状态随机游走：状态编号 0 到 6， 0 和 6 是终止状态，走到 0 得 0 分、走到 6 得 1 分。 中间 5 个状态每走一步，以 0.5 的概率向左一格、0.5 的概率向右一格（蒙特卡洛的英文是 Monte Carlo，本课简称 MC）， 也就是平均一百步里大约五十步向左。每局都从状态 3 出发。

请实现 mc_prediction(n_episodes=20000, gamma=1.0, seed=0)。

输入

  • n_episodes：int，采样多少个完整回合，默认 20000；
  • gamma：float，折扣因子，默认 1.0；
  • seed：int，随机种子，默认 0。

输出

  • 返回 np.ndarray，形状 (7,)，float：V[s] 是状态 s 的价值估计；状态 0 与 6 是终止状态，价值保持 0。

会被检验返回值是 numpy 数组且形状为 (7,)；V[0] 与 V[6] 保持 0；V[1..5] 与真值 s/6 的偏差小于 0.05；V[5] 比 V[1] 高出 0.4 以上。上面这些精度只有在按首次访问统计、用样本平均更新时才达标，同一个回合里重复出现的状态只算第一次，不要换成固定步长；随机数必须来自 np.random.default_rng(seed)，不要用全局 np.random；只用标准库加 numpy。

卡住了？看提示
  • 第一句先建随机数生成器：rng = np.random.default_rng(seed)， 后面每一步的随机数都从它取，这样同一个种子必然给出同一串数。
  • 再建两个长度 7 的数组：V = np.zeros(7) 放价值估计， counts = np.zeros(7) 放每个状态被走到过多少次。 np.zeros(7) 返回"装了 7 个 0 的一维数组"，下标从 0 开始。
  • 每个回合从 s = 3 出发，用一个 while True 循环走： 每次抽 rng.random()（它返回 0 到 1 之间的一个随机小数）， 小于 0.5 就让 s 减 1，否则加 1，并把走过的新状态追加进一个列表。 走到 0 或 6 就 break。
  • 回合结束后先给回报定初值：走到 6 时 G = 1.0，走到 0 时 G = 0.0。
  • 用 for st in reversed(轨迹列表) 从末尾往前遍历，每遇到一个状态先做 G = r + gamma * G 把折扣补上（这里的 r 是进入该状态那一步的奖励， 除终点外都是 0），再用 seen 集合判断这个状态是不是本回合第一次出现， 是的话就让 counts[st] += 1，再做增量平均 V[st] += (G - V[st]) / counts[st]。
  • 循环跑完 n_episodes 个回合后 return V。 两个终止状态的价值不动，所以一直是 0。

代码题 2 · 用 ε-soft 蒙特卡洛控制解一个小网格

背景只估价值不够。要改策略，就得先知道每个动作值多少分， 也就是动作价值 Q(s, a)；拿到 Q 之后对每一行取 argmax，就得到"每个状态选哪个动作"的规则。 mc_control 做的是 on-policy（边学的那套策略，就是正在产生数据的那套） 的蒙特卡洛控制：在 3×3 网格上反复跑完整回合， 用探索起点加 ε-greedy 的行为策略保证每个状态动作对都被试到。 业务上对应能反复跑完、又有明确起止的场景，比如一局游戏或一轮促销周期。

请实现 mc_control(episodes=20000, epsilon=0.1, gamma=1.0, seed=0)。环境是 3×3 网格：状态按行优先编号 0–8，8 是终止状态（到达即结束，奖励 0），其他状态每走一步奖励 −1；动作编号 0=上、1=右、2=下、3=左，撞到边界时原地不动；每个回合从一个随机非终止状态、一个随机动作开始，之后按当前 Q 的 ε-greedy 选动作，平局取下标小的。更新用首次访问的样本平均。

输入

  • episodes：int，采样回合数，默认 20000；
  • epsilon：float，ε-greedy 中以该概率随机选动作，默认 0.1；
  • gamma：float，折扣因子，默认 1.0；
  • seed：int，随机种子，默认 0。

输出

  • 返回 np.ndarray，形状 (9, 4)，float：Q[s, a] 是状态动作价值，从全 0 开始累积。

会被检验Q 的形状是 (9, 4)；对 Q 取 argmax 得到的贪心策略里，终点左侧那格（状态 7）选动作 1（右），终点上方那格（状态 5）选动作 2（下）；从状态 0 出发沿贪心动作走，6 步以内到达终点 8；随机数只用 np.random.default_rng(seed)；只用标准库加 numpy。

卡住了？看提示
  • 开局先写 rng = np.random.default_rng(seed)， 再用 Q = np.zeros((9, 4)) 和 counts = np.zeros((9, 4)) 建两个二维数组。形状 (9, 4) 表示 9 行 4 列， 下标写成 Q[s, a]，行下标和列下标都从 0 开始。
  • 另写一个小函数当行为策略：先抽 rng.random()， 小于 epsilon 就用 int(rng.integers(0, 4)) 随机取一个动作下标 （rng.integers(0, 4) 返回 0、1、2、3 中的一个整数，右端 4 取不到）， 否则用 int(np.argmax(Q[s])) 取 Q 最大那一列的下标。
  • 每个回合按题面从随机的一个非终止状态和一个随机动作开始， 然后在 while True 里用题面给的 move 规则算出下一个状态， 奖励是"进入终点得 0，否则得 −1"， 把 (s, a, r) 追加进轨迹列表，再用行为策略选下一个动作，直到走到终点。
  • 回合结束后从轨迹末尾往前推：每退一步先算 G = r + gamma * G。 用 seen 集合保证同一个状态动作对在一个回合里只统计第一次出现， 是第一次就 counts[s, a] += 1，再 Q[s, a] += (G - Q[s, a]) / counts[s, a]。
  • 跑完 episodes 个回合后 return Q。
