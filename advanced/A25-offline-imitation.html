离线 RL 与模仿学习

这一节的场景很窄：你手上只有一份过去攒下来的记录，不能拿真实系统做实验。 这种"不能与真实环境交互，只能用已经攒下来的历史数据学"的做法叫离线， 下面统一叫离线 RL。在这个约束下，照着别人的做法学能走多远、什么时候会崩、 什么条件下才值得上离线 RL，下面逐个回答。

你会得到

  • 能用一句话说清分布偏移，以及它为什么让 Q 不可信
  • 能解释复合误差为什么让行为克隆越走越偏，并给出一条诊断方法
  • 能判断日志够不够做离线 RL，以及该先跑什么基线

设定：只有日志，没有实验

前面所有算法都假设你能反复与环境交互：试、失败、召回、再试。 真实业务里这几乎从不成立：生产线不能停下来陪你探索，用户也不能被随机发优惠券。 先交代几个这一节反复要用的词。

监督学习（拿"题目 + 标准答案"来学的机器学习方式，像做一本有答案的练习册）。 策略（一套"看到什么状态就选什么动作"的规则）。 回报（从现在起一直到结束，把每一步奖励加起来的总分）。 价值函数（从某个状态出发，按某套策略走下去，平均能拿多少总分）。 自举（用自己当前的估计去更新自己当前的估计，等于自己拽自己的鞋带往上提）。 函数逼近（状态太多记不下整张表，干脆用一个带参数的函数去"猜"值）。 基线（打分时先减掉的一个参照值，只用来压住波动，不改变平均方向）。

再看这一节另外几个词。动作空间（一个状态下所有能选的动作合起来有多大）。 动作价值（在某个状态下先选某个具体动作，之后再好好走，能拿多少总分）。 经验回放（把走过的每一步都存进一个池子，训练时从池子里随机抽一批出来用，像个错题本）。 过估计（因为总是取最大值，估计出来的分数会偏高）。 双 Q（用两套估计分别负责"挑动作"和"打分"，压住总是高估的毛病）。 超参（需要你自己设定、而不是训练学出来的参数，像火候）。 收敛（一轮轮算下去，数值不再明显变化，稳定下来了）。 人类偏好（只告诉你"这两个里我更喜欢哪一个"，不给绝对分数）， 这样叫是为了和 0002 课那种"每个臂一个打分"的偏好区分开。 交叉熵（衡量两套概率分布差多远的一个常用指标）。 重要性采样（用另一套策略产生的数据来估计当前策略的表现，需要按概率比例做修正）。 这两个词这一节不展开，知道大致用途就够了。

你手上只有一份固定日志：(s, a, r, s′) 记录， 由某个行为策略（behavior policy, πβ）产生，此后不再与环境交互。 这就是离线 RL（offline RL，不能与真实环境交互， 只能用已经攒下来的历史数据学）的设定，也叫 batch RL。 历史操作记录、专家演示、别的模型跑出的轨迹都能用。

它和经验回放的区别在于：回放缓冲区里也是旧数据，但它为当下的探索服务， 随时能用新样本补充；离线数据是封口的，采样不到那些"我想知道"的状态。术语对照见 术语表。

分布偏移：离线 RL 失败的头号原因

把 Q-learning 直接搬到离线数据上，会发生一件很隐蔽的事：策略会去查询那些 日志里从未出现的 (s, a)， 想知道"如果当时选了另一个动作会怎样"。这些位置的 Q 没有数据约束， 完全由函数逼近器的外推决定，而外推可以是任意值。

这里插一句术语：正在学的那套策略，与产生手上这批数据的策略， 可以是同一套，也可以不是。是同一套叫 on-policy（边学的那套策略，就是正在用来产生数据的那套）； 不是同一套叫 off-policy（边学的那套策略，不是产生数据的那套，数据来自另一套旧策略）。 Q-learning 属于后者，正因为它允许"拿旧数据学新策略"，离线这种设定才会被提出。 下一批读它时，如果外推给出的估计偏了，整套学习就会被带偏。

更糟的是策略会主动去找那个任意值：某处 Q 被外推得偏高，策略就更愿意去那里， 越去越没数据，Q 越不可信。这个自我强化的过程叫 外推误差（extrapolation error）， 整体现象叫分布偏移（distribution shift）。

这条链路有两个推论。第一，离线 RL 的核心动作只有让价值函数在数据支撑之外保持保守， 换优化器没有用。第二，评测要小心：日志上算出来的分数不可信（它是 离线评估的经典难题）， 上线必须走 shadow 模式（新策略只在后台跟着真实流量跑、不真的生效，先看它会怎么决策）、小流量 A/B 测试（只让一小部分用户看到新方案）与护栏指标（用来兜底的安全线，比如"下单成功率不能掉"）。

行为克隆：该先跑的那件事

最省事的做法叫模仿学习（imitation learning， 不去试错，直接学着模仿别人的动作），生活里的说法就是"看师傅怎么做就跟着做"。 它里面最朴素的一种叫行为克隆（behavior cloning, BC， 把"别人看到什么就做什么"当成监督学习来学），说白了就是抄作业。

行为克隆（behavior cloning, BC）把日志里的 (s, a) 当监督学习样本，直接拟合 πθ(a|s)，θ（策略参数）是待学参数：连续动作退化为均方误差， 离散动作就是分类交叉熵。它不做价值估计、不做自举、不做探索，所以稳、便宜、好解释。

它也有一个结构性缺陷：复合误差（compounding error）。 训练时模型只在自己见过的状态上犯错；预测稍微偏一点，环境就把你推到 分布边缘的状态，那里的动作覆盖更差，误差更大，于是偏得更远。 误差随步数累积，最坏可达 O(εT²)。式中 ε（单步误差）是每步的偏差上界。

一个立刻能用的诊断：拿日志后半段的轨迹当测试集，让学到的策略从同一初始状态重走一遍， 看动作偏差是否随步数单调放大。训练集准确率很高、重放误差却一路涨，多半是复合误差。

DAgger：把专家的纠正补回来

DAgger（dataset aggregation，把数据一轮轮攒起来）针对的就是上面那个诊断： 训练分布与策略实际访问的分布不一致，那就让专家去看策略会走到哪里。 每轮用当前策略跑出新状态，请专家（或人工审核）标注正确动作，追加进数据集重训； 几轮后训练分布向策略的真实分布靠拢。

代价很明确：你必须能问到专家，而且每轮都要新数据。 只能查历史日志的场景用不了 DAgger，只能回到离线那一侧。

离线 RL：让价值在数据外保守

离线 RL 要解决的问题比 BC 更进一步：数据里混着次优行为时， 怎么学出一个比"数据平均水平"更好的策略。主流做法共享同一个核心，约束价值或约束策略：

  • CQL（conservative Q-learning，保守 Q 学习）在贝尔曼误差之外加一项惩罚： 压低策略偏好、但日志里没出现过的动作的 Q，保留出现过动作的 Q。 不确定性由此变成保守。
  • IQL（implicit Q-learning，隐式 Q 学习）用期望回归（expectile regression） 估计价值，不做"数据外的最大化"，所以不需要显式约束，实现也更简单。
  • BCQ / TD3+BC换一条路：直接约束策略本身， 让新策略只能输出数据里见过的动作附近的动作。

三条路线的取舍与超参见 算法速查表 · CQL。

实践顺序：先 BC，再离线 RL

问题先做什么
日志能覆盖到决策需要的状态吗？先画状态覆盖图；覆盖不到的状态上什么算法都救不回来
我只想复现既有水平BC。它便宜、稳、可解释，是所有离线方法的对照基线
数据混有次优行为，想学得更好这时才上 CQL / IQL / TD3+BC，并用 BC 当上界参照
日志上的评估很好看别信。上 shadow 模式、小流量 A/B、护栏指标

"离线 RL 不需要交互，所以更省钱"是一种常见的误读。它省的只有交互预算， 成本换成了别的：足够多样的行为数据（每个重要状态下得有多种动作被尝试过）、 保守系数的调参，还有一条比在线 RL 更谨慎的评估链路。

课后练习

1. 直接拿离线日志训练 Q-learning，为什么会失败？

  1. 策略会查询日志里没有的动作，那些位置的 Q 值不受约束
  2. 日志按时间顺序收集，样本相关性使梯度噪声偏大
  3. 日志奖励带噪声，Q-learning 会把噪声当成真实信号
  4. Q-learning 是 on-policy 方法，不能用别的策略产生的数据

为什么：失败的核心是查询了没有数据的位置。目标里的 maxa′ 会估计日志里从未执行过的动作，这份估计由外推决定， 可以任意大，策略随后就跑向虚高的区域。

B 的梯度噪声靠回放就能缓解。C 对在线与离线的影响一样。 D 与事实相反：Q-learning 是 off-policy，能复用旧数据。

2. 行为克隆的复合误差是怎么产生的？

  1. 训练集太小而模型容量过剩，在日志上严重过拟合
  2. 动作标签不均衡，模型只学会最常见的那个动作
  3. 小误差把策略推到覆盖很差的状态，误差随步数放大
  4. 学习率（每次更新时往新信息的方向挪多远）太大，参数在训练后期震荡而无法收敛

为什么：BC 的训练分布是专家访问过的状态分布。策略预测偏一点，环境就把它带到 覆盖很差的地方，那里的预测更不可靠，误差继续累积。它对状态覆盖的敏感度 远高于对模型容量的敏感度。

A 说的是过拟合，与误差累积无关。B 属于类别不均衡，只会让策略一开始就偏。 D 调小学习率即可。

3. DAgger 与行为克隆的关键区别是什么？

  1. 它直接学价值函数，用自举替代监督学习，不需要专家标注
  2. 它让专家在策略实际访问的状态上标注动作，修正分布不匹配
  3. 它在线交互并把新数据加入回放缓冲区，属于 on-policy 方法
  4. 它用多个策略并行采样做多数投票，降低数据方差

为什么：DAgger 针对的就是 BC 的痛点，训练分布与部署时分布不一致。 做法是用当前策略跑出新状态、请专家标注正确动作，再聚合回数据集重训。

A 把它说成了价值学习：DAgger 只拟合动作，没有自举。C 收集的是自己会访问的状态， 而且仍然做监督学习，不是 actor-critic。D 与多数投票无关。

4. 关于离线评估，下列哪一项是可靠的结论？

  1. 只要离线数据量足够大，日志估计就等价于上线表现
  2. 同一批日志做交叉验证得到的分数，可以直接决定上线
  3. 换成双 Q 之后，离线评估的偏差会被自动校正
  4. 分布偏移让日志上的估计偏乐观，上线必须用 A/B 与护栏兜底

为什么：日志由行为策略 πβ 产生，被评估的策略却会去看 πβ 没走过的区域，那里的估计没有数据支撑，通常偏乐观。 上线只能用 shadow、A/B 与护栏兜底。

A 与 B 都错在"数据多就能解决问题"：量不解决覆盖。C 混淆了目的： 双 Q 缓解的是训练中的过估计，给不了离线评估的无偏估计。

5. CQL 与 IQL 这类离线算法的核心设计原则是什么？

  1. 把动作空间离散化，用表格法避免函数逼近的外推误差
  2. 让价值或策略在数据支撑外保持保守，不追逐无数据支持的高估值
  3. 引入在线探索，用小流量随机动作补齐日志缺的动作
  4. 并行训练多个策略，挑日志上回报（从现在起一直到结束，把每一步奖励加起来的总分）估计最高的部署

为什么：离线 RL 的困难来自外推：没有数据的位置上 Q 可以任意大。 主流算法都在做同一件事：让价值在数据外偏低（CQL）、不去查询数据外的最值（IQL）， 或把策略约束在数据动作附近（BCQ / TD3+BC）。

A 只是把外推搬到表格的另一格。C 违反离线设定。 D 的分母仍是那份不可信的离线估计，选择会被同样的偏差污染。

代码题 1 · 训练线性行为克隆并预测动作

背景本课的设定是只有一份固定日志，不能与环境交互。 行为克隆是最先要跑的基线：把日志里的状态动作对当监督样本。训练函数在离线拟合阶段被调用， 学出一个线性 softmax 策略；预测函数在部署阶段被调用，拿当前状态选动作。 两者共用同一套中心化特征，训练与推理的输入必须对齐。

请实现 fit_behavior_cloning(states, actions, n_actions, steps=2000, lr=1.0) 与 behavior_clone_predict(states, W, b)。

输入

  • states：形状 (N, D) 的状态数组，D 是特征维数。测试里是一维，取值在 0 到 1 之间。
  • actions：长度 N 的整数动作标签，取值在 [0, n_actions)。
  • n_actions：动作个数，决定输出层宽度。
  • steps、lr：全批量梯度下降的步数与学习率，默认 2000 与 1.0。
  • W、b：训练好的权重与偏置，也是预测函数的输入。

输出

  • fit_behavior_cloning 返回 (W, b)：W 形状 (D, n_actions)，b 形状 (n_actions,)，是线性 logits 的权重与偏置。
  • behavior_clone_predict 返回形状 (N,) 的数组，dtype 为 int64，第 i 个元素是第 i 个状态上 argmax logit 的动作下标。

会被检验W 与 b 的形状； 预测必须是 int64；两组日志上的训练准确率都接近 1，两个动作的权重必须被拉开， 否则策略退化成常量；小状态判动作 0、大状态判动作 1；第二组数据在 0.5 附近没有样本， s = 0.5 处仍判为动作 0。只用标准库与 numpy。

卡住了？看提示
  • softmax 要减去每行最大值再取指数：z = z - z.max(axis=1, keepdims=True)。
  • one-hot：Y = np.zeros_like(P); Y[np.arange(N), actions] = 1.0。
  • 一步梯度下降：W -= lr * (s.T @ G)、b -= lr * G.sum(axis=0)， G = (P - Y) / N。

代码题 2 · 拟合线性 Q 并测量外推误差

背景分布偏移是离线 RL 失败的头号原因，它的效果集中体现在外推上： 日志没覆盖过的状态动作上，Q 函数给出的值没有数据支撑。这三个函数是验证该现象的仪器， 在离线评估阶段给候选算法打分。先在 s ∈ [0, 1] 的日志上拟合线性 Q， 再推到数据范围之外，看误差怎么放大。输入输出都对应日志记录 (s, a, r)。

请实现 fit_linear_q(states, actions, rewards)、 linear_q_value(w, states, actions) 与 extrapolation_error(w, states, actions)。

输入

  • states、actions、rewards：等长的一维数组（长度 N），即日志里的状态、动作与回报；长度为 1 的数组也要能用。
  • w：fit_linear_q 解出的权重，长度 3。

输出

  • fit_linear_q 返回形状 (3,) 的数组：按特征 φ(s, a) = [1, s, a] 的最小二乘权重，w[0] 是常数项、w[1] 对应状态、w[2] 对应动作。
  • linear_q_value 返回形状 (N,) 的数组：第 i 个元素是 φ(si, ai) · w。
  • extrapolation_error 返回 Python float：真实动作价值取 q(s, a) = s²，返回估计值与它的均方误差。

会被检验权重形状是 (3,)；数据严格线性时 w 必须是 [0, 2, 0] 且插值精确；日志范围内均方误差小于 0.1； s = 3、a = 2 处真实值是 9，线性外推的预测低于 5、均方误差远大于 10； 严格线性那组外推到 s = 3 时均方误差正好是 9。只用标准库与 numpy。

卡住了？看提示
  • 设计矩阵：np.column_stack([np.ones_like(s), s, a])，别写成行向量的拼接。
  • np.linalg.lstsq(A, r, rcond=None)[0] 返回的就是最小二乘解。
  • 先 np.asarray(..., dtype=float).reshape(-1)， 再 float(np.mean((pred - true) ** 2)) 返回 Python 浮点数。
