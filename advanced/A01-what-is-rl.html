强化学习到底是什么

这一节只回答一个问题：你手上的问题该不该用强化学习（RL）。 它会先让你看懂五个词，再告诉你它和"有标准答案的那种学习"差在哪里， 最后给你三道筛子；过不了筛子的，越早换别的办法越省事。

你会得到

  • 能用自己的话定义智能体、环境、状态、动作、奖励这五个词
  • 能说出它和"有标准答案的学习"（监督学习）差在哪三点，并各举一个业务例子
  • 拿到一个新问题，能用三个筛子判断它是否适合 RL

一个真实的决策问题

假设你在电商公司管库存。每天你要决定每种商品补多少货：补多了压资金、占仓库，补少了丢订单、收差评。 难处在于：你手上没有"标准答案"可以学。历史记录只写下了你当时补了多少、后来卖得怎么样， 却没写"如果当时补 80 件会怎样"。（SKU 是 stock keeping unit 的缩写，库存量单位，就是"一种商品"；下面直接用"商品"。）

推荐系统也一样。你给用户推了 A，就永远看不到"如果推 B，他会不会更喜欢"。 你能拿到的只是一个数：他点了吗、买了吗、待了多久。

这两类问题长得一样：你的决定会改变你以后能看到的数据，而你只能拿到一个分数，拿不到答案。 强化学习（reinforcement learning，RL）就是专门处理这种问题的。

五个词，一个循环

RL 把这类问题抽象成一个不断重复的循环：

  • 智能体（agent）：做决策的一方，比如你的补货算法。
  • 环境（environment）：智能体之外的一切，包括用户、市场、供应链。
  • 状态（state）：此刻环境给智能体的信息，比如当前库存、在途、最近七天销量。
  • 动作（action）：智能体的选择，比如补 0 件、补 50 件。
  • 奖励（reward）：环境给这个动作的即时评分，比如当天的毛利减仓储成本。

循环是：观察状态 s → 选动作 a → 环境换成一个新状态 s' 并给出奖励 r → 再观察、再决策。就这么一圈一圈转下去。

你要学的东西叫策略（policy）：一套"看到什么状态就选什么动作"的规则。 换个说法，策略就是你写在程序里的那份"出招习惯"。

这里有个坑：r 只是这一步拿到的分数，而真正要最大的是长期总分。 中间隔着一长串决策，所以"这一步分高"不等于"长期总分高"。第一个难点就在这里。

它和"有标准答案的学习"差在哪

你可能听过监督学习（supervised learning）：给你一大堆"题目 + 标准答案"， 让程序学会看到题目就写出答案，像做一本有答案的练习册。下面三点是它和 RL 的根本差别， 也是判断"该不该用 RL"的全部依据。

一、没有标准答案，只有一个分数

监督学习拿到的样本是"输入 → 正确答案"，错就是错，答案摆在那里。 RL 拿到的是"动作 → 这个动作得了多少分"。分数是比较性的，不是指示性的： 告诉你"这次补货扣了 3 分"，并不会告诉你"应该补 42 件"，你得自己从分数里摸索出该怎么做。

二、分数来得晚：到底该怪哪一步

你今天补了 200 件，三天后才发现货压在仓库里。这个"错"该算在哪一天的决策头上？ 把最终结果分摊到中间若干步决策，这件事叫信用分配，通俗说就是"分锅"：一个团队项目搞砸了，责任怎么摊到每个人头上。

这是 RL 比监督学习难的核心原因之一。

三、你看到的数据，是你自己的决策挑出来的

这一点最容易被忽略，代价也最大。监督学习的数据集是固定的一批，你可以反复看同一批样本。 但 RL 里，你能采到什么数据取决于你现在怎么决策。你手头这批数据偏向哪些情况，是被你自己的做法决定的（这批数据的"偏向"，下面叫数据分布）。

后果很直接：如果你一直只补"看起来最热"的那几件商品，你就永远不知道其他商品多补一点会怎样。 更糟的是，你可能因为早期一次坏运气，从此永久放弃一个本来更好的做法。

所以 RL 必须在"用现在觉得最好的"和"试试别的"之间做权衡，这叫探索与利用： 利用是"点你最爱吃的那道菜"，探索是"换个没吃过的菜试试"。

三个筛子：什么时候不该用 RL

RL 昂贵、不稳定、难调试。动手之前先过这三个筛子。任何一条不满足，就先回去用更简单的办法。

筛子满足的条件不满足时用什么
有标签吗 没有可用的"正确答案"，只有评价性反馈 直接用监督学习。有标签就别上 RL。
能试错吗 能在可接受的成本和风险下反复尝试，或者有一个可信的仿真环境（一个能让你随便试错的模拟器） 先用仿真器或历史数据评估；实在不能试错，就考虑离线（只用已经攒下来的历史记录学，不再与真实环境交互）的办法，或者干脆不做
奖励可定义吗 能写出一个可计算、且与真实目标一致的标量奖励 先解决度量问题。奖励写错，RL 只会高效地学坏。

应用向的经验：实际项目翻车，多数出在奖励设计和不能安全试错上，不在算法选型。 第 0006 课会专门花一整课讲建模，第 0027 课讲怎么为你的问题选算法。

接下来会发生什么

接下来你会先学一个最简版本：多臂老虎机（一排老虎机摆在你面前，你不知道哪台吐钱多，只能一台台试），它连"局面会变"都没有，只看"选哪个"。探索与利用的权衡，在它身上被剥得只剩骨架。

然后把"局面会变"加回来，进入马尔可夫决策过程（简单说，就是"下一步会怎样只取决于现在，跟更早的历史无关"的那类标准问题设定）。

课后练习

1. 与监督学习相比，强化学习最本质的特点是什么？

  1. 训练数据规模通常更大，因此需要显著更强的算力支撑
  2. 没有给定标签，反馈来自奖励且取决于自己选择的动作
  3. 只能处理序列决策问题，监督学习只能处理单步预测
  4. 必须与环境交互，而监督学习完全不需要任何训练数据

为什么：核心在于"没有标准答案，只有对所选动作的评价"。奖励是相对的评分， 不是正确的输出，而且你必须先做动作才能拿到它。

A 错在把"数据量/算力"当成本质区别；那是工程代价，不是问题结构。 C 错在把边界画得太死：监督学习也能做序列建模（如机器翻译）。 D 错得很明显：监督学习当然需要数据，只是那些数据带标签。

2. 在 RL 语境里，"延迟反馈"具体指的是什么？

  1. 奖励要在若干步之后才出现，把结果归因到哪一步很困难
  2. 奖励的计算需要额外的资源开销，因此拖慢了整体训练速度
  3. 环境返回的观测带有噪声，需要额外的滤波模块来做处理
  4. 策略更新依赖离线数据，因此无法与环境直接交互来训练

为什么：延迟反馈直接导致信用分配问题：最终的好结果或坏结果， 要摊到中间哪几个决策上？后面 0004 课要讲的两件工具就是为了解决这件事。一件是价值函数（站在某个局面估计最终能拿多少分），另一件是贝尔曼方程（把"这一步的分数"和"下一步的分数"连起来的等式）。

B 把它误解成性能问题，C 说的是观测噪声（是另一个独立问题）， D 描述的是离线 RL 的一种设定，与延迟反馈无关。

3. 关于"数据分布由策略决定"，下列哪一项描述是准确的？

  1. 数据分布由环境本身固定下来，与智能体选择什么动作无关
  2. 数据分布只在离线 RL 中才会变化，在线训练过程中始终稳定
  3. 数据分布由当前策略决定，会随训练推进不断发生漂移变化
  4. 数据分布由奖励函数决定，策略只影响动作而不影响其分布

为什么：你采到的样本是你自己行为的结果。策略一改，访问到的状态和动作分布就变， 这让"反复看同一批数据"这种监督学习式的做法在 RL 里不成立。

A 和 D 都把分布归给了环境或奖励函数，忽略了策略的作用； B 说反了：在线训练本身就是分布持续漂移的场景。

4. 下列哪种情形，最不应该优先考虑强化学习？

  1. 需要做长期决策，且短期收益与长期目标之间存在冲突
  2. 可以低成本地反复试错，并且能量化最终带来的业务收益
  3. 动作会改变系统状态，同时没有现成的监督标签可供使用
  4. 已有大量带标签的历史数据，目标是预测一个已知的量

为什么：有标签、有明确预测目标，这就是监督学习的标准场景。 用 RL 去解它属于自找麻烦：你会丢掉标签信息，还要额外承担探索的成本和风险。

A、B、C 描述的恰好是 RL 的三个适用信号：长期决策、可安全试错、无标签但有反馈。

5. 探索与利用之所以存在冲突，根本原因是什么？

  1. 环境的可能状态太多（术语叫状态空间太大），没法一个一个列出来
  2. 当前的最优估计可能是错的，而验证它需要付出真实代价
  3. 奖励函数往往难以设计，导致智能体最终学到错误行为
  4. 直接学策略这类办法波动太大（方差高），往往还要额外加一个基线（一个用来压住波动的参照值）

为什么：你手上的是"估计"，不是真值。只按估计挑眼前最好的那个（这叫贪心）可能锁死在不够好的选择上； 要纠正它就得去试那些当前看起来更差的动作，而尝试本身有成本。

A 说的是状态空间太大带来的困难，C 是奖励设计问题，D 是策略梯度（直接调整策略参数的那类方法）的细节。 三者都真实存在，但都不是探索-利用冲突的根源。

代码题 1 · 计算折扣回报

背景从这里开始，你写的代码要真的算东西了。折扣回报（discounted return）就是 RL 要最大化的那个总分： 从当前时刻起把每一步的奖励加起来，但越靠后的奖励，算进总分时权重越小，等于给它打了个折；这个折的力度由折扣因子（就是 γ，取值 0 到 1，越小打折越狠）决定。 为什么要打折？因为越远的未来越不确定；而且不打折的话总分可能是无穷大，就没法比较了。 这个函数把一串已经记下来的奖励折算成一个数，后面算"这套策略值多少分"时会反复用到它。

请实现 discounted_return(rewards, gamma)。

Gt = rt + γ rt+1 + γ² rt+2 + … = Σk=0∞ γk rt+k (1.1)

公式里的 Σ 是求和号，意思是"把后面那串东西全加起来"；除了 Σ 之外， 右边那个看起来无穷长的加法实际上只有有限项（奖励序列有多长就有多少项）。

输入

  • rewards：一串奖励，Python 列表或一维 numpy 数组都行（numpy 数组就是一排数字的容器），长度允许为 0；
  • gamma：float，折扣因子，取值在 0 到 1 之间；第 k 步的奖励要乘上 γk （也就是 γ 连乘 k 次：第 0 步乘 1，第 1 步乘 γ，第 2 步乘 γ×γ……）。

输出

  • 返回一个 Python float，即从第 0 步起算的折扣回报 G0。

会被检验gamma=1 时等于各步奖励之和；gamma 小于 1 时越靠后的奖励被衰减得越重；只有一步时回报等于那一步的奖励；rewards 为空时必须返回 0.0，测试用 == 比较。只用标准库与 numpy，本题不需要随机数。

卡住了？看提示
  • 准备两个变量：total = 0.0 存总分，g = 1.0 存"这一步该乘的权重" （第 0 步的权重是 γ0 = 1）。
  • 依次遍历 rewards 里的每个 r，做两件事：先把 g * r 累加进 total， 再让 g = g * gamma（为下一步把折扣再乘一次）。
  • 循环结束后 return total。不要每一步都写 gamma ** k，累乘更简单也更快。
  • rewards 可能是列表也可能是 numpy 数组，for r in rewards 两种都能遍历； 它为空时循环一次都不执行，正好返回 0.0。

代码题 2 · 实现 ε-greedy 动作选择（ε 是探索率）

背景这个函数负责决定"下一步做什么"。手上的价值估计都带误差， 如果一直挑当前看起来最好的动作，就可能一直锁死在某个不够好的选择上； 所以要留出一部分概率去试试别的。它在智能体与环境交互的每一步都会被调用： 给它当前的价值估计和探索率（英文 epsilon，写作 ε，意思是有多大比例的概率去随便试一个动作），它告诉你这一步实际执行哪个动作。它只负责选动作，不负责更新任何估计。

请实现 epsilon_greedy(Q, epsilon, rng)。

a = ⎧
⎩随机动作，  以概率 ε
arg maxa Q(a)，  否则 (1.2)

式子里的 argmax 读作"arg-max"，意思是"挑出让后面那个式子最大的那个选择"： arg maxa Q(a) 就是"挑出 Q 值最大的那个动作下标"。 注意下标从 0 开始，所以 n 个动作的下标是 0 到 n−1。

输入

  • Q：长度 n 的一维 numpy 数组（一排数字的容器），第 i 个数表示"第 i 个动作现在估计值多少分"；
  • epsilon：0 到 1 之间的 float 探索率。按"平均一百次里大约多少次"来理解： 0.1 就是大约每十次里有一次随便试一个动作；
  • rng：测试传进来的随机数生成器 numpy.random.Generator。 随机数只能从它取：同一个种子（seed）必然给出同一串数，测试才能复现； 用全局的 np.random 就复现不了。

输出

  • 返回被选中动作的整数下标，取值 0 到 n-1；类型应当是 int 或 np.integer，不能是浮点数或数组。

会被检验epsilon=0.0 时连续 50 次都必须选 Q 最大的动作，epsilon=1.0 时 4000 次的选择次数近似均匀，每个动作在 700 到 1300 次之间；下标 1 是 Q 的最大值所在位置；平局时返回下标最小的动作。随机数只能取自传入的 rng，不要用全局 np.random，否则测试无法复现；只用标准库与 numpy。

卡住了？看提示
  • 第一步：抽一个 0 到 1 之间的随机小数，r = rng.random()。 它小于 epsilon 的可能性正好是 epsilon，这就是"以概率 ε 探索"的实现办法。
  • 第二步：如果 r < epsilon（抽中了探索），就用 rng.integers(0, len(Q)) 在 0 到 n−1 之间随机取一个动作下标。 注意 integers 的右端是取不到的，所以要写 len(Q) 而不是 len(Q)-1。
  • 第三步：否则（利用）用 np.argmax(Q) 取 Q 最大值的下标。 平局时它天然返回最小的那个下标，正好符合要求。
  • 最后把它转成 Python 的整数再返回：return int(...)。 numpy 有自己的整数类型，测试要求返回的是普通整数，不要返回数组。
