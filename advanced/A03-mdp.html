马尔可夫决策过程

上一节讲的是每次选择互不影响的情况，现实中这个假设很少成立。 这一节把"选择会改变下一步局面"的问题写成一套标准格式，并给你一把尺子， 用来检查自己定义的状态够不够用。状态定错，后面所有算法都会稳定地学出错误行为。

你会得到

  • 能写出 MDP 五元组，并解释 p(s′,r|s,a) 里每个符号在代码里对应什么
  • 能用"给定状态后未来与历史无关"检验自己的状态设计
  • 能算出一串奖励的折扣回报，并说清 γ（折扣因子）取 0.9 与 0.99 的实际差别

从老虎机到"有后果的选择"

第 0002 课里的老虎机假设每次选择互不影响。现实里这个假设几乎从不成立： 你今天给用户推了低价商品，他明天对价格的预期就变了；你这条产线降了库存，下个月的缺货率跟着上升。 选择会改变你下一步面对的局面，所以需要一个带状态的模型。

马尔可夫决策过程（Markov decision process, MDP）：规则明确、只看当前局面就能决定下一步的那类问题设定。 它把一步交互写成五元组 (S, A, P, R, γ)。

五元组逐项看：S 是状态集合，也叫状态空间（所有可能局面的集合）； A 是动作集合，也叫动作空间（你这一步能做的选择有多少种）； P 是状态转移（你做完动作之后，环境从当前状态跳到下一个状态）的规律； R 是奖励（每个动作得几分）；γ 是折扣因子（越往后的奖励，算进总分时权重越小，相当于给它打了个折）。 前四个描述"世界怎么运转"，最后一个描述"你多看重未来"。

一步交互的定义

在时刻 t，智能体（做决策的那一方，就是你写的程序）看到状态 St， 选一个动作 At。环境随后给出奖励 Rt+1，并把局面转移到 St+1。 环境的全部规律就是下面这一个条件概率：

p(s′, r | s, a) = ℙ[ St+1 = s′, Rt+1 = r | St = s, At = a ] (3.1)

式子读作"在状态 s、做了动作 a 之后，落到状态 s′ 并且拿到奖励 r 的概率是多少"。 概率就是"平均一百次里大约发生几次"：0.3 就是大约一百次里三十次。 注意它是联合分布：下一状态和奖励是一起给出的。写成代码，就是一张查表 p[(s, a)] → [(概率, s′, r), …]，每一行的概率加起来等于 1。

一个常见错误是只写 P[s′|s,a]，再单独配一个平均奖励。那样你就丢掉了"奖励和状态一起变化"的相关性， 后面算期望时会出错。

写代码时还有一个偷懒但正确的等价形式：把奖励并进转移， 用 r(s,a) = Σs′,r r · p(s′,r|s,a) 表示期望即时奖励。 这里的 Σ 是求和号，意思是把后面那串东西全加起来。表格法常用 R[s][a] 这种写法。

马尔可夫性：状态必须"够用"

MDP 成立的前提是马尔可夫性（Markov property，下一个状态只取决于当前状态和动作，与更早的历史无关）。 用一句大白话说：只看现在的局面就能决定下一步，不必把之前的每一步都回放一遍。 状态是决策所需的全部信息，历史里没有更多有用的东西。

这一条最容易被轻视，代价也最大。库存问题里，只把"当前库存量"当状态就不满足它： 在途订单、最近七天的销量、季节性都会改变未来的缺货分布。你的算法不会报错， 它只会稳定地学出一个不够好的策略（一套"看到什么状态就选什么动作"的规则），而且你很难从曲线上看出原因。

应用向的检验办法：把数据按"你的状态表示"分组， 看同一个状态下的下一步结果分布是否一致。若某个状态里还藏着一组明显不同的未来分布， 你就漏了信息。第 0006 课会把这件事做成一份建模检查表。

反过来说，完整观测并不等于马尔可夫状态。视频游戏里单帧画面看不到速度， 所以工程上会堆叠最近几帧；这不优雅，但它把"速度"这个隐含变量重新塞回了状态。

回报与折扣因子

要最大化的东西叫回报（从现在起一直到结束，把每一步奖励加起来的总分）：

Gt = Rt+1 + γRt+2 + γ²Rt+3 + … = Σk=0∞ γk Rt+k+1 (3.2)

公式里的 Σ 是求和号，意思是把后面那串东西全加起来；γk 是 γ 连乘 k 次。 因为越靠后的奖励都要打折，这个量也常被叫成折扣回报（从此刻起，把后面每一步奖励打折后加起来的总分）。

γ ∈ [0, 1] 是折扣因子（越往后的奖励，算进总分时权重越小，相当于给它打了个折）。 它的数量级值得记一下：γ = 0.9 时，10 步之后的奖励权重只剩 0.910 ≈ 0.35； 换成 0.99，同样 10 步的权重是 0.9910 ≈ 0.90。 所以 γ 直接决定你的智能体看多远：0.9 大致关心未来十步，0.99 关心未来上百步。

当 γ < 1 且每一步的奖励有上限时，无限项的回报仍然是有限的：每步都拿 1 的话， 总和不超过 1/(1−γ)；γ = 0.9 时这个上界是 10。 这种"再算下去也基本不变"的状态就叫收敛（一轮轮算下去，数值不再明显变化，稳定下来了）。 这也是"延迟满足"的数值体现：γ 越小，策略越短视、越急于兑现眼前收益。

episodic、continuing 与策略

任务按是否自然结束分两类。分幕任务（episodic task，从开始到结束是一整局，结束后重置） 有终止状态，比如一盘棋、一次会话；持续任务（continuing task，永不终止、一直进行下去） 没有终止状态，比如长期运行的推荐系统或库存控制。两类任务都可以用 γ < 1， 但持续任务必须用 γ < 1（否则回报可能发散），而分幕任务允许 γ = 1。

智能体行为规则叫策略（policy，一套"看到什么状态就选什么动作"的规则），记作 π(a|s)：在状态 s 下选动作 a 的概率。 当每个状态下只有一个动作概率为 1 时，就退化成确定性的写法 π(s)。 策略是智能体自己的东西；环境只负责 p(s′,r|s,a)，两者不要混。

到这里，问题已经被完整描述：找一套策略 π，让期望回报 𝔼[Gt] 最大。 这里的 𝔼（期望，同一件事重复很多次之后的平均结果）说的是：同一套策略跑很多次，把每次的总分平均一下。 但"某一套策略到底值多少"还没有定义。第 0004 课会用 贝尔曼方程（把"这一步的价值"和"下一步的价值"连起来的等式）回答这个问题； 那里的价值函数（从某个状态出发，按某套策略走下去，平均能拿多少总分）就是为它准备的。 再往后，策略改进（根据算出的分数，把策略里明显吃亏的选择换掉）和策略梯度 （不绕道估价值，直接调整策略参数的那类方法）都要先用上"从某一步开始的累积回报"。

课后练习

1. 关于马尔可夫性，下列哪一项描述是准确的？

  1. 状态必须能够唯一地还原出此前完整的观测与动作历史
  2. 给定当前状态之后，未来与更早的历史之间互相条件独立
  3. 状态必须是有限个离散取值，连续取值的状态不满足该性质
  4. 状态转移只由环境自身决定，与智能体选了什么动作无关

为什么：马尔可夫性只要求当前状态是决策所需的充分统计量， 历史在给定状态后不再提供增量信息，因此未来与历史条件独立（S&B 第 3.1 节）。

A 是过强要求：状态只需充分，不必能还原历史。 C 把表格法的限制当成了 MDP 的前提；连续状态空间同样是合法的 MDP。 D 恰好抹掉了动作的作用，而 p(s′,r|s,a) 明确依赖 a。

2. 取折扣因子 γ = 0.9，那么"10 步之后才会拿到的奖励"权重是多少？

  1. 约 0.09，因为每往后一步都要从总权重中扣除 0.09
  2. 约 0.31，因为 10 步的累计折扣等于 0.9 的 10 次方的一半
  3. 约 0.90，因为折扣只在超过 10 步之后才真正开始生效
  4. 约 0.35，因为第 10 步的权重就是 0.9 连乘 10 次的结果

为什么：权重是 γ10 = 0.910 ≈ 0.349。10 步以后的奖励只剩三分之一的份量， 这就是"γ = 0.9 看未来十步左右"这个说法的依据。

A 把指数衰减当成了线性扣减（0.9 不是每步减 0.09）。 B 的"折半"没有依据。C 描述的是一种根本不存在的免折扣窗口期。

3. 分幕任务（episodic）与持续任务（continuing）的关键区别是什么？

  1. 分幕任务不能使用折扣因子，持续任务则必须使用折扣因子
  2. 分幕任务的动作空间是离散的，持续任务的动作空间都是连续的
  3. 分幕任务会自然终止并重置，持续任务没有终止状态可以到达
  4. 分幕任务的回报一定是有限值，持续任务的回报必定发散到无穷

为什么：区分标准只有一条：交互序列是否会自然结束并重新开始。 分幕任务存在终止状态，持续任务则一直在同一个过程里延续下去（S&B 第 3.3 节）。

A 错：分幕任务同样可以（也常常）用 γ < 1，只是允许 γ = 1。 B 与动作空间无关。D 错：持续任务在 γ < 1 且奖励有界时回报有限，上界就是 1/(1−γ)。

4. 关于策略 π，下列哪种说法是正确的？

  1. π(a|s) 给出各状态下动作的概率，π(s) 是它的确定性特例
  2. π 属于环境的一部分，与智能体学到的价值函数没有直接关系
  3. 只有当状态空间是有限的时候，策略才能写成条件概率形式
  4. π(a|s) 描述状态如何转移，而奖励由另外的策略函数单独给出

为什么：策略是智能体的决策规则，π(a|s) 是它的随机形式； 当某个动作概率为 1、其余为 0 时，就写成确定性形式 π(s)。

B 把策略归给了环境；环境负责的是 p(s′,r|s,a)。 C 不成立：无限或连续状态空间照样可以定义策略。 D 把策略和转移模型搞混了。

5. 五元组里的 p(s′,r|s,a) 描述的是什么？

  1. 它直接给出每个状态下的最优动作，属于策略的一部分内容
  2. 它只描述奖励取值的分布，不包含下一个状态会是谁的信息
  3. 它同时给出下一状态与奖励的联合概率，定义了环境的动态规律
  4. 它只在分幕任务中是必需的，持续任务里完全用不到这个量

为什么：它是"下一状态和奖励一起出现"的联合分布， 按它取期望就得到贝尔曼方程里的那两项。所有基于模型的算法都以它（或其等价表格）为输入。

A 错：最优动作要靠价值函数推出来，环境不会告诉你。 B 漏掉了 s′：两者是联合的，奖励和状态才能相关，算期望时不能拆开。 D 错：两类任务都需要它，区别只在是否有终止状态。

代码题 1 · 从轨迹奖励算出每一步的折扣回报

背景跑完一条轨迹后，拿到的只有每步的即时奖励。轨迹就是从开始到结束、一路上状态动作奖励的记录；而后面给策略打分的算法要的是"从某一步开始的累积回报"。这个函数把奖励序列变成整条轨迹上每一步的折扣回报，在采集完一条轨迹之后调用，是后面蒙特卡洛（把一整局走完，用真实拿到的总分来估计价值）这类算法的输入准备步骤。输入是记录下来的奖励，输出是从同一时刻起算的长期收益。

请实现 returns_from_rewards(rewards, gamma)。

G[t] = Σk≥0 γk · rewards[t+k] (3.3)

输入

  • rewards：长度为 T 的奖励序列，Python 列表或一维 numpy 数组都可以。numpy 数组是"一排数字的容器"，形状记作 (T,)，下标从 0 开始，T 允许为 0；
  • gamma：float，折扣因子（越往后的奖励，算进总分时权重越小，相当于给它打了个折）；未来第 k 步的奖励要乘 γk，也就是 γ 连乘 k 次。

输出

  • 返回用浮点数存放、长度为 T 的 numpy 数组 G，形状 (T,)；G[t] 是从第 t 步起、把 rewards[t] 当作第一步的折扣回报。

会被检验测试逐项核对 G 与定义一致，并检查相邻两项满足 G[t] = rewards[t] + gamma * G[t+1]；最后一步的回报等于那一步的奖励；只有一步时返回长度 1 的数组；rewards 为空时返回形状 (0,) 的数组。只用标准库与 numpy，本题不需要随机数。

卡住了？看提示
  • 返回的必须是 numpy 数组：先写 G = np.zeros(len(rewards))。np.zeros(n) 返回长度 n、全是 0 的数组，下标从 0 开始，最后一步的下标是 T-1。
  • 用一个变量 running = 0.0 记住"后面所有奖励的折扣和"。它一开始是 0，因为最后一步之后没有奖励。
  • 让 t 从 T-1 倒着走到 0，写成 range(len(rewards) - 1, -1, -1)。 每轮先做 running = rewards[t] + gamma * running，再把 running 存进 G[t]。
  • 不要对每个 t 都重新往后累加一遍，那样要算 O(T²) 次，边界上还容易出错。

代码题 2 · 用数据检验状态表示是否满足马尔可夫性

背景状态表示漏掉关键历史时，同一个状态下的下一步会依赖被丢掉的信息，马尔可夫性就不成立，后面所有基于价值函数的算法都会跟着失准。这个函数用一批转移记录给状态表示做体检：同一状态、不同历史下的结果分布差得越远，说明这个状态表示漏掉的东西越多。输入是交互日志，输出是一个可以跨状态设计比较的偏差分数。

请实现 max_markov_gap(records)。

TV(p, q) = ½ Σo | p(o) − q(o) | (3.4)

输入

  • records：转移记录列表，每条是三元组 (state, history, outcome)；state 是状态表示看到的值，history 是这个表示丢掉的历史信息，outcome 是这一步之后观察到的结果（整数）。

输出

  • 返回 Python float：所有状态里、所有历史组合两两比较中最大的总变差距离。总变差距离（total variation distance）是这样算的：把两套"平均一百次里各出现几次"的比例逐项相减、取绝对值、加起来再除以 2，取值在 0 到 1 之间。

会被检验records 为空时返回 0.0；某个状态只有一种 history 时没有可比对象，同样返回 0.0；两个历史的经验分布完全不相交时返回 1.0，相差 1/3 时返回约 0.3333；某个 outcome 只在一侧出现时，另一侧的概率按 0 处理。这个函数只做统计，不要修改传入的 records；只用标准库与 numpy，本题不需要随机数。

卡住了？看提示
  • 先统计次数：用一个字典记下每个结果出现了几次，写成 counts[state][history][outcome] += 1。 字典的键可以再套字典，用 setdefault 可以先把空的子字典建好。
  • 再把次数换成概率：某个 history 下的概率 = 这个 outcome 的次数 ÷ 这个 history 的样本总数。这就是"平均一百次里大约几次"的那个比例。
  • 然后对同一个 state 下的每一对 history 算 TV：把两套概率的键并成一个集合，对每个键取 abs(p - q)； 某个 outcome 只在一侧出现时，另一侧的概率按 0 处理。最后把总和乘以 0.5。
  • 所有 state、所有 history 对里取最大的那个返回；records 为空、或者某个 state 只有一种 history 时，直接返回 0.0。
  • 这个函数只做统计，不要修改传入的 records；返回的是 Python 的 float。
