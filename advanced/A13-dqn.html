DQN：经验回放与目标网络

到上一课为止，估计一个局面值多少分的那套公式，输入还是靠人手设计的。 状态一旦是一张画面或者一段很长的序列，手工设计就顶不住了。 这一节讲 DQN（深度 Q 网络）怎么把这一步也交给神经网络，以及它为此必须加上的两件装备。

你会得到

  • 能写出 DQN 的损失与目标，并说出"只对所选动作算误差"为什么重要
  • 能解释经验回放解决的三个问题，以及它为什么要求 off-policy
  • 能在训练震荡或发散时，按症状表定位最可能的原因

为什么还要一个神经网络

0012 课的函数逼近 （状态太多记不下整张表，干脆用一个带参数的函数去"猜"价值）可以是线性的、粗编码的， 上限却取决于你手写的特征（把原始状态加工成一组数字，供函数使用）。 状态是一张画面、一个棋盘、一段用户行为序列时，状态空间（所有可能状态的集合） 大得根本列不完，手写特征本身就顶不住了： 很难把"画面里有个球正往右上飞"写成几百维向量。

DQN（Deep Q-Network，深度 Q 网络）的做法很直接： 把提特征这一步也交给神经网络。网络输入状态，输出每个离散动作的 Q 值向量， 取 argmax（挑出让后面那个式子最大的选择）就是策略 （一套"看到什么状态就选什么动作"的规则）。参数 θ（网络参数） 从此代替了 0012 课里的 w。

但把线性回归直接换成 MLP（multilayer perceptron，多层感知机， 也就是好几层神经元堆起来的网络）还不够，这样做几乎一定会发散。 DQN 的贡献是让它稳下来的两件工程装备，下一节和后面一节各讲一件。

损失函数：只算你选的那个动作

L(θ) = 𝔼(s,a,r,s′)∼D[ ( y − Q(s,a;θ) )² ],   y = r + γ maxa′ Q(s′,a′;θ−) (13.1)

式 (13.1) 里的 𝔼 读作"E"，是期望 （同一件事重复很多次之后的平均结果）的记号；它右下角那串 (s,a,r,s′)∼D 表示"从缓冲区 D 里随便取一条转移再求平均"。 式中 γ 是折扣因子（越往后的奖励，算进总分时权重越小，相当于给它打了个折）， r 是即时奖励，θ 是网络参数。 目标 y 里只有即时奖励 r 和下一步的估计，而那一长串的总分， 也就是回报（从现在起一直到结束，把每一步奖励加起来的总分），是它们一层层拼出来的。 这里说的 TD 误差，就是时序差分（不用等到一局结束， 用"走一步之后的新估计"来更新"走这一步之前的估计"）误差。

式子里那个缓冲区 D 下一节解释。 这里有三个最容易写错的地方。

  • 只对所选动作算误差。网络对每个状态输出一整个向量， 而损失只取 batch（一批样本，训练时一次处理一小批，而不是一条一条来） 里实际采取的那个 a：实现上就是 gather（按动作下标把对应的元素取出来）出 Q(s,a;θ) 再算均方误差。对所有动作都算误差， 等于逼那些没被选中的动作去逼近一个并不属于它们的数。
  • 终止转移的目标就是 r。终止状态没有未来，自举 （用自己当前的估计去更新自己当前的估计，等于自己拽自己的鞋带往上提）必须停掉。 少了这个判断，回合末尾会把下一回合的价值灌回来，这是最常见的实现 bug。
  • 目标里的参数是 θ−，不是 θ。它来自下一节要讲的另一份参数， 那份参数更新得慢，下一节解释为什么必须分开。

经验回放：把相关的样本打散

按时间顺序喂样本时，相邻的 (s,a,r,s′) 高度相关， 连续两帧画面几乎一样。用这种批做随机梯度下降，梯度噪声严重偏离"样本之间互不相关"这个假设， 网络会围着最近这段数据反复调整，学完就忘。 更浪费的是：采一条样本、更新一次、就把它丢掉， 样本效率（拿到同样多的经验能学多好，效率高就是更省数据）低得离谱。

经验回放（把走过的每一步都存进一个池子，训练时从池子里随机抽一批出来用） 把最近的 N 条转移存进一个环形缓冲区（写满之后新的一条会盖掉最旧的一条； DQN 原文取 N = 106，也就是一百万条）， 每次更新从里面均匀随机抽一个 mini-batch（一小批样本）。 好处有两个：样本之间近似互不相关，梯度噪声更符合那条假设； 每条样本被复用很多次，样本效率大幅提高。

这里补一句概率的话。"均匀随机抽"的意思是每条被抽中的可能性一样大， 这个可能性叫概率（一件事发生的可能性，用"平均一百次里大约发生几次"来理解）， 每条都是 1/N。这些随机数由计算机按一个起始编号生成， 同一个编号必然给出同一串数，这个编号叫随机种子 （一个起始编号，同一粒种子必然给出同一串随机数，所以测试才能复现）。

代价是：只有 off-policy（边学的那套策略不是产生数据的那套，数据来自另一套旧策略） 的算法能用它，因为缓冲区里的数据来自旧策略。 这就是 0010 课那个"off-policy 到底意味着什么" 第一次变现的地方：Q-learning 的更新式不含 a′， 拿旧数据训练毫无问题。缓冲区也不能太小，否则样本又会变回相关的。

目标网络：别追一个同时在跑的靶子

式 (13.1) 有个尴尬之处：同一个 Q 网络既在被更新的左边，又当右边的目标。 每次更新都在动目标，等于追自己的尾巴，这在数学上不是一个稳定的回归问题。

目标网络（另存一份"稍旧"的网络专门用来算目标，隔一阵才同步一次，避免追着自己跑） θ− 是 θ 的一份周期性拷贝， 原文每 10,000 步硬拷贝一次。实践中也常用软更新 （每次只把旧参数往新参数的方向挪一点点，不整体替换）， 这种做法也叫 Polyak 软更新，让它一点点跟上。 损失里的 max 用这份冻结的参数算，于是一段区间内目标不动， 回归重新变成一个稳定问题。

经验回放加目标网络，就是致命三元组 在深度价值方法里的标准解法：前者削弱"分布漂移 + 样本相关"，后者掐断自举的自我循环。

ε（探索率）衰减与预处理

  • ε 是探索率（有多大比例的概率去随便试一个动作）， 它从 1.0 线性衰减到 0.1，在前 106 帧内完成，之后固定 0.1。早期需要大量随机动作把缓冲区在不同区域铺开； 后期大部分时候都挑当前估计里最好的那个动作（这叫贪心： 在当前估计里挑看起来最好的那个），所以要把 ε 降下来。
  • 把连续 4 帧堆叠成一个状态（frame stacking，把连着几张画面摞起来当一个状态用）。 单帧看不出速度与方向，这违反了"状态必须包含决策所需的全部信息"（0003 课）。 单帧也不满足马尔可夫性（下一个状态只看当前状态和动作、与更早的历史无关）。
  • 奖励裁剪到 [−1, 1]， 让不同的游戏能共用一套学习率（每次更新时往新信息的方向挪多远）。
  • 输入归一化到 [0, 1]。输入尺度不统一是训练发散的常见原因。
  • 上面这些数字都是超参（需要你自己设定、而不是训练学出来的参数）， 照原论文的取值起步最稳。

训练不稳时先查什么

先分清两件事：训练不稳，和收敛（一轮轮算下去，数值不再明显变化，稳定下来了） 是两回事。按下面这张表先定位症状，再动手改。

症状最可能的原因
Q 值随训练时间持续膨胀目标网络没生效、γ 太接近 1、奖励没裁剪
loss 剧烈震荡或变成 NaN（not a number，非数）学习率太大、输入没归一化、没有梯度裁剪
训到一半突然整体崩溃回放缓冲区太小、目标网络同步太频繁
策略始终接近随机ε 没衰减，或缓冲区里几乎全是随机动作

还有一个没解决的问题：DQN 继承了 Q-learning 的最大化偏差 （总是取最大值，估计出来的分数会整体偏高，学习因此带上系统性错误）， 在某些 Atari 游戏上会把 Q 值抬到好几倍。0014 课的 Double DQN 就是修这个的，Dueling 结构改的则是网络输出的分解方式。

课后练习

1. DQN 的损失函数对哪些 Q 值计算 TD（temporal difference，时序差分）误差？

  1. 只对 batch 里实际采取的那个动作对应的那一个 Q 值
  2. 对网络输出的全部动作 Q 值求平均之后得到的那个值
  3. 只对当前状态下 Q 值最大的那个动作所对应的那一个值
  4. 只对目标网络输出的全部动作 Q 值中的最大值计算误差

为什么：网络对每个状态输出一个向量，但只有一个动作真的被执行了。 损失只取 Q(s,a;θ)，其中 a 来自缓冲区里的样本。 这也是为什么实现里总要先 gather 再算均方误差。

B 是常见的错误写法：它会把没被选中的动作也拉向同一个目标。 C 混淆了"选动作"与"算损失"：max 只出现在目标 y 里， 和"对哪个 Q 求误差"是两件事。D 描述的是 y 的算法，不是损失的对象。

2. 经验回放缓冲区主要解决的是哪一组问题？

  1. 它把目标网络的参数周期性冻结，从而消除追逐移动目标
  2. 它把连续的状态空间离散成有限的格子，让表格法可用
  3. 它保证缓冲区里的数据一定来自当前正在学习的那个策略
  4. 它把时间上高度相关的样本打散，并让每条样本被反复复用

为什么：回放同时修两件事：随机采样让批内样本近似独立， 更符合随机梯度下降的 i.i.d. 假设；反复复用让宝贵的交互数据被榨干。 前者治训练不稳，后者治样本效率。

A 说的是目标网络，是另一件装备。B 与事实相反：回放不做离散化。 C 恰好说反了：缓冲区里存的就是旧策略产生的数据，它要求 off-policy 的原因就在这里。

3. 目标网络 θ− 在 DQN 里的作用是什么？

  1. 让损失函数可以同时对所有动作求误差，从而加快收敛速度
  2. 提供一份更新缓慢的目标参数，让自举的回归目标短期内稳定
  3. 保存训练过程中最优的那份参数，作为最终交付的模型权重
  4. 代替经验回放缓冲区，直接用最近采到的样本做在线更新

为什么：如果目标里也用正在更新的 θ， 每次梯度步都在移动回归目标，这不是一个良定义的回归问题。 目标网络把 y 里的参数固定一段时间，把问题变回稳定的监督式回归。

A 与损失的对象无关，而且它不加快收敛。C 混淆了目标网络与"最优权重快照"， 目标网络是一直在缓慢更新的，不是挑最优存档。D 与回放缓冲区是两件独立的装备。

4. 在 DQN 的目标 y 里，终止转移应当如何处理？

  1. 目标仍要加上下一状态的最大 Q 值，只是把折扣因子取成 0
  2. 目标取 r 加上下一回合首个状态的最大 Q 值再乘以折扣因子
  3. 目标取 r 本身，不再加 γ 乘以下一状态的最大 Q 值
  4. 目标取 r 减去 γ 乘以下一状态的最大 Q 值作为终止惩罚

为什么：终止状态之后没有未来，自举项必须消失， 此时 Bellman 最优方程退化成 y = r。 实现上就是一个 (1 - done) 因子或 if done 分支。

A 在数学上等价于取 γ=0，但显式写出来更容易掩盖"忘了处理终止"这个 bug， 而且它把终止与"折扣为 0"两件事混为一谈。B 会把下一回合的回报灌进本回合的末尾， 是最典型的错误。D 的惩罚项没有任何理论依据。

5. 关于 ε 衰减与状态预处理，下列哪一项符合 DQN 的实践？

  1. ε 从 1 线性衰减到 0.1，并把最近若干帧堆叠成一个状态
  2. ε 固定为 0，并把画面里的每一帧单独作为一个状态输入
  3. ε 从 0.1 线性增长到 1，并且只使用最近的那一帧作为状态
  4. ε 始终保持为 1，并把每一步的奖励放大到一个很大的区间

为什么：早期需要高 ε 把缓冲区在不同区域铺开， 后期需要低 ε 让学到的贪心策略被执行，所以从 1 衰减到 0.1 是标准做法。 堆叠多帧是为了让状态包含速度信息，单帧不满足马尔可夫性。

B 与 C 都取消了探索，缓冲区会迅速退化成只在少数状态上打转。 D 保持了纯随机行为，等于从不利用已经学到的价值； 放大奖励则正好违反"裁剪奖励以稳定学习"的做法。

代码题 1 · 写固定容量的环形回放缓冲区

背景DQN 每走一步得到一条转移 (s, a, r, s′, done)，先存起来，更新时随机抽一批算目标与损失，靠随机性打断样本之间的相关性。回放缓冲区就是这个容器，容量固定，写满后新转移覆盖最旧的一条。训练循环每步调用 push 存一条，每次更新前调用 sample 取一批，len 给出当前条数。请实现 ReplayBuffer(capacity, seed=0) 的 __init__、__len__、push、sample，只许用标准库和 numpy。补一句 numpy：数组是一排（或几排）数字的容器，形状说的是它几行几列，下标从 0 开始数。

输入

  • capacity：整数，缓冲区能存的最大条数（测试用 4、32）。
  • seed：整数，交给 np.random.default_rng 存成 self.rng；采样只用它。
  • s：push 的当前状态标量。
  • a：push 的动作标量，测试里是整数下标。
  • r：push 的即时奖励标量。
  • s_next：push 的下一状态标量。
  • done：push 的布尔标量，True 表示这条在 s_next 终止。
  • batch_size：sample 的整数，一批抽多少条。

输出

  • __init__：无返回值，只建好空缓冲区。
  • __len__：返回 Python int，当前条数，从 0 起，到 capacity 为止不再增加。
  • push：无返回值，原地写入一条转移，满了覆盖最旧的一条。
  • sample：有放回均匀抽 batch_size 条，返回五元组 (states, actions, rewards, next_states, dones)，五个 numpy 数组长度都等于 batch_size；states、rewards、next_states 是 float，actions 是整数，dones 是 bool。

会被检验空缓冲区长度为 0；容量 4 写进 6 条后长度保持 4、只留最后 4 条；sample(200) 的五个数组长度都是 200，dtype 分别是浮点、整数、布尔；五个数组同一下标必须来自同一条转移（用 a = s % 3、r = s * 10.0、s_next = s + 1、done = (s % 2 == 0) 核对）；容量 32 抽 500 条要覆盖到至少 25 条。

卡住了？看提示
  • 用一个 self.pos 记录下一个写入位置，写入后 self.pos = (self.pos + 1) % capacity。 % 是取余数，位置走到末尾会绕回 0，这就是环形缓冲区。
  • 容量固定，所以直接预分配五个数组最省事：np.zeros(capacity) 造一串全是 0 的数， np.zeros(capacity, dtype=np.int64) 造整数数组， np.zeros(capacity, dtype=bool) 造真/假数组。 再用 self.size 记住当前实际存了几条。
  • __len__ 直接返回 self.size；push 把五个值分别写进 self.states[self.pos] 这些位置，再移动 self.pos、更新 self.size。
  • 采样用 idx = self.rng.integers(0, len(self), size=batch_size)。 它返回长度 batch_size 的整数数组，每个数在 0 到 len(self)-1 之间（右端取不到），而且是有放回地抽。
  • 最后用同一组 idx 去索引五个数组并一起返回： self.states[idx], self.actions[idx], ...。 同一组下标才能保证五个值来自同一条转移，配对不会乱。

代码题 2 · 用 numpy 手写 DQN 目标与损失

背景DQN 的一次梯度更新分三步：用目标网络算下一状态的 Q(s′,·) 并折算成 TD 目标 y，再用在线网络对所选动作的输出与 y 算损失并反传。这两个函数承担后两步，由手写训练循环调用。终止样本的目标只能等于即时奖励。请实现 dqn_targets(rewards, dones, next_q_values, gamma) 与 dqn_loss(q_values, actions, targets)，都不修改输入，只许用 numpy。补一句 numpy：axis=1 表示"沿每一行做运算"，对二维数组取最大值时会得到每一行的最大值。

输入

  • rewards：形状 (B,) 的 float 数组，即时奖励。
  • dones：形状 (B,) 的 bool 数组，True 表示该条在 s′ 终止。
  • next_q_values：形状 (B, n_actions) 的 float 数组，目标网络在 s′ 上给出的 Q 值。
  • gamma：float，折扣因子 γ。
  • q_values：形状 (B, n_actions) 的 float 数组，在线网络对当前状态的输出。
  • actions：形状 (B,) 的整数数组，已执行的动作下标。
  • targets：形状 (B,) 的 float 数组，目标 y。

输出

  • dqn_targets 返回 np.ndarray，形状 (B,) 的 float：第 i 个元素是 yi = ri + (1 − donei) γ maxa′ Qtarget(s′i, a′)。
  • dqn_loss 返回二元组 (loss, grad)。loss 是 Python float，所选动作 Q[si, ai] 与 yi 的均方误差；grad 是 np.ndarray，形状 (B, n_actions)，只有 (i, ai) 位置非零，值为 2(Q[si,ai] − yi) / B。

会被检验dones 为真时即使 Q(s′,·) 全是 1e6，目标也只等于 r；非终止样本按最大值自举（如 0.9×max(2,5) = 4.5）；dqn_loss 只统计被选中的动作，Q 全为 9 而只选动作 0 时算 (1−3)² = 4；所选 Q 正好等于目标时 loss 为 0 且 grad 全零；未被选中的位置梯度严格为 0。

卡住了？看提示
  • 目标里"终止不自举"可以用 (~dones) 乘在自举项上，一行搞定。 ~ 是布尔取反：True 变 False、False 变 True。
  • 先取下一状态每一行的最大值：np.max(next_q_values, axis=1)。 axis=1 表示沿每一行压下去，返回形状 (B,) 的一维数组。
  • 再拼目标：rewards + gamma * bootstrap * (~dones)。 形状相同的数组逐项相乘；一个数乘一个数组时，numpy 会把这个数用到每个元素上。
  • 取所选动作用花式索引 q_values[np.arange(B), actions]： np.arange(B) 返回 0 到 B−1 的一串整数， 和 actions 配起来，就取出了每一行里被选中的那一个值。
  • 均方误差对所选值的导数是 2 * diff / B，别漏掉除以 B。 把梯度写回去也用同一种花式索引：grad[np.arange(B), actions] = 2.0 * diff / B。
