进阶 · 第二部分 · 无模型方法

n-step 回报与 TD(λ)

这一节回答一个问题：估计一个局面值多少分时，往前看几步最合适？ 只看一步最省事，看完一整局最准但来得最慢。中间还有一整排选择， 而且可以用一个旋钮把它们平滑地混在一起。下面从两个极端说起。

你会得到

  • 能写出 n-step 回报，并说出 n=1 与 n=∞ 各退化成什么
  • 能解释资格迹为什么让"看未来多步"变成单步在线更新
  • 知道实践中 n 与 λ 该取多少，以及迹的累积式与替换式之别

两个极端之间是一整条谱

先看两个极端。TD(0) 是最省事的那一种： 它的更新目标只有一步真实奖励，再加上一项自举（用自己当前的估计去更新自己当前的估计，等于自己拽自己的鞋带往上提）。它说的是： 目标里那个 V(St+1) 并不是真实答案，它只是自己当前的估计。 式中 γ 是折扣因子（越往后的奖励，算进总分时权重越小，相当于给它打了个折）。 TD(0) 是时序差分（不用等到一局结束，用"走一步之后的新估计"来更新"走这一步之前的估计"） 里最简单的一种，这个做法英文叫 temporal difference，简称 TD。

TD(0) 的两项统计性质正好相反：方差小，偏差大。 这两个词要先说清。偏差（估计值稳定地偏离真值）说的是"平均下来是歪的"； 方差（同一个做法重复很多次，结果波动有多大）说的是"每次上下抖多少"。 TD(0) 的偏差来自 V(St+1) 本身还没学准， 方差小是因为目标里只有一步随机奖励。

另一个极端是蒙特卡洛 （把一整局走完，用真实拿到的总分来估计价值）：它用完整的回报（从现在起一直到结束，把每一步奖励加起来的总分） Gt，没有偏差， 但方差大，而且必须等一整局结束才能更新一次。 折扣回报（把回报里越靠后的奖励打上越重的折之后得到的总分）是它实际在算的那个数。

这两者之间还有一整排选择。n-step 回报（n-step return：先往前看 n 步拿真实奖励，剩下的用估计补上）把自举往后推了 n 步：

Gt(n) = Rt+1 + γ Rt+2 + … + γn−1 Rt+n + γn V(St+n) (11.1)

式子里每个符号在实现里都很直白。n 是"自举之前先走几步真实奖励"。 式子里的 γn 读作"γ 的 n 次方"，也就是 γ 连乘 n 次； γn−1 同理，是连乘 n−1 次。 n=1 时右边只剩 Rt+1 + γ V(St+1)，就是 TD(0)； n 一直取到回合结束、把 V 那一项换成 0，就是蒙特卡洛的 Gt。中间的每个 n 都合法，也都是不用环境模型的。

调 n 就是在调偏差与方差的配比：n 越大，越少依赖自己那个可能不准的 V（偏差小），但要累积越多步真实奖励（方差大）。 代价是延迟更新（delayed update）：要更新 t 时刻的价值， 得先观察到 t+n 步。离线（不能与真实环境交互，只能用已经攒下来的历史数据学） 批量学习无所谓，在线控制里要缓存最近 n 步。

λ-回报：把所有 n 加权平均

与其在 n 上做单选题，不如把所有 n 一起用，按几何权重平均。 每一个 n 拿到的权重按 λ 的幂次递减，所以越近的 n 说话越算数。 这就是 λ-回报（λ-return）：

Gtλ = (1 − λ) Σn=1∞ λn−1 Gt(n) (11.2)

前面的 (1 − λ) 只是让所有权重加起来等于 1。 λ=0 时权重全给了 Gt(1)，退化成 TD； λ=1 时权重均匀铺到无穷步上，等于蒙特卡洛回报。 以 λ=0.9 为例，n=1 的权重是 0.1，n=10 的权重约 0.035，越近的 n 说话越算数。

式子里那个 Σ（求和号，把后面那串东西全加起来）表示从 n=1 开始， 把每一个 n 对应的 n-step 回报乘上它的权重，一项一项加下去。

前向视图与后向视图

式 (11.2) 叫前向视图（forward view，站在 t 时刻往未来看）。 它的概念干净，但要求在 t 时刻就知道未来所有步的奖励，没法在线实现。 工程里实际能用的是后向视图（backward view，从当前这一步往回记账）。

后向视图给每个 (s,a) 配一个资格迹（eligibility trace，刚做过的事记得最清，越久越淡）。 可以想成给最近走过的每个状态动作对记一笔"欠账"：被访问时这笔账加 1， 之后每一步都乘 γλ 慢慢缩水。

更新量是 δt 乘 Et(s,a)， 其中 δt 是 TD 误差（这一步的目标减去当前的估计， 表示"这一步估计得偏高还是偏低"），Et(s,a) 就是那笔欠账。 刚刚走过的、走过多次的 (s,a) 被更新得更多。 迹就是一份短期记忆，记录哪些状态动作对最近参与过决策， 好把当前这个 TD 误差按贡献分摊回去。 把最后的结果摊回中间若干步，这件事叫信用分配（最后的结果该算在哪几步头上）， 迹在这里给了它一个可实现的解法。

两种视图在数学上是等价的（S&B 第 12.2 节）。工程上的差别才是关键： 后向视图每步都能更新，内存只需要一张和 Q 一样大的表，不用等未来。

SARSA(λ) 与两种迹

把后向视图接到上一课的 SARSA 上，就是 SARSA(λ)。 SARSA 学的是一套策略（策略就是"看到什么状态就选什么动作"的规则）值多少分， 也就是在某个状态下先选某个具体动作、之后再好好走能拿多少总分。 更细一点说，价值函数（从某个状态出发、按某套策略走下去，平均能拿多少总分） 和动作价值（在某个状态下先选某个具体动作、之后再好好走，能拿多少总分）是它的两种形式， 本课更新的是动作价值 Q，也就是每个状态动作对占一格的那张表。

Et(s,a) = γλ Et−1(s,a) + 1{St=s, At=a} (11.3)
Q(s,a) ← Q(s,a) + α δt Et(s,a),   δt = Rt+1 + γ Q(St+1,At+1) − Q(St,At) (11.4)

式中 α 是学习率（每次更新时往新信息的方向挪多远）， δt 是上面那个 TD 误差。 式 (11.4) 里的箭头 ← 读作"更新为"，左边那个数被右边的结果替换掉。

其中 1{·} 是指示函数，条件成立取 1，否则取 0。 式 (11.3) 叫累积式迹（accumulating trace）：重复访问同一个 (s,a) 会不断累加。 另一种是替换式迹（replacing trace）：命中时把该位置直接置为 1。 长回合里替换式通常更稳、学得更快，因为它不会让一个反复经过的状态把权重吃满。

把 λ 设成 0，式 (11.4) 每一步之后迹就清零，只剩下当前 (s,a) 被更新，正好退化回普通的 SARSA。 你上一课写的那个算法，就是这一族算法的 λ=0 端点。

再把几个容易混的名字分开，后面的选择题会用到它们。 策略评估（给定一套策略，算出它到底值多少分）； 策略改进（根据算出的分数，把策略里明显吃亏的选择换掉）； 策略迭代（反复"打分 → 改招"，直到改不动为止）。 这几个名字属于动态规划那一族方法，本课只借它们的名字做对照，不展开。

实践建议与诊断

  • n 取 3–5，λ 取 0.9 左右。这两个数都是超参（需要你自己设定、 而不是训练学出来的参数）。中间值通常比两个端点都好，这是 S&B 第 7 章的核心结论。
  • 量级直觉：γ=0.9、λ=0.9 时，10 步之前的迹权重是 (γλ)10 ≈ 0.35，20 步之前只剩 0.12。再远的经历基本被忘掉。
  • λ 太小：学得慢，而且继承了 V 的偏差。λ 太大：方差大，学习曲线抖。
  • 本课的定位：n-step 与 TD(λ) 算不上新算法族，它们只是把"TD 还是 MC（Monte Carlo，蒙特卡洛）"从选择题变成了两个旋钮。
  • 状态空间（所有可能状态的集合）很大时，这张表本身就装不下，那得换一条路， 叫函数逼近（状态太多记不下整张表，干脆用一个带参数的函数去"猜"价值）。 那是 0012 课的事。

为什么后面还要用：0019 课的 GAE（generalized advantage estimation）就是把这里的 TD(λ) 原封不动搬去估计优势（在某个状态下，选这个动作比"平均水平"好多少）， 也就是优势函数（在某个状态下，选这个动作比"平均水平"好多少）。 这套做法中文译作广义优势估计，说的就是这件事。 它们都属于信赖域（规定这一步只允许在"离旧策略不太远"的范围内改）这一类"别改太狠"的思路； TRPO（trust region policy optimization，信赖域策略优化）与 PPO（proximal policy optimization，近端策略优化）里的 λ 就是这个 λ。 n-step 回报也常出现在 0013 课之后的 DQN（deep Q-network，深度 Q 网络）变体里，用来缩短自举链。

课后练习

1. n-step 回报里，n=1 与 n=∞ 分别对应哪两种方法？

  1. n=1 对应时序差分 TD(0)，n=∞ 对应蒙特卡洛方法
  2. n=1 对应蒙特卡洛方法，n=∞ 对应时序差分 TD(0)
  3. n=1 对应动态规划的策略评估，n=∞ 对应蒙特卡洛方法
  4. n=1 对应时序差分 TD(0)，n=∞ 对应动态规划的策略迭代

为什么：n=1 时式 (11.1) 只剩一步真实奖励加一个自举项，就是 TD(0) 的目标； n 取到回合结束、不再自举，得到的就是完整回报 Gt，即蒙特卡洛。 中间任意 n 都落在两者之间。

B 把两端对调了。C、D 混进了动态规划，动态规划需要环境模型，而这一族方法都不需要。

2. 把 n 调大（多走几步真实奖励、少自举几次）会怎样？

  1. 偏差与方差同时减小，因此 n 取得越大，结果总是越好
  2. 偏差增大但方差减小，因为向价值估计自举的次数变少了
  3. 偏差减小但方差增大，因为要累积更多步的随机奖励
  4. 偏差与方差都不变，n 只影响更新发生的先后顺序

为什么：自举项 γnV(St+n) 带着 V 的偏差，n 越大它权重越小，所以偏差下降； 同时真实奖励项变多，每步奖励的随机性累加起来，方差上升。 这就是 TD 与 MC 的权衡被 n 参数化之后的样子。

A 错在假设可以两全。B 把两个方向说反了。D 错：n 改变的是估计量的统计性质，不只是时序。

3. 资格迹（后向视图）在实现上最本质的好处是什么？

  1. 它完全消除了自举带来的偏差，让估计变得与蒙特卡洛一样无偏
  2. 它把状态空间压缩成一个低维向量，从而避免了维度爆炸问题
  3. 它让学习率可以安全地取到 1，因此不再需要手动调任何超参数
  4. 它把"等未来 n 步"变成单步在线更新，记忆量只是一张额外表

为什么：前向视图要等未来所有步的奖励，后向视图只用当前这一条转移 和一张资格迹表，就能实现同一个 λ-回报。这是"数学上等价、工程上可行"的典型例子。

A 错：迹不消除偏差，偏差由 λ 与自举决定。B 说的是函数逼近，与迹无关 （见 0012 课）。 C 错：学习率仍然要调，迹不改变步长条件。

4. 累积式资格迹与替换式资格迹的区别是什么？

  1. 累积式只在回合结束时清零，替换式在每一步都会清零迹值
  2. 累积式每次访问都做累加，替换式把该位置直接置为 1
  3. 累积式只用于离策略学习，替换式只用于同策略的学习
  4. 累积式需要同时维护两张表，替换式只需要维护其中一张表

为什么：差别只在"命中时怎么记"：累积式执行 E ← E + 1，替换式执行 E ← 1。 前者会让反复经过的 (s,a) 权重越堆越高，后者给了一个上限。

A 错：两种迹都按 γλ 每步衰减，不是只在回合末清零。 C 错：与 on/off-policy 无关。D 错：两者都只需一张与 Q 同形状的表。

5. 关于 n 与 λ 的常用取值，下列哪一项符合实践建议？

  1. n 常用 1，λ 常用 0，优先追求最低的估计方差
  2. n 常用 50 以上，λ 常用 1，优先追求最低的估计偏差
  3. n 常用 3 到 5，λ 常用 0.9 左右，兼顾估计偏差与方差
  4. n 常用 10，λ 常用 0.1，两项超参数都取偏小的值

为什么：n 与 λ 都在偏差-方差之间插值，中间值通常优于两个端点， 这也是 S&B 第 7 章的经验结论。n=3–5 意味着自举之前先看三到五步真实奖励， λ=0.9 意味着更远的经历按几何速度被遗忘。

A 与 B 分别取了两端的极端值，通常会落在折中方案的下风。 D 把两个旋钮都压小，结果接近 TD(0)，等于放弃了这一节的收益。

代码题 1 · 计算 n-step 回报

背景TD(0) 的目标只走一步真实奖励就自举，蒙特卡洛要等回合结束，n-step 回报把自举往后推 n 步，是这两端之间的一整条谱。 这个函数算的是式 (11.1) 里自举之前的那一半：从当前时刻往前数 n 步的折扣奖励和。 实践中它被用来拼 TD 目标，γnV(St+n) 那一项由调用方在外面补上。 它不碰价值函数也不依赖环境，输入就是一段奖励序列，输出一个可以直接拿去当目标的标量。 这里补一句 numpy 的基础：rewards 是一维数组，也就是一排数字的容器， 下标从 0 开始，rewards[0] 是当前时刻拿到的奖励，rewards[1] 是下一步的。

请实现 n_step_return(rewards, gamma, n)。

返回 R1 + γ R2 + … + γn−1 Rn (11.5)

输入

  • rewards：一维奖励序列，列表或 numpy 数组，rewards[0] 是当前时刻拿到的奖励。 len(rewards) 是序列的长度；
  • gamma：折扣因子 γ，0 到 1 之间的标量；
  • n：往前累计的步数，正整数。

输出

  • 返回 Python float，不是 numpy 标量：rewards 前 n 项的折扣累加， 下标 k−1 的那一项乘 γk−1。 序列长度不足 n 时只累计实际存在的那些项；rewards 为空时返回 0.0。

会被检验n=1 时只返回 rewards[0]； gamma=1、n=3、三个 1 时返回 3.0，gamma=0.5、n=3 时返回 1.75； n 超过序列长度不报错，只累计实际长度，三个 1 配 n=10 仍是 1.75； 奖励出现在第 3 步时被 γ2 衰减，[0.0, 0.0, 10.0] 配 γ=0.9、n=3 得 8.1； 返回值的类型是 Python float，能直接当 TD 目标用。只许标准库加 numpy。

卡住了？看提示
  • 先设两个变量：total = 0.0 存累加结果， weight = 1.0 存"这一项该乘的 γ 的幂"（第 0 项乘 γ0，正好是 1）。
  • 循环写成 for k in range(min(int(n), len(rewards)))。 min(...) 取两者中较小的那个，序列不够长时自动截断，不会越界报错。
  • 循环体里做两件事：先 total += weight * rewards[k]， 再 weight *= gamma（为下一项把折扣再乘一次）。
  • 循环结束后 return total。不要每一项都写 gamma ** k，累乘更简单也更快。

代码题 2 · 写一步 SARSA(λ) 的累积式资格迹更新

背景λ-回报的前向视图要求站在 t 时刻看未来所有步，没法在线实现。后向视图给每个 (s, a) 配一个资格迹， 把当前这一步的 TD 误差按迹分摊回最近参与过决策的格子，于是每一步都能更新，内存也只要一张和 Q 一样大的表。 这个函数是训练循环里最内层的那一次调用，它同时维护 Q 表与形状相同的资格迹 E。 输入是上一步留下的 Q、E 与当前这一步的转移，输出更新后的二元组，调用方拿它们继续走下一个环境步。对应的公式是式 (11.3) 与 (11.4)。

请实现 sarsa_lambda_step(Q, E, s, a, r, s_next, a_next, done, alpha, gamma, lam)，返回新的 (Q, E) 二元组。

输入

  • Q：形状 (状态数, 动作数) 的二维 numpy 数组，动作价值表。 二维数组就是排成几行几列的一堆数字，Q[s, a] 是第 s 行第 a 列那一格， 下标从 0 开始；
  • E：与 Q 同形的二维 numpy 数组，资格迹，记录哪些 (s, a) 最近参与过决策；
  • s、a：当前状态与动作的整数下标；
  • s_next、a_next：下一状态与下一动作的整数下标，a_next 由行为策略给出；
  • r：这一步拿到的即时奖励，float；
  • done：布尔值，表示 s_next 是不是终止状态；
  • alpha：学习率 α；gamma：折扣因子 γ；lam：迹衰减参数 λ，都是标量。

输出

  • 返回二元组 (Q_new, E_new)，两个都是 np.ndarray，形状分别与传入的 Q、E 相同；
  • Q_new：这一步之后的整张动作价值表。按迹分摊的结果是可能有多于一个格子被改动，不只是 [s, a]；
  • E_new：这一步之后的资格迹，供下一次调用接着用。传入的 Q 与 E 都不被就地修改。

会被检验λ=0 时返回的 E 全为 0，但当前 (s, a) 仍被更新； 重复访问同一个 (s, a) 后迹累加到 2，说明用的是累积式而不是替换式； γλ=1 时先前访问过的 (s, a) 也会被更新，更新的是整张 Q 而不是单个格子； done=True 时 Q[s_next, a_next] 不参与自举，即使它的值很大； 传入的 Q 与 E 在调用后保持原值。只许标准库加 numpy。

卡住了？看提示
  • 第一步，复制两份可写的表：Q = np.array(Q, dtype=float)、 E = np.array(E, dtype=float)。np.array(...) 返回新数组， 改它不会动到调用方传进来的那个。
  • 第二步，给当前格子记一笔欠账：E[s, a] += 1.0。 这就是"累积式"：同一格再被访问一次就再加 1。
  • 第三步，先算 TD 误差 delta。done 为真时 delta = r - Q[s, a]；否则 delta = r + gamma * Q[s_next, a_next] - Q[s, a]。
  • 第四步，按迹把误差分摊回去，整张表一起更新：Q += alpha * delta * E。 E 与 Q 同形状，numpy 会对每个格子各算各的。 λ=0 时 E 只有当前格子非零，效果退化成只更新 (s,a)。
  • 第五步，让迹缩水：E *= gamma * lam。最后 return Q, E。
