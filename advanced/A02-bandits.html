多臂老虎机：探索与利用

这一节从最简单的选择讲起：反复挑一样东西，每次都只能看到拿到多少分，没有别的信息。 你会看到三种挑法各自把"试着换一个"的机会花在哪里，也能说清 ε-greedy（ε 是探索率，也就是平均一百次决策里， 大约有几次去随便试一个）、乐观初始值、UCB（upper confidence bound，置信上界）分别适合什么场景。

你会得到

  • 能写出样本平均的增量式更新式，并解释 1/n 与固定 α（步长）的区别
  • 能说清三种探索策略各自解决什么毛病、什么时候失效
  • 能判断一个业务场景该不该先当老虎机来做

剥到只剩骨架的强化学习（RL）

先看一个每天都会遇到的小决定。首页有十张 banner（网页或 App 顶部那条可以点的图片广告）， 但展示位只有一块，你只能放一张，目标是点率最高。点率就是"看到它的人里，有多大比例真的点了它"。 每张 banner 的真实点率是固定的，但你事先不知道。你能做的只有一件事：今天放一张，看有多少人点，明天再换个方式试。 这里没有"状态"：昨天放了哪一张，不会改变今天的点率，这一次的选择也不会影响下一刻的局面。 这类问题有个名字，叫 k 臂老虎机（k-armed bandit，一排老虎机摆在你面前，你不知道哪台吐钱多）。

它比完整的强化学习少了最重要的东西：长期后果。剩下的只有一件事要权衡： 继续用现在看起来最好的那个，还是花一次机会试试别的。 所有算法的"探索直觉"都可以在这里用最低成本试出来。真实业务里，A/B 测试（把流量分成几组、每组给不同方案，比一比哪组效果好）的流量分配、 冷启动阶段的推荐位选择、广告素材轮换，都是老虎机问题的直接对应物。

动作价值与它的估计

先给每个臂定一个分数。所有臂合起来，就是你这一步能做的全部选择，也就是动作空间（你这一步能做的选择有多少种）。 其中第 a 个臂的分数叫它的动作价值（先选这个动作，之后再好好走，平均能拿多少总分）， 定义成"拉起这个臂，长期平均能拿到多少奖励"：

q*(a) = 𝔼[ Rt | At = a ] (2.1)

式子里的 𝔼（期望，同一件事重复很多次之后的平均结果）说的是：把"拉这个臂"重复很多次， 每次的奖励加起来再除以次数。真实点率是固定的，所以重复得越多，这个平均越接近真实值。

现实里你拿不到真值，手上只有一个估计 Qt(a)。 最自然的估计是"到目前为止这个臂的平均奖励"，叫样本平均法（sample-average method，把拿到的奖励全加起来再除以次数）。 每一步都挑当前估计最大的臂下注，这种选法叫贪心（greedy，只挑眼前最好的那个）。

贪心的问题很具体。第一张 banner 碰巧第一个被点了一下，它的估计就领先， 于是你再也不给别人机会。可一次点击说明不了什么，估计里带着噪声，它不是真实点率。

增量式更新：两个数记住全部历史

把 n 次奖励全存下来再求平均，内存会随步数一直涨。下面这个等价形式只需要两个数：

Qn+1 = Qn + (1/n) [ Rn − Qn ] (2.2)

读法是：新估计 = 老估计 + 步长 ×（实际奖励 − 老估计）。方括号里是这一次的预测误差， 也就是"这次比原来的估计高多少、或低多少"。

这里最容易想岔：1/n 变小，意思并不是"后来的尝试不值钱"。 每一次拿到的奖励，在最终结果里的分量完全一样——都占 1/n 里的那一份。 1/n 之所以越来越小，是因为分母在变大：样本从 3 个变成 300 个， 这一次的修正自然只占总量的一小部分。

手算一遍就清楚了。假设三次拿到的奖励分别是 1、2、3：

  • 第 1 次：Q = 0 + (1/1)×(1 − 0) = 1，也就是第一次的奖励本身；
  • 第 2 次：Q = 1 + (1/2)×(2 − 1) = 1.5；
  • 第 3 次：Q = 1.5 + (1/3)×(3 − 1.5) = 2。

而 (1 + 2 + 3) / 3 = 2，一模一样。这个式子算出来的，就是全部奖励的算术平均： 早期和后期的奖励同等重要，只是换了个算法，不必把历史全存下来。

别把它和折扣因子（越往后的奖励，算进总分时权重越小，相当于给它打了个折，常用 γ 表示） 搞混。折扣因子是"未来的奖励故意打折"，那是你为了表达"远期收益没那么重要"而主动做的取舍； 1/n 只是平均值的记账方式，没有"后来者不值钱"这层意思。

这个"估计 + 步长 × 误差"的形状会一路跟着你。后面要学的策略 （一套"看到什么状态就选什么动作"的规则）也是这么一小步一小步改出来的， 同样的形状会一直用到 Q-learning 和 PPO（proximal policy optimization，近端策略优化）。

把 1/n 换成固定常数 α（比如 0.1），得到的是指数加权平均： 近期奖励权重更高，估计大约只记得最近 1/α 次的结果。 推荐的点击率会随季节和活动漂移。奖励分布不随时间变化的场景叫静止环境，会漂移的叫非静止（nonstationary）场景。 漂移的场景必须用固定 α；静止环境才用 1/n，因为这样算出来的估计最终会收敛 （一轮轮算下去，数值不再明显变化，稳定下来了），停在真实均值附近。

ε-greedy：把探索写成预算

概率先用一句话理解：平均一百次里大约发生几次。以概率 ε 随机选一个臂， 就是"平均一百次里，大约有 ε × 100 次去随便试一个"，剩下的次数选当前估计最大的那个：

At = 随机臂（概率 ε）；arg maxa Qt(a)（概率 1 − ε） (2.3)

式子里的 arg max 读作 arg-max，意思是"挑出让后面那个式子最大的那个选择"： arg maxa Qt(a) 就是挑出当前估计最大的那个臂。

工程上它就是"拿出 10% 的流量做随机投放"。好处是实现简单，也不需要任何环境知识。 坏处是探索太平均：它照样会去试已经明显很差的臂。而 ε 固定不变，意味着永远有一部分步数 花在没有信息的尝试上，长期平均收益比最优策略低一截。

两种更聪明的探索

乐观初始值（optimistic initial values）

做法很土：把每个臂的初始估计 Q1(a) 设成一个偏高的数。 奖励上限是 1，你就设成 5。一开始每个臂都"看起来很好"，贪心会把它们挨个试一遍。 真拉起来总是失望，估计一路往下掉。探索就是被这份失望推着走的，不需要 ε。 它只适合静止环境：环境一变，这些虚高的初值就不再提供任何信息。

UCB：按不确定性分配探索

At = arg maxa [ Qt(a) + c √( ln t / Nt(a) ) ] (2.4)

Nt(a) 是臂 a 到现在被选过多少次。 试得少的臂，根号里的分母小，加分项就大；试得多的臂，加分项趋近于零。 这份加分让它自动拿到"置信上界（upper confidence bound）"的身份。

于是探索被挤到没把握的地方：Nt(a) = 0 的臂加分视为无穷大， 开局每个臂必须先各试一次。常数 c 决定探索的激进程度，越大越敢试没试过的臂。

有一种误读是"UCB 更聪明，所以不用探索"。它是更省，不是不用： 少了那一次初始访问，它连一个数都拿不到。

什么时候先做老虎机就够了

判断标准只有一条：你这次的选择会不会改变以后各选项的收益。 今天放哪张 banner 不影响明天的用户构成，那它就是个老虎机问题，别急着上 Q-learning。 先当成静止或缓慢漂移的老虎机，用 ε-greedy 或 UCB 把收益拿稳， 再问要不要把状态加回来（见第 0003 课）。

诊断视角：线上 A/B 测试长期跑不出结论，问题多半不在样本量，而在"胜利者诅咒"： 你在多个臂上反复偷看指标，把噪声当成了信号。固定的探索预算比"随时切到当前最好"更可靠。

还有一种更细的做法叫梯度老虎机（gradient bandit）。它不用价值估计，改用一组 softmax （把一组原始分数变成一组加起来等于 1 的概率，分数高的概率大）偏好 （每个臂一个可正可负的打分，只表示相对好坏，不是奖励本身），适合只关心相对名次的场景。 推导见 Sutton & Barto 第 2.8 节。

课后练习

1. ε 固定不变的 ε-greedy 在训练后期仍然拿不到最优收益，最主要的原因是什么？

  1. 价值估计的方差太大，导致 argmax 经常选到错误的那个臂
  2. 初始值设置得不够乐观，导致一部分臂始终没机会被访问到
  3. 总有固定比例的步数在执行一次没有信息量的随机尝试
  4. 样本平均法会遗忘早期的奖励，使估计逐渐偏离真实均值

为什么：固定 ε 意味着每个时刻都有 ε 的概率完全随机选臂， 这部分流量永远学不到东西，稳态收益因此被钉在最优值以下（Sutton & Barto 第 2.3 节）。

A 把稳态损失说成了估计噪声：估计方差只影响收敛快慢，不影响"是否永远随机试"。 B 误以为 ε-greedy 依赖乐观初值，那是另一条独立路线。 D 说反了：遗忘早期奖励是固定步长 α 的性质，样本平均不遗忘。

2. 把增量式更新里的步长 1/n 换成固定常数 α = 0.1，会发生什么？

  1. 估计变成指数加权的平均，近期奖励权重更高，能跟上漂移的环境
  2. 估计仍然等于算术平均，只不过每一步的计算量变得明显更小
  3. 估计不再收敛，会随着每次奖励的符号在真值附近持续震荡
  4. 估计将永远停留在第一次奖励上，之后的奖励会被完全忽略掉

为什么：固定步长下老数据的权重按 (1−α)k 指数衰减，估计只反映最近大约 1/α 次的结果，代价是引入了稳态偏差， 收益是能跟踪非静止的奖励分布（S&B 第 2.5 节）。

B 错在"仍然等于算术平均"：它是有偏的滑动平均。 C 错在把权重衰减当成不收敛：估计依然会收敛，只是收敛到一个指数加权均值。 D 描述的是 α = 1 的极端情况，而不是 0.1。

3. UCB 与 ε-greedy 在选择动作时最本质的差别是什么？

  1. UCB 完全不估计动作价值，只按每个臂被访问过的次数来排序
  2. UCB 的探索比例会随训练推进单调上升，最终覆盖到所有的臂
  3. UCB 只在静止环境中有效，而 ε-greedy 只能用于非静止的环境
  4. UCB 给不确定性高的臂额外加分，把探索集中在没把握的地方

为什么：UCB 的选择值是"价值项 + 置信上界加分项"，加分项随访问次数增加而下降， 所以它把试验次数优先分给样本少、估计不可靠的臂，而不是像 ε-greedy 那样均匀乱试。

A 忽略了价值项 Qt(a)，那才是 UCB 的主项。 B 说反了：ln t 增长慢于 Nt(a)， 加分项随时间单调下降，探索是递减的。 C 也反了：置信上界依赖奖励分布静止，漂移环境里 UCB 反而吃亏。

4. 用乐观初始值来驱动探索，什么情况下它会失效？

  1. 当臂的数量很少、每个臂被反复访问很多次的时候
  2. 当环境非静止、奖励分布随着时间不断漂移的时候
  3. 当奖励的取值范围是负的、初始值只能设成负数的时
  4. 当估计采用样本平均而不是用固定步长来做更新的时候

为什么：乐观初始值靠"初值误差"制造前期探索，它假设奖励分布不动。 环境一旦漂移，被平均进来的旧数据不再代表当前分布，虚高的初值也不再提供任何信息， 所以 Sutton & Barto 第 2.6 节明确把它归为静止环境的方法。

A 恰好是它最有效的场景（臂少、访问多时误差很快被洗掉）。 C 不成立：初值只要高于当前真实值就能驱动探索，与奖励正负无关。 D 也反了：S&B 图 2.3 的标准组合就是"乐观初始值 + 样本平均"。

5. 把一个业务问题先当成老虎机来处理，最重要的前提是什么？

  1. 动作空间需要是连续的，这样才能做足够精细的流量分配
  2. 你必须能事先精确估计出每个动作真实期望收益的上界
  3. 当前的这一次选择不会改变后续各动作的收益分布
  4. 奖励必须是稀疏出现的，否则探索不会带来任何额外收益

为什么：老虎机假设无状态、无延迟后果：每次拉臂得到的奖励分布只由臂本身决定， 与其他时刻的选择无关。满足这条，长期后果这一整块复杂度就可以先不付。

A 相反：老虎机通常是少量离散的臂，连续动作是后续课程的问题。 B 说的就是老虎机要解决的问题：真值未知才需要估计。 D 与稀疏性无关：密集奖励同样需要探索来发现更好的臂。

代码题 1 · 用增量式公式更新臂的均值估计

背景老虎机的核心是把每个臂的价值估计成它至今的平均奖励。这个函数用增量式公式在线更新这一步被拉起的那个臂：每来一个新奖励，就把估计往它那个方向挪一点点，不需要保存全部历史奖励。它在学习循环里每次拉臂后调用，输入是这一步选了哪个臂、拿到多少奖励，输出是更新后的价值估计与访问计数。

请实现 incremental_update(Q, N, a, reward)。

N[a] ← N[a] + 1；  Q[a] ← Q[a] + (reward − Q[a]) / N[a] (2.5)

式子里的 ← 读作"更新为"：把右边算出来的值写回左边这个位置。两行有先后，先把计数加一，再用新的 N[a] 当分母。

输入

  • Q：长度 k 的一维 numpy 数组（一排数字的容器），形状记作 (k,)，存每个臂的价值估计；
  • N：同样长度、同样形状的整数数组，存每个臂被访问过的次数；
  • a：本轮所选臂的整数下标，从 0 开始数，所以合法取值是 0 到 k-1；
  • reward：本轮拿到的浮点奖励，一个数。

输出

  • 返回更新后的 (Q, N)，两个数组的长度与传入时相同，N 保持整数类型；只有下标 a 那一项被改写，Q[a] 是历史上所有奖励的算术平均。

会被检验同一臂连续更新 7 次后 Q[a] 与 np.mean 一致；两次相同的奖励 10.0 会使估计停在 10.0；第一次更新后 Q[a] 就等于那次奖励；没被访问到的臂，Q 与 N 一个元素都不能改动。就地修改传入数组或返回新数组都可以；只用标准库与 numpy，本题不需要随机数。

卡住了？看提示
  • Q 和 N 都是 numpy 数组，Q[a] 是取第 a 个位置上的数（下标从 0 开始）。
  • 第一步先做 N[a] += 1，把访问次数加一。第二步的除法要用这个新值当分母；顺序反了，第一次更新就会除以 0。
  • 第二步算误差 reward - Q[a]，除以 N[a] 得到这一步要挪的距离，再加回 Q[a]： 写成一行就是 Q[a] += (reward - Q[a]) / N[a]。
  • 不需要保存历史奖励，那个误差就是全部所需信息。最后 return Q, N；就地改传入的两个数组也行。

代码题 2 · 用 UCB 加分挑出下一个臂

背景UCB（upper confidence bound，置信上界）把探索预算花在估计最不确定的臂上：估计值加上一个随访问次数下降的加分项，加分大的臂优先被选。这个函数在每轮决策时被调用，输入是当前的价值估计与访问次数，输出这一步要拉的臂。它只做选择，不更新任何估计。

请实现 ucb_select(Q, N, c, t)。

At = arg maxa [ Q[a] + c √( ln t / N[a] ) ] (2.6)

输入

  • Q：长度 k 的一维 numpy 数组，形状 (k,)，存每个臂的价值估计；
  • N：同样长度、同样形状的整数数组，存每个臂的访问次数；
  • c：控制探索强度的 float 系数，越大越敢试访问少的臂；
  • t：当前总步数，整数且至少为 1。

输出

  • 返回本轮要选的动作下标，类型为 int，取值 0 到 k-1。

会被检验N[a] == 0 的臂加分视为无穷大，必须先访问，有多个未访问的臂时返回下标最小的那个；加分项相同时取下标较小的臂；所有臂访问次数相同时退化为选价值最高的臂；完全平局时返回下标 0。测试还会核对传入的 Q、N 一个元素都没被改动。只用标准库与 numpy，本题不需要随机数。

卡住了？看提示
  • 先查有没有没访问过的臂：N == 0 得到一个布尔数组， np.where(...)[0] 把里面为 True 的位置下标取出来，返回一个下标数组。
  • 这个数组非空时，直接返回它的第一个元素 int(unvisited[0])。它的下标最小，正好满足"有多个未访问臂时返回下标最小的那个"。
  • 否则算加分项：bonus = c * np.sqrt(np.log(t) / N)。np.log(t) 是 t 的自然对数，返回一个数； np.sqrt 是开平方。除法和开方都逐项作用在整个数组上，得到每个臂一个加分。
  • 最后 int(np.argmax(Q + bonus))。np.argmax 返回最大值所在的下标，平局时返回最小的下标。
  • 这个函数只做选择，不要修改传入的 Q 或 N。
