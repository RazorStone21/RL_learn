SARSA：on-policy 控制

前面两节都在"给一套做法打分"，这一节往前走一步：让程序自己改做法。 要学的算法叫 SARSA（state-action-reward-state-action，一种边学边改的控制方法）。 你会看懂一条只改动一个符号的更新式，以及它和下一课的那条式子为什么是两种完全不同的思路。

你会得到

  • 能写出 SARSA 的一步更新，并说清用 a' 而不是取最大值会带来什么后果
  • 能用自己的话解释 on-policy 的含义，以及它适合什么场合
  • 能解释悬崖行走上 SARSA 为什么学到远离悬崖的路径

从预测走到控制

先回顾一下手上有什么。第 0008 课的 TD(0) 估计的是 状态价值（只看状态、不管具体选哪个动作的那个价值）， 写作 V(s)。它回答的是"现在这个局面好不好"。

可我们要的是让程序自己把做法改好。这件事在强化学习里叫控制， 而控制（control，就是一边估价值、一边把做法往好里改） 需要的是另一个东西：动作价值 （在某个状态下先选某个具体动作，之后再好好走，能拿多少总分），写作 Q(s, a)。它回答的是"现在走这一步好不好"。

为什么一定要动作价值？因为要改做法，就得比较"这个局面下选哪个动作更好"。 只有动作价值能直接回答这个问题：挑出让 Q 最大的那个动作， 也就是 arg maxa Q(s, a)。 这里的 argmax 读作"arg-max"，意思是 argmax（挑出让后面那个式子最大的那个选择）。

把"每个状态都挑当前 Q 最大的动作"这条规则固定下来，就叫 贪心（在当前估计里挑看起来最好的那个）做法。 但只照着它走会有一个毛病：没被选过的动作，它的 Q 永远是初始值， 你也就永远不知道它到底好不好。所以要留一点概率去试别的，这就是探索（故意试试那些现在看起来不是最好的选择）。

把 TD 从 V 搬到 Q，会冒出一个新问题：更新目标里的"下一步价值"， 该用下个状态的哪个动作来算？这个算法（它的名字叫 SARSA，读作"萨萨"， 就是下面更新式里那五样东西的英文首字母）的回答是：用你下一步真会执行的那个动作 a'。

Q(s, a) ← Q(s, a) + α [ r + γ Q(s', a') − Q(s, a) ] (9.1)

先把公式 (9.1) 读一遍。箭头读作"更新为"； α 是学习率（每次更新时，往新信息的方向挪多远）； γ 是折扣因子（越往后的奖励，算进总分时权重越小，等于给它打了个折）； r 是这一步刚拿到的即时奖励； s 与 a 是刚离开的状态和刚执行的动作； s' 是进入的新状态，a' 是你在这个新状态下选出的下一个动作。

这个算法的名字就是更新式里用到的五样东西。它属于前面讲过的 时序差分（不用等到一局走完，用"走一步之后的新估计"来更新"走这一步之前的估计"）。 它的名字 SARSA 来自五个英文单词的首字母：state、action、reward、state、action， 也就是状态、动作、奖励、状态、动作。

每个符号在代码里都很好找：a 是刚执行的动作， r 是刚拿到的奖励，s' 是新状态， a' 是用当前做法在新状态上选出的动作。

用 a' 而不是取最大值，差别在哪

把 Q(s', a') 换成 maxa' Q(s', a')， 也就是换成"下个状态里最好的那个动作价值"，就得到下一课的 Q-learning。 一个符号的差别，划出了两类算法。这个差别会在下一课展开。

先看 SARSA 这一边。它评估的是你当前真正在用的那套做法的价值， 其中包括它偶尔随机乱走那部分的代价。所以 SARSA 的 Q 值乐观不起来： 它知道你会以 ε（探索率，就是每次决策时有多大比例的概率去"随便试一个"） 的概率随机动一下，于是把这份风险也算进了价值里。

这里顺便把两个容易混的说法讲清。真正在环境里做决定、产生数据的那套做法， 这条规则本身叫策略（看到什么状态就选什么动作的规则），这里叫它行为策略。 而当前正在学、正在被评估的那套做法，叫目标策略。

SARSA 里这两套是同一个，所以叫 on-policy（边学的那套，就是产生数据的那套）， 比喻是"边打边改自己的打法"。 如果边学的那套不是产生数据的那套，就叫 off-policy（边学的那套，不是产生数据的那套）， 比喻是"看别人的录像学自己的打法"。 第 0007 课提过这两个词，这里是第一次细说。

SARSA 怎么改做法？更新完 Q 之后，把行为策略也换成对 Q 的 ε-greedy： 大多数时候挑当前最好的动作，小部分时候随机试一个。行为策略与目标策略始终是同一个， 所以这套流程叫 on-policy 控制（边学边用同一套做法的那种控制）。

悬崖行走：两种"最优"的分野

Sutton & Barto 的悬崖行走[第 6.5 节]是一个 4 行 12 列的网格： 左下角是起点，右下角是终点，最下面一行的中间十格是悬崖。 踩进悬崖要扣 100 分并被送回起点，每走一步扣 1 分。

Q-learning 用 max 当目标，学到的是贴着悬崖走的最短路径： 在它眼里，只要不掉下去，13 步就是最优。

SARSA 用下一步真会执行的 a'。而 a' 有 ε 的概率是随机选出来的，所以它把"以 ε 的概率随机迈步"这件事算进了价值里。 贴着悬崖走，意味着每走一步都有约 2.5% 的概率掉下去：ε 取 0.1、四个动作时就是 0.1 乘上四分之一。一次扣 100 分，足以让这条看起来最短的路变得不划算，于是它宁可绕远。

这里要多说一句：两个算法没有谁更聪明，它们回答的问题不一样。 SARSA 估的是你真正在用的那套带探索的做法值多少分； Q-learning 估的是最优做法的价值，数据则由探索的做法提供。 当你真正要上线的就是那套带探索的做法时，SARSA 的估计才是诚实的。

什么时候该选 on-policy

ε 必须随训练衰减，比如从 0.2 慢慢降到 0.02。 如果不降，SARSA 会稳定在某个"一直保留随机性"的做法上，而不是最好的做法， 因为"乱走"本来就是它评估对象的一部分。

反过来说，如果探索本身有真实代价，比如推荐系统里的一次坏推荐、 库存里的一次缺货、医疗决策里的一次错误尝试，那么把这份代价算进价值就是你想要的。 该选 on-policy 的信号在这里：你要的是"实际执行做法"的可靠估计， 而不是一个只写在纸面上的最优做法。

课后练习

1. SARSA 更新式里的 Q(s', a')，那个 a' 是什么？

  1. 行为策略在下一个状态实际选择并且执行的那个动作
  2. 让 Q(s', ·) 取到最大值的那一个动作，相当于贪心
  3. 目标策略在下一状态会选择的动作，与行为策略无关
  4. 下一状态所有动作价值的平均值，需要先遍历求和

为什么：SARSA 用"下一步真正会执行的动作"来构造目标， 所以它估计的是当前行为策略的价值，而不是某个更贪心的策略。

B 描述的是 Q-learning：一旦换成 max，算法就变成 off-policy 了。 C 混淆了 on/off-policy，SARSA 里行为策略和目标策略是同一个。 D 是完全没有依据的凑法，更新从来不对动作求平均。

2. 说一个算法是 on-policy 的，准确的含意是什么？

  1. 它必须在线收集数据，完全不能使用历史经验回放（存下来的旧经历）
  2. 它的更新目标只来自当前状态获得的即时奖励信号
  3. 它正在评估的那套做法，与正在产生数据的那套做法是同一个
  4. 它只在改过一次做法之后，才更新一次价值估计

为什么：on-policy 的判据是"行为策略与目标策略是否同一个"。 SARSA 采数据用 ε-greedy，评估的也是这个 ε-greedy，所以是 on-policy。

A 把它误解成"必须在线学习"：能不能用回放缓冲区是工程选择， 不能与真实环境交互、只能用已经攒下来的历史数据学的 on-policy 算法照样存在。B 把 TD 更新说成了只吃即时奖励。 D 把策略迭代（反复"打分、改招"，直到改不动为止）的节奏当成了定义。

3. 在悬崖行走中 SARSA 学到远离悬崖的路径，根本原因是什么？

  1. SARSA 的目标里用了 max，因此高估了掉下悬崖的代价
  2. SARSA 把行为策略随机探索的代价算进了价值估计里
  3. SARSA 的学习率通常更小，所以最后稳定下来的解更保守
  4. SARSA 无法处理负奖励，所以只能选择绕远的那条路径

为什么：SARSA 的目标是 r + γQ(s', a')， 而 a' 有 ε 的概率是随机动作。贴着悬崖走等于反复暴露在 "随机一步就掉下去"的风险里，这份期望损失被如实记进了价值。 这里说的收敛，是指"一轮轮更新下去，Q 值不再明显变化，稳定下来了"。

A 说反了：用 max 的是 Q-learning。C 错：学习率只影响收敛速度， 不改变算法最终稳定到的那个解。不动点指的是"再更新一次也不变的那种解"。D 错：SARSA 处理负奖励毫无问题。

4. 下列哪种情况更该优先考虑 on-policy 的 SARSA？

  1. 你只能离线（不能与真实环境交互，只能用已经攒下来的历史数据），反复回放日志，且探索不产生任何成本
  2. 你只关心最后那套最优做法，过程中怎么试错完全无所谓
  3. 你需要用旧做法产生的数据，反复评估多套候选的新做法
  4. 探索本身有真实代价，且你关心实际执行策略的表现

为什么：探索有代价时，"把探索代价算进价值"是优点； SARSA 给出的就是部署后真会拿到的收益估计。

A 和 C 描述的是 off-policy 的典型用武之地：数据可复用、要评估别的策略。 B 也偏向 off-policy，因为 SARSA 的价值里永远含着探索成本， 即使 ε 很小，它也从不声称那是纯贪心策略的价值。

5. SARSA 的 TD 误差 δ（时序差分误差）等于什么？

  1. r + γQ(s', a') − Q(s, a)，其中 a' 由行为策略选出
  2. r + γ maxa' Q(s', a') − Q(s, a)，取下一状态最大
  3. r + γV(s') − V(s)，其中 V 是状态价值的估计
  4. Gt − Q(s, a)，其中 Gt 是本回合实际拿到的总分（每个奖励先打折再加起来）

为什么：把 (9.1) 的方括号展开就是 SARSA 的 TD 误差， 目标的第二项来自行为策略实际选出的 a'。

B 是 Q-learning 的 TD 误差，差别恰在这个 max。 C 是 TD(0) 预测 V 的误差，不是控制用的形式。 D 是蒙特卡洛（把一整局走完，用真实拿到的总分来估价值）的动作价值误差，它要等回合结束。

代码题 1 · 写一步 SARSA 更新

背景SARSA 是本课要学的控制算法，它把上一节的 TD(0) 从状态价值 V 推到动作价值 Q，因为只有 Q(s, a) 才能直接取出一套做法。 程序每走一步就会拿到五元组 (s, a, r, s', a')， 这个函数负责用这五样东西修正 Q 表里的一个格子，是训练循环里最内层的那次调用。 输入是更新前的 Q 表与这一步的五元组，输出是改好一格的新 Q 表， 下一步的决策就从它里面取 ε-greedy 动作。

请实现 sarsa_update(Q, s, a, r, s_next, a_next, alpha, gamma)，按 Q(s,a) ← Q(s,a) + α[r + γQ(s',a') − Q(s,a)] 更新一步。

输入

  • Q：形状 (状态数, 动作数) 的二维 numpy 数组，是训练到目前为止的动作价值估计；
  • s：当前状态的整数下标；a：当前动作的整数下标，两者一起指定被改的那一格；
  • r：这一步拿到的即时奖励，float；
  • s_next：下一状态的整数下标；a_next：下一步实际会执行的动作的整数下标，由行为策略给出；
  • alpha：学习率 α；gamma：折扣因子 γ，两者都是标量。

输出

  • 返回 np.ndarray，形状与 Q 相同 (状态数, 动作数)：第 [s, a] 个格子是更新后的值， 其余格子逐位等于传入时的值。不要就地修改传入的 Q。

会被检验返回值是 np.ndarray 且形状不变； 传入的 Q 在调用后保持原值；除 [s, a] 之外的格子逐个不变； 自举（用自己当前的估计去更新自己当前的估计）项用的是 Q[s_next, a_next]， 而不是 Q[s_next] 的最大值， 测试里 Q[s_next] = [5.0, 1.0]、a_next = 1 时目标必须是 1.0 而不是 5.0。只许标准库加 numpy。

卡住了？看提示
  • 先用 np.array(Q, dtype=float, copy=True) 复制一份再改。
  • 目标 = r + gamma * Q[s_next, a_next]；注意是 a_next，不是 max。

代码题 2 · 在悬崖行走上训练 SARSA

背景上一题只做一步更新，这道题把 SARSA 放进完整的控制循环里：在悬崖行走上反复跑回合，边用 ε-greedy 探索边把 Q 表改好。 它对应本课"SARSA 学到远离悬崖的路径"那个结论，训练循环调用它一次、拿回 Q 表，再对 Q 取贪心就得到学到的策略。 环境规则全部给定，不需要你另外实现环境：4 行 12 列、行优先编号 0–47，起点 36，终点 47，37–46 是悬崖； 动作 0/1/2/3 依次是上/右/下/左，撞边界原地不动；每步奖励 −1，踩悬崖奖励 −100 并退回 36（回合继续），走到 47 结束，每回合最多 400 步。

请实现 train_sarsa_cliff(episodes=30000, alpha=0.5, epsilon=0.1, gamma=1.0, seed=0)。

输入

  • episodes：训练的回合数，默认 30000；
  • alpha：学习率 α，默认 0.5；
  • epsilon：ε-greedy 的探索率 ε，默认 0.1；
  • gamma：折扣因子 γ，默认 1.0；
  • seed：随机种子，用 np.random.default_rng(seed) 取随机数，不要用全局 np.random。

输出

  • 返回 np.ndarray，形状 (48, 4)：第 s 行第 a 列是状态 s 下动作 a 的估计价值， 行下标就是上面那套行优先编号。对每一行取 argmax 就得到训练学到的策略。

会被检验返回的 Q 形状是 (48, 4)； 对每行取 argmax 得到的贪心策略从起点 36 出发能在 20 步以内走到 47，且路径不经过 37–46； Q[36, 1] 比 Q[36, 0] 低 30 以上，因为起点向右一步就进悬崖， 而 ε-greedy 的随机探索也会被算进价值里。只许标准库加 numpy。

卡住了？看提示
  • 开头先写 rng = np.random.default_rng(seed)， 再写 Q = np.zeros((48, 4))（48 就是 4 行乘 12 列）。 形状 (48, 4) 是 48 行 4 列，也就是每个状态一行、每个动作一列， 下标写成 Q[s, a]，行列都从 0 开始。
  • 环境怎么动、每一步给多少奖励，题面已经写全，照题面算就行。 代码里的顺序是：选动作 a，执行它得到奖励 r 和新状态 s_next，再选一个 a_next。
  • 选动作的小函数写成：先抽 rng.random()（0 到 1 之间的随机小数）， 小于 epsilon 就用 int(rng.integers(0, 4)) 随机取一个动作 （它返回 0、1、2、3 中的一个整数，右端的 4 取不到）， 否则用 int(np.argmax(Q[s])) 取当前 Q 最大的动作下标。
  • 踩到悬崖（下一个状态落在 37 到 46 之间）时，奖励记 -100.0， 并把 s_next 强制改成起点 36，这一回合继续；其他情况奖励记 -1.0。
  • 然后用刚拿到的 (s, a, r, s_next, a_next) 更新一格： Q[s, a] += alpha * (r + gamma * Q[s_next, a_next] - Q[s, a])。 注意方括号里第二项是 a_next 那一格，不是这一行的最大值。
  • 更新完再前进：s, a = s_next, a_next。如果 s == 47 就结束这一回合。 整个回合用一个最多跑 400 步的 for 循环兜住，防止永远走不完。
  • 跑完 episodes 个回合后 return Q，形状仍然是 (48, 4)。
