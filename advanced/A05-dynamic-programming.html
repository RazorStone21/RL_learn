进阶 · 第一部分 · 基础概念

动态规划：策略迭代与价值迭代

这一节的产出很具体：你能在一个模型已知的马尔可夫决策过程（Markov decision process，简写 MDP）上 算出最优策略（一套"看到什么状态就选什么动作"的规则）。 你还能说清 DP 卡在哪里，那条边界就是后面所有无模型方法的起点。

你会得到

  • 能写出策略评估的迭代式，并解释它为什么是"备份"而不是"解方程"
  • 能说清策略迭代与价值迭代的差别，以及各自什么时候更合适
  • 能指出 DP 的两个硬前提，以及它们如何逼出蒙特卡洛与时序差分

当模型已知时，问题就变成了计算

第 0004 课留下了一组贝尔曼最优（Bellman optimality equation）： 动作层直接取最大，不再按策略加权。只要解出 v*， 对它贪心（只挑眼前最好的那个）就得到最优策略。问题在于方程里有 max， 它不是线性的，解不出来；不过可以迭代着逼近。

动态规划（dynamic programming, DP）就是这套迭代解法。 它的入场券是一张完整的模型表：对任意 (s, a)，转移概率 （这个跳转不一定百分之百确定，而是一组可能性，各带着自己的概率） p(s′,r|s,a) 会告诉你"接下来会发生什么，概率各是多少"。 在业务里这意味着你先有了一版可信的仿真器，或者一张统计出来的转移表。

策略评估：反复套用贝尔曼期望方程

给定 π（策略），先要算出它每个状态值多少分。这一步叫策略评估（给定一套策略，算出它到底值多少分）， 算出来的东西叫状态价值（只看状态、不管具体选哪个动作的那个价值），记作 vπ。 把贝尔曼期望方程当成更新规则而不是方程来用，就得到下面这个迭代式：

Vk+1(s) ← Σa π(a|s) Σs′,r p(s′, r | s, a) [ r + γ Vk(s′) ] (5.1)

式子里的 ← 读作"更新为"：把右边算出来的值写回左边这个 V。每扫一遍所有状态， 价值就更接近 vπ 一步。为什么一定收敛（一轮轮算下去，数值不再明显变化，稳定下来了）？ 因为右边对 V 是一个压缩映射（每迭代一次，两个估计之间的差距就缩小一点，所以最终必然稳定）。 式中 γ 是折扣因子（越往后的奖励，算进总分时权重越小，相当于给它打了个折），缩小的系数就是它： 两轮之间的最大误差每轮至少缩小 γ 倍。γ = 0.9 时误差每轮乘以 0.9，大约 200 轮后就能精确到小数点后 9 位； γ = 0.99 时要慢一个数量级。这是"γ 接近 1 训得慢"最朴素的原因。

算到某个价值不再变化就停，这种"再迭代一次也不变"的解叫不动点（再迭代一次也不变的那种解）。

实践中不会真的解线性方程组（n 个状态就要解 n 元方程组， 代价是 O(n³)），而是迭代到相邻两轮的最大变化小于 θ（停止阈值）就停。 θ 就是你的精度预算：θ 太大，你会把"没算准的价值"当成收敛结果，后面的改进自然跟着错。

策略改进：贪心一步就够

有了 vπ，就能算出每个动作的价值 qπ(s,a)，然后每个状态挑最大的那个。这一步叫策略改进 （根据算出的分数，把策略里明显吃亏的选择换掉）：

π′(s) ← arg maxa Σs′,r p(s′, r | s, a) [ r + γ vπ(s′) ] (5.2)

式子里的 arg max 读作 arg-max，意思是"挑出让后面那个式子最大的那个选择"。 策略改进定理（policy improvement theorem，把打得差的招换成更好的，结果一定不会更差）保证： 这样得到的 π′ 在每个状态上都不差于 π，要么等价，要么严格更好。 于是"评估 → 改进 → 再评估"交替进行，价值单调上升且有上界， 必然停在某个点；在这一点上策略对自己的价值已经贪心，它就是最优策略。

这样得到的 π′ 是确定性策略（每个状态固定选一个动作，不靠抽签）。 反过来，按概率随机挑动作的那类策略叫随机策略（同一个状态下按概率随机挑，不固定某一个）。

这就是策略迭代（policy iteration，反复"打分 → 改招"，直到改不动为止）。它的每一轮都很贵 （评估要迭代到收敛），但需要的轮数通常很少。

价值迭代：把评估截断成一步

一个观察：评估根本不必做到收敛，做一步就接着改进，效果往往更好。 把两者合并，得到价值迭代（value iteration，不显式维护策略，直接把价值反复往最优方向推）：

Vk+1(s) ← maxa Σs′,r p(s′, r | s, a) [ r + γ Vk(s′) ] (5.3)

它就是贝尔曼最优（Bellman optimality equation，动作层直接取最大）的直接迭代。 收敛后从 V 里提取一次贪心策略即可。 注意它没有跳过价值函数（从某个状态出发，按某套策略走下去，平均能拿多少总分）： 它算的仍然是价值，只是不再为每套策略单独评估到收敛。

维度策略迭代价值迭代
每轮做什么评估到收敛 + 改进一次一步最优备份
轮数 / 每轮代价轮数少，每轮贵轮数多，每轮便宜
实现要点需要内层循环与策略表一个循环，代码极短

异步 DP，以及 DP 卡在哪里

异步 DP（asynchronous DP，不要求每轮扫遍所有状态，只更新其中一部分也行）放松了"每轮必须扫遍所有状态"的要求： 你可以只更新一部分状态，甚至就地更新（Gauss-Seidel 风格），只要每个状态都被访问到足够多次， 收敛性依然成立。这带来两个实际好处：状态里只有一小部分会被频繁访问时省算力； 也能把宝贵的算力集中到"策略真正会走到"的区域。

但 DP 有两个绕不过去的前提，它们合起来决定了这门课后面的走向：

  • 需要完整模型。真实业务里 p(s′,r|s,a) 通常拿不到， 或者仿真器与真实世界有偏差。这就是 0007 课蒙特卡洛（把一整局走完，用真实拿到的总分来估计价值）与 0008 课时序差分（不用等到一局结束，用"走一步之后的新估计"来更新"走这一步之前的估计"）的动机：用采样代替模型。
  • 要遍历整个状态空间（所有可能局面的集合）。状态数一大（哪怕只是几十维连续特征离散化）， 每轮扫一遍就不可行。这是 0012 课函数逼近 （状态太多记不下整张表，干脆用一个带参数的函数去"猜"价值）的动机。

诊断视角：DP 的结果不对，先查三件事：终止状态有没有被当成普通状态参与备份 （它应当保持零价值，且不再向外传播）、θ 是否过大、γ 是否接近 1 导致看起来"没收敛"。 这三条在后面的 DQN（deep Q-network，深度 Q 网络）里会以几乎相同的形式再出现一次。

课后练习

1. 使用动态规划求解 MDP，最关键的适用前提是什么？

  1. 需要有足够多的历史交互轨迹，用来估计状态价值函数
  2. 需要状态空间是连续取值的，否则迭代过程不会收敛
  3. 需要已知环境的转移概率分布 p(s′, r | s, a)
  4. 需要能够在线与环境交互，并持续采集新的样本数据

为什么：式 (5.1) 与 (5.3) 的右边都要对 p(s′,r|s,a) 求期望，因此必须能枚举所有可能的下一次结果。 有模型是 DP 的入场券（S&B 第 4.1 节）。

A 与 D 描述的是无模型方法（蒙特卡洛、时序差分）的路线。 B 恰好说反了：连续状态空间反而是表格型 DP 的痛点。

2. 策略评估与策略改进之间的关系，正确的描述是哪一项？

  1. 先评估把当前策略的价值算准，再对它贪心换掉不够好的动作
  2. 先改进把所有动作换到最好，再评估这些动作各自值多少分
  3. 两者必须同时执行，单独跑任何一步都不可能得到收敛结果
  4. 评估只对确定性策略有效，改进只对随机策略才有效果

为什么：改进要用到 qπ(s,a)， 而它由 vπ 与模型算出，所以顺序必然是"先评估、后改进"， 这也构成策略迭代的一个外层轮次。

B 把顺序颠倒了。C 错：策略迭代就是先把内层评估跑完再改进， 两者不必同时进行。D 错：两者对确定性与随机策略都成立。

3. 价值迭代与策略迭代最核心的差别是什么？

  1. 价值迭代需要完整模型，而策略迭代完全不需要环境模型
  2. 价值迭代只能用于分幕任务，策略迭代对两类任务都支持
  3. 价值迭代直接优化策略参数，跳过了价值函数的计算过程
  4. 价值迭代每轮只做一次备份，省掉了评估到收敛的内层循环

为什么：式 (5.3) 把"评估到收敛"截断成一步，再立刻取 max， 等价于评估与改进在每次扫描中同时发生，因此只需要一层循环。

A 错：两者都需要完整模型。B 错：两者都适用于分幕与持续任务。 C 错：价值迭代算的依然是价值函数，策略是最后从 q 里提取出来的。

4. 异步 DP（asynchronous DP）指的是什么？

  1. 在多台机器上各自维护一份独立的价值表，最后把结果汇总
  2. 不要求每轮扫遍所有状态，可以只更新其中一部分状态的价值
  3. 把更新顺序写成随机排列，因此保证收敛速度一定快于同步版
  4. 只在采样访问到的状态上做备份，所以不再需要环境模型支持

为什么：异步 DP 只要求每个状态被访问足够多次，不要求每轮完整扫描， 更新顺序可以任意，甚至就地更新（S&B 第 4.5 节）。它的价值在于把算力投到重要的区域。

A 说的是分布式实现，不是异步 DP 的定义。 C 错在"保证更快"：顺序会影响收敛速度，但异步 DP 本身不做这种承诺。 D 错：异步 DP 仍然需要模型，只是更新粒度更灵活。

5. 在策略评估里把停止阈值 θ 设得过大，会有什么后果？

  1. 价值还没算准就提前停止，最终得到的策略可能并不是最优
  2. 迭代所需的轮数会明显增加，但最终结果仍然保持完全一致
  3. 折扣因子会被自动调小，从而让整个迭代重新变得可以收敛
  4. 价值函数会一路发散到无穷大，必须重新从零初始化价值表

为什么：θ 是精度预算。提前停止意味着 V 与 vπ 的差还没被压下去，基于它算出的 qπ 和贪心策略就可能选错动作。

B 说反了：θ 越大，停止越早、轮数越少。C 错：θ 与 γ 是两个独立的量。 D 错：备份是 γ-压缩映射，在 γ < 1 时不会发散，θ 只影响停得多早。

代码题 1 · 用迭代备份估计随机策略的价值

背景模型已知的 MDP 里，转移概率与奖励表都摆在手边，求解退化成迭代计算。policy_evaluation 是策略迭代中"评估"那一步，被策略改进与策略迭代的主循环调用：给定一个策略 π，先把它的价值函数 vπ 迭代出来。传进来的 P、R、policy 相当于业务里那版可信仿真器或统计出来的转移表，返回的 V 就是"从每个状态出发按 π 一直走，长期平均能拿多少分"的估计。

请实现 policy_evaluation(P, R, policy, gamma, theta=1e-8)。

输入

  • P：形状 (S, A, S) 的 float 数组。形状说的是每个维度各有多少个位置，下标从 0 开始；P[s, a, s′] 是状态 s 执行动作 a 后转到 s′ 的概率，固定 (s, a) 时对 s′ 求和为 1；
  • R：形状 (S, A) 的 float 数组，R[s, a] 是在 s 执行 a 能拿到的期望即时奖励；期望就是同一件事重复很多次之后的平均结果；
  • policy：形状 (S, A) 的 float 数组，policy[s, a] 是 π 在 s 选 a 的概率，对 a 求和为 1；
  • gamma：float，折扣因子（越往后的奖励，算进总分时权重越小，相当于给它打了个折）；theta：float，收敛阈值，默认 1e-8。

输出

  • 返回 np.ndarray，形状 (S,)，float：第 s 个元素是策略 π 下状态 s 的估计价值 vπ(s)，对应"这个状态值多少分"。终止状态的动作为自环、奖励恒为 0，它的价值应当保持 0。
Vk+1(s) ← Σa policy[s, a] Σs′ P[s, a, s′] ( R[s, a] + γ Vk(s′) ) (5.4)

会被检验返回值是 numpy 数组且形状为 (S,)；全等待策略下 V[0] = 10.0、V[1] = 9.0、V[2] = 0（容差 1e-5）；全前进策略下 V 约为 [9, 10, 0]；V 是贝尔曼期望算子的不动点，残差小于 1e-4；theta 收紧到 1e-12 后结果更接近 10.0；调用后 P、R、policy 逐元素不变，返回的是新数组；只用标准库加 numpy。

卡住了？看提示
  • 先取 S, A = policy.shape，再建 V = np.zeros(S)。np.zeros(S) 返回长度 S、全是 0 的数组，下标从 0 开始。
  • 外层写 while True。每轮开始先设 delta = 0.0，用它记录这一轮里单个状态变化的最大值。
  • 内层对每个状态 s：先设 total = 0.0，再对每个动作 a 累加 policy[s, a] * (R[s, a] + gamma * (P[s, a] @ V))。算完先更新 delta = max(delta, abs(total - V[s]))，再写回 V[s] = total。
  • 一轮跑完，如果 delta < theta 就 break，最后 return V。 就地更新（刚算出来的值马上给后面的状态用）是标准做法，收敛更快，也不需要额外数组。

代码题 2 · 价值迭代求最优策略

背景同一套已知模型，价值迭代把"评估到收敛"截断成一步最优备份，评估与改进合进一个循环，轮数多但每轮便宜。value_iteration 在规划阶段被调用：先把最优价值迭代出来，再从它提取一次贪心策略交给部署。这里的 P、R 是模型表，V 回答"每个状态在最优策略下值多少分"，policy 回答"到了这个状态该按哪个动作"。

请实现 value_iteration(P, R, gamma, theta=1e-8)。

输入

  • P：形状 (S, A, S) 的 float 数组，P[s, a, s′] 是状态 s 执行动作 a 后转到 s′ 的概率；
  • R：形状 (S, A) 的 float 数组，R[s, a] 是期望即时奖励；
  • gamma：float，折扣因子；theta：float，收敛阈值，默认 1e-8。

输出

  • 返回二元组 (V, policy)，两项都是 np.ndarray；
  • V：形状 (S,) 的 float 数组，V[s] 是最优价值 v*(s)，终止状态保持 0；
  • policy：形状 (S,) 的整数下标数组，policy[s] 是最终 V 的贪心动作下标，平局取下标小的动作。
Vk+1(s) ← maxa [ R[s, a] + γ Σs′ P[s, a, s′] Vk(s′) ] (5.5)

会被检验收敛后的 V 约为 [10, 10, 0]（容差 1e-4）且 V[2] = 0；V 满足贝尔曼最优方程，残差小于 1e-4；policy 的 dtype 是整数，每一项都是合法动作下标，状态 0 选等待（下标 1）、状态 1 选前进（下标 0）；状态 1 的最优价值高于一直等待的价值；gamma 从 0.9 改成 0.5 后状态 0 的最优动作随之改变；调用不修改 P、R，两次调用返回的 V 互不影响；只用标准库加 numpy。

卡住了？看提示
  • 主体和策略评估很像，区别只有一个：内层不再对动作按 policy 加权，而是直接取最大值。 对每个状态算 best = max(R[s, a] + gamma * (P[s, a] @ V) for a in range(A))。
  • 同样用 V = np.zeros(S)、while True 和 delta = 0.0： 每轮把 abs(best - V[s]) 的最大值记进 delta，小于 theta 就跳出循环。
  • 收敛之后再算一次 Q = R + gamma * (P @ V)，形状 (S, A)； 用 np.argmax(Q, axis=1) 在每个状态那一行里挑最大的动作，得到长度 S 的整数下标数组。
  • 返回 (V, policy) 二元组。V 要是新数组，不要修改传入的 P、R。
