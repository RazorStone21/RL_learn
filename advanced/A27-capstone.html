综合实战：为你的工作问题选算法

收尾这一节不再介绍新算法，只做一件事：把手头的真实问题过一遍。 三个问题定出算法族，五条检查表把关上线，训练出错时知道先看哪里。

你会得到

  • 能用「能不能交互 / 动作是什么 / 采样多贵」三步定位算法族
  • 能用 5 条检查表与 4 层评估方案替项目把关
  • 能从学习曲线的形状反推病因，不再盲目调学习率

选型只有三个问题

前二十六课讲了十几个算法，落到你自己的问题上，分岔只有三处。 按顺序问，每一步都能砍掉一大半选项。

先把后面反复出现的词一口气交代掉。监督学习（拿"题目 + 标准答案"来学的机器学习方式）。 策略（一套"看到什么状态就选什么动作"的规则）。回报（从现在起一直到结束， 把每一步奖励加起来的总分）。价值函数（从某个状态出发，按某套策略走下去，平均能拿多少总分）。 函数逼近（状态太多记不下整张表，干脆用一个带参数的函数去"猜"值）。 基线（打分时先减掉的一个参照值，只用来压住波动，不改变平均方向）。 优势（在某个状态下，选这个动作比"平均水平"好多少）。 过估计（因为总是取最大值，估计出来的分数会偏高）。 学习率（每次更新时往新信息的方向挪多远）。超参（需要你自己设定、而不是训练学出来的参数）。 泛化（在没见过的状态上也能给出靠谱的估计）。收敛（一轮轮算下去，数值不再明显变化）。 样本效率（拿到同样多的经验能学多好，高就是更省数据）。 目标网络（另存一份"稍旧"的网络专门用来算目标，隔一阵才同步一次，避免追着自己跑）。 对数概率（把概率取对数，概率很小的时候也不会变成 0，方便计算）。 熵（衡量选择有多随机、多分散，也用来衡量两套概率分布差多远）。 人类偏好（只告诉你"这两个里我更喜欢哪一个"，不给绝对分数）， 这样叫是为了和 0002 课"每个臂一个打分"的偏好区分开。 奖励模型（用一个学出来的模型给回答打分，代替人去打分）。

  • 能不能交互？你能不能安全地拿真实反馈试错。 不能，就只剩历史日志可用。这种设定叫离线（不能与环境交互，只能用已经攒下来的数据学）， 走 0025 课的离线路线；能，才谈得上在线学习。
  • 动作是什么？离散的少数选项、连续的控制量， 还是「直接输出一整段决策」的策略输出，各自对应不同的算法族。
  • 采样多贵？每次交互要花钱、要人等，还是不可回滚。 贵就得提高单次交互的价值：模型基规划、离线预热、用演示数据做基线。

问这三个问题之前还有一道更基础的关卡：这件事要不要用 RL（reinforcement learning，强化学习）？ 0006 课的检查表， 0002 课那种「没有状态转移（做完动作之后局面不会变）、只做反复选择」的问题， 答案常常是不需要，一条规则或一次 A/B 实验就够。

三个问题，换一张选型表

你的情形首选备选与代价

上线前检查表

五条里任何一条答不上来，先回去补，不要开始调参。

  1. 真的需要 RL 吗？规则、A/B 实验或监督学习能不能先拿到大部分收益。
  2. 状态满足马尔可夫性（下一个状态只看当前状态和动作，与更早的历史无关）吗？ 也就是两个看起来一样的状态，未来会不会不同（0003 课）。
  3. 奖励能逐步计算，并且和真实目标一致吗？能钻空子的地方就是 奖励黑客的入口（0006 课）。
  4. 能安全试错吗？真实试错有不可逆代价时，先做仿真或离线评估（0025 课）。
  5. 评估方案定了吗？主指标、护栏指标（用来兜底的安全线，比如"下单成功率不能掉"）、shadow 与 A/B 的判定阈值要在训练前写下来； 事后补的评估总是偏向已完成的模型。

评估与上线：四层

  1. 离线评估：只用日志估计新策略，受分布偏移影响而偏乐观， 只能筛掉明显更差的候选（0025 课）。
  2. Shadow 模式：新策略只做决策、不真执行，动作与现网动作并排记录。
  3. A/B 实验：小流量（只让一小部分用户看到）真上线，主指标要有判定阈值与实验周期。
  4. 护栏指标：与主指标同时监控、一旦恶化就必须叫停的指标。

每层拦不同的失败：离线拦明显更差的，shadow 拦会误操作的， A/B 回答有没有变好，护栏在你答错时止损。

故障速查：先看曲线，再动手

训练不顺时，先按症状定位，再决定改什么。下表是常见的五种。

症状最可能的病因先查什么

什么情况下答案是「不要用 RL」

收尾这句提醒放在这里：先证明 RL 值得用，再决定用不用它。以下情形通常应当放弃：

  • 规则系统、阈值策略或一次 A/B 实验就能拿到八成收益，工程成本差一个量级。
  • 奖励无法度量，或者要等三个月才拿到。没有及时的学习信号，算法学不动。
  • 试错有不可逆的代价（不可回滚的资损、人身安全、合规风险），又没有可靠仿真器。
  • 问题里根本没有「状态转移」，只是反复选择，那属于多臂老虎机 （一排老虎机摆在面前，不知道哪台吐钱多，只能一台台试），甚至只是一组实验设计。

反过来，当决策是持续的、结果要隔一段时间才显现、而且你确实能安全试错时， RL 才开始有优势。回到 0001 课的五要素， 把这四条对照自己的问题过一遍，再挑算法。

课后练习

1. 按本课的选型顺序，挑算法之前第一个该问什么？

  1. 动作空间有多大、是离散还是连续，它决定算法族
  2. 能不能与真实系统安全交互，它决定在线还是离线
  3. 每次采样成本有多高，它决定样本效率要求
  4. 状态维度有多高，它决定能否用表格型方法

为什么：三问的顺序有依赖。不能交互时，动作空间的精细选择没有意义， 只能在固定日志上做离线的文章，所以「能不能交互」先落地。

A、C、D 是另外几问，放在第一问会让选型建立在一个还不成立的假设上， D 更是把数据来源放到了最后。

2. 某推荐场景动作是上万件商品，训练系统能大量并行交互。首选哪一族？

  1. DQN，它对离散动作的处理最直接，样本效率最高
  2. SAC，最大熵框架能处理上万维的离散动作
  3. PPO，不要求逐动作取最大值，能直接输出动作概率
  4. 表格型 Q-learning，状态与动作明确，不需要函数逼近

为什么：DQN 要对下一状态的全部动作取 max 与 argmax，动作上万时既昂贵又容易过估计； PPO 只需要动作的对数概率，不受动作维度限制，并行仿真又便宜。

A 的问题在 max 的开销与过估计。B 用错了场景：SAC 为连续动作设计。 D 忽略了上万动作的表格规模与泛化需求。

3. 你只有历史日志、不能上线探索。最合理的第一步是什么？

  1. 直接上 PPO，在日志上反复更新策略，直到离线指标变好
  2. 先做随机策略（每个动作都按概率随机试，不挑最好的）的离线评估，估出所有候选动作的价值
  3. 先训一个奖励模型，用它给日志里的动作重新打标签
  4. 先把行为克隆做成基线，再考虑 CQL / IQL 一类离线算法

为什么：行为克隆便宜、稳定，很多业务问题到这一步就够交付； 离线 RL 的价值必须相对它来证明，先有基线才有参照。

A 忽略了 PPO 需要在线采样。B 说的是离线评估做不到的事：日志只覆盖旧策略的动作分布， 其他动作的价值无从估计。C 混淆了离线 RL 与 RLHF（reinforcement learning from human feedback，基于人类反馈的强化学习）的奖励模型。

4. 上线前的评估方案，哪一项组合最符合本课建议？

  1. 离线评估筛候选，shadow 并排观察，再做 A/B 与护栏指标
  2. 只做 A/B 实验，离线评估的结果从来不值得参考
  3. 只做离线评估，不需要真实流量，成本最低也最安全
  4. 直接全量上线，靠人工回滚兜底，最快拿到收益

为什么：四层各拦一种失败：离线便宜但偏乐观，用来筛候选；shadow 不真执行， 能发现会误操作的决策；A/B 回答有没有变好；护栏兜住意外恶化。

B 忽略了离线评估在筛选阶段的价值。C 把最不可信的一层当成唯一依据。 D 跳过全部防线，奖励设计一有漏洞，代价就落在业务上。

5. 训练奖励一路上涨，但业务指标同时下滑。最可能是什么问题？

  1. 探索不足，策略过早收敛到奖励较低的局部最优
  2. 奖励黑客，代理指标与真实目标不一致，被策略钻空子
  3. 过估计，Q 值被一路抬高，学到的策略并不可用
  4. 样本效率不足，训练还没看到足够多样本

为什么：「训练奖励涨、业务指标跌」说明奖励与真实目标脱钩：策略在优化你写下的 代理指标，而它不等于你想要的东西。该做的是回头查奖励定义与护栏指标，再人工抽查决策。

A 的症状是奖励长期不涨且策略单一。C 表现为 Q 值单调膨胀，业务指标未必立刻下滑。 D 是学习还没到位，方向没错。

代码题 1 · 写一个算法推荐器

背景本课是收尾实战课：拿到一个新业务问题时，先按选型表定算法族， 再决定训练方案。recommend_algorithm 就是这一步的代码化， 在选题评审阶段由做方案的人调用一次，把口径统一下来， 输出直接写进设计文档给团队与主管看，让「先问能不能交互」这件事不靠记忆。

请实现 recommend_algorithm(problem, action_space, interactive, samples, needs_policy_output=False)。

输入

  • problem：问题名，字符串，只作标识，不参与判断。
  • action_space："discrete" 或 "continuous"，表示动作空间是离散还是连续。
  • interactive：布尔，False 表示不能与真实系统安全交互，只能拿固定日志。
  • samples：布尔，True 表示采样极贵，要花钱、要等人或不可回滚。
  • needs_policy_output：布尔，默认 False，表示是否需要策略直接输出动作。

输出

  • 返回 {"family": 算法族, "reason": 中文理由} 这一个 dict。
  • family 是字符串，取值只有四个："offline-RL"、"model-based"、"SAC-TD3"、"DQN-family"。
  • reason 是字符串，给出这条推荐的理由，直接展示给读者，不需要复述问题名。

会被检验family 只能是上面四个字符串之一； 不能交互时优先于采样成本与动作空间，即使采样极贵也返回 "offline-RL"； 采样极贵返回 "model-based"；连续动作或要求策略直接输出动作返回 "SAC-TD3"； 其余离散动作返回 "DQN-family"。reason 至少要 8 个字， 且不能把 problem 抄回去。只用标准库与 numpy。

卡住了？看提示
  • 五个分支写成一条 if / elif 链即可，不要嵌套。
  • 顺序重要：能不能交互必须排在最前面，否则会推荐出无法落地的方案。

代码题 2 · 由学习曲线判断病因

背景训练不顺时先看曲线，再动手改超参，顺序反了会白调很久。 本课的故障速查表给了五种症状与对应的病因。 diagnose_training 把这张表写成可调用的函数， 在训练监控脚本里定期跑一次，把指标曲线转成一个病因标签。 输出进告警与实验记录，让值班的人一眼知道该查奖励定义、该扩 batch，还是该补探索。

请实现 diagnose_training(curve)。

输入

  • curve：dict，键是训练曲线指标名，值是 float。可能含 q_max（Q 值绝对值的峰值）、train_reward_change（训练奖励变化量）、eval_metric_change（业务指标同期变化量）、return_std（回报的标准差，回报指从现在起一直到结束、把每一步奖励加起来的总分）、policy_entropy（策略的熵，熵衡量选择有多随机、多分散，越大说明越敢试）。缺的键按 0.0 处理，policy_entropy 缺省为 1.0。

输出

  • 返回一个字符串，取值只有五个："value-divergence"、"reward-hacking"、"high-variance"、"exploration-collapse"、"not-converged"。
  • 按这个优先级取第一个命中的：q_max > 1e4 → "value-divergence"；train_reward_change > 0 且 eval_metric_change < 0 → "reward-hacking"；return_std > 100 → "high-variance"；train_reward_change <= 0 且 policy_entropy < 0.3 → "exploration-collapse"；其余 → "not-converged"。

会被检验四条曲线各命中对应标签； 同时命中多条时返回优先级最靠前的那条，例如 Q 值峰值超过 1e4 而回报标准差也超过 100 时给 "value-divergence"； 奖励不涨但策略仍有熵要判 "not-converged"，不能误判成 "exploration-collapse"； 缺失的键要用默认值补上，空字典或只剩一个键也不能抛异常。 只用标准库与 numpy。

卡住了？看提示
  • 用 curve.get("q_max", 0.0) 一类写法取缺失的键。
  • 五个分支写成一条 if / elif 链，顺序照题干即可。
